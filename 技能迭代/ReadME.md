# 技能迭代流程

## 一、迭代原则

1. **复盘驱动**：所有技能文档修改必须源于复盘记录中发现的问题，不得凭主观判断直接改文档。
2. **深度反思先行**：在提炼改进项之前，必须经过完整的思维链条（见第四节），对复盘数据和报告进行彻底反思、高度归纳和逆向思考，找到真正的问题根因和潜在机会，而非机械地照搬复盘报告中的改进建议。
3. **先备份再修改**：修改 `docs/` 下任何文档前，必须先将原文档备份到 `技能迭代/History/` 目录。
4. **最小化变更**：只改与反思结论直接相关的条款，不做附带重构或风格调整。
5. **可追溯**：每轮迭代必须留下变更日志，记录改了什么、为什么、依据哪份复盘报告。

---

## 二、迭代触发条件

当满足以下任一条件时，启动一轮技能迭代：

- 复盘报告中包含「技能改进建议」表格（P0/P1/P2 优先级）；
- 复盘报告正文中明确指出技能文档的某条款存在缺陷或缺失；
- 人工判断复盘结论需要修订技能文档（需说明理由）。

---

## 三、备份规则

修改 `docs/` 下任一文档前，按**与技能根目录原样的目录结构**复制到 `技能迭代/History/` 中，并在文件名末尾追加 `_YYYY_MM_DD` 日期后缀（年月日用下划线分隔）。

### 备份示例

原文件路径：

```
docs/Martingale-Grid-Trading-Strategy/00-Router.md
```

备份到：

```
技能迭代/History/docs/Martingale-Grid-Trading-Strategy/00-Router_2026_08_07.md
```

### 注意事项

- 如果同一天对同一文件多次修改，只在首次修改前备份一次。
- 如果一次迭代涉及多个文档，逐个备份。
- `History/` 下的备份文件为只读归档，不再修改。

---

## 四、深度反思思维链条

> **这是迭代的核心环节。** 不经过完整的思维链条，不得进入改进项提炼和文档修改。反思的目的是穿透表象，找到真正的问题根因和隐藏的机会，避免"头痛医头脚痛医脚"式的表面修补。

### Step 0：深度反思（进入迭代流程前的必经阶段）

#### 0.1 数据全景拉取

通过 vnpy_mcp 拉取全量数据，建立反思的事实基础：

- 账户状态（`get_accounts`）：总资产、可用资金、盈亏变化
- 策略全貌（`cta_strategies_get_all`）：所有策略的运行状态、方向、持仓、参数
- 交易历史（`cta_strategy_get_trade_history`）：实际开仓/加仓/减仓/平仓行为
- 分析报告（`cta_report_list` + `cta_report_get`）：大盘报告、策略分析报告、选股报告
- 持仓明细（`get_positions`）：当前持仓与浮盈浮亏

#### 0.2 第一层反思：事实还原——「发生了什么」

**逐策略还原完整交易生命周期的客观事实：**

- 每个策略从创建到当前（或平仓）的全过程时间线
- 每笔交易的价格、时间、方向、触发原因（CCI/网格/手动/AI 指令）
- 参数变更历史（谁在什么时间改了什么参数）
- AI 分析报告在每个关键节点的判断和输出

**关键提问：**
- 策略的盈亏是什么？（不是看浮盈浮亏，而是看已实现盈亏+未实现盈亏的总和）
- 交易行为和 AI 报告的判断是否一致？
- 参数变更和报告建议是否一致？

#### 0.3 第二层反思：根因穿透——「为什么会这样」

**不停留在"止损没开""参数没落地"等表象，追问为什么：**

- **为什么 openclaw 会关闭等待首仓策略的止损？** -> 是技能文档中存在模糊地带，允许 AI 自行判断"空仓不需要止损"？还是文档明确要求但 AI 未遵守？
- **为什么 AI 报告输出了修正建议却不落地？** -> 是技能流程中缺少"输出即执行"的闭环约束？还是 set_parameters 的调用条件不明确？
- **为什么追高开仓反复发生？** -> 是"禁止追高"的判定条件不够具体（只有定性描述没有量化阈值）？还是 AI 对"追高"的理解与文档定义不一致？
- **为什么亏损加仓在逆势中持续？** -> 是网格加仓前置检查不足？还是"亏损加仓"开关的设置时机不明确？

**根因分析方法——连续追问 5 次「为什么」：**

```
问题：MARTIN-META 亏损 -8.4%
为什么 1：因为 07-16 在 $673.76 追高开仓
为什么 2：因为 AI 判断当前可开仓，未执行"禁止追高"约束
为什么 3：因为"追高"在文档中只有定性描述，没有量化判定标准
为什么 4：因为 01-Entry-Rules.md 的禁止条件依赖 AI 自行解读"区间上半部"
为什么 5：因为缺少"近 N 日价格分位 > X% 即判定为追高"的硬性阈值

-> 根因：开仓入场规则缺少量化追高判定条件
-> 改进方向：在 01-Entry-Rules.md 中增加价格分位硬性阈值
```

#### 0.4 第三层反思：高度归纳——「这些问题的共性是什么」

**把多个具体问题抽象为模式，找到系统性缺陷：**

- **"输出不落地"模式**：AI 报告识别问题 -> 输出建议 -> 不执行。SOFI、NVIDIA、UNH 都出现了这个模式。这不是个别策略的问题，而是技能流程中缺少"分析-执行"闭环的系统性缺陷。
- **"参数裸奔"模式**：多个等待首仓策略被统一设置为止损关/网格密/加仓关。这不是偶发，而是 AI 对"空仓等待"阶段有一套自创的默认参数模板，与技能文档的硬约束冲突。
- **"逆势加仓不设防"模式**：META、UNH、NFLX 都在亏损中继续网格加仓。共性是网格加仓前置检查不充分——只检查了"是否到加仓间距"，没检查"趋势是否支持"。
- **"盈利不可复制"模式**：GOOGLE 和 AMD 盈利了，但盈利的原因是什么？是技能规则发挥了作用，还是人工干预的结果？如果规则有效，为什么其他策略不适用？

**归纳提问：**
- 这些问题是否指向同一个技能文档缺陷？
- 如果只修一个地方，能同时解决几个问题？
- 修改后会不会引入新的风险？

#### 0.5 第四层反思：逆向思维——「反过来想，总是反过来想」

**运用逆向思维，从失败中找到利润机会，从共识中发现风险：**

- **逆向于失败**：亏损策略做错了什么？反过来做是否就是利润机会？
  - TSLA 逆势马丁加仓亏损 -> 反过来：在趋势确认下跌时禁止加仓，甚至反向做空
  - NVDA 震荡市反复止损 -> 反过来：识别震荡市后切换为均值回归策略，不做趋势
  - EMA QQQ 多空双杀 -> 反过来：均线粘合时禁止使用 EMA 交叉策略

- **逆向于共识**：AI 报告和选股报告的共识在哪里可能出错？
  - 所有报告都说"做多"时 -> Margin Debt 天量 + OAS 极窄 = 做多拥挤度极高，逆向做空概率更大
  - 分析师密集上调目标价时 -> 市场过度乐观的顶点信号
  - VIX 极低时 -> 市场 complacency，黑天鹅概率上升

- **逆向于规则**：技能规则本身是否在某些场景下应该被反转？
  - "宁可错过不可追高"是做多规则 -> 但在做空场景下，是否应该"宁可追空不可等待"？
  - "CCI 超卖不做空"是常识 -> 但如果 CCI 极端超卖 + 基本面恶化 + 支撑已破，是否应该反转为"超卖正是做空确认"？
  - "网格加仓摊低成本"是马丁格尔核心逻辑 -> 但在趋势反转时，是否应该反转为"网格减仓锁定亏损"？

**逆向思考提问：**
- 如果把所有亏损策略的方向反过来，会盈利吗？如果会，说明什么？
- 如果把所有盈利策略的规则复制到其他策略，会盈利吗？如果不会，差异在哪里？
- 当前技能规则中，哪条规则在特定条件下会从"保护"变成"枷锁"？

#### 0.6 第五层反思：机会发现——「从反思中提炼可执行的改进」

**把反思转化为具体的、可验证的改进方向：**

- 反思发现"输出不落地"是系统性缺陷 -> 改进方向：在技能流程中增加"分析-执行-复核"闭环检查点
- 反思发现"追高"缺少量化标准 -> 改进方向：在入场规则中增加价格分位/支撑压力分位的硬性阈值
- 逆向思维发现"震荡市做趋势必亏" -> 改进方向：增加市场状态识别模块，震荡市自动切换策略参数
- 逆向思维发现"财报后均值回归"是高确定性机会 -> 改进方向：在开仓规则中增加"财报后 N 日"的逆向入场条款

**机会提炼标准：**
- 必须有实盘数据佐证（不是理论推测）
- 必须有明确的触发条件和失效边界
- 必须能映射到具体技能文档的具体条款
- 必须能在下一轮复盘中验证

#### 0.7 反思输出

反思完成后，输出一份**反思备忘录**，包含：

1. **事实还原**：关键策略的完整交易生命周期还原
2. **根因清单**：每个问题的 5 层"为什么"追问结果
3. **系统性缺陷归纳**：从具体问题抽象出的模式
4. **逆向机会发现**：从失败和共识中发现的反向利润机会
5. **改进方向初判**：哪些改进值得做、哪些需要进一步观察、哪些应该放弃

反思备忘录存入 `技能迭代/History/REFLECTION_YYYY_MM_DD.md`，作为后续改进项提炼和文档修改的依据。

## 五、迭代流程（5 步）

> 以下流程在第四节「深度反思」完成后执行。反思未完成或不充分时，不得进入本节。

### Step 1：读取复盘记录与反思备忘录，提炼改进项清单

- 读取 `复盘记录/` 下最新日期文件夹中的复盘报告；
- 读取 `技能迭代/History/REFLECTION_YYYY_MM_DD.md` 反思备忘录；
- 综合复盘报告中的「技能改进建议」和反思备忘录中的「改进方向初判」；
- **以反思备忘录的结论为主**，复盘报告中的改进建议仅作为参考输入；
- 整理为改进项清单，每项包含：编号、问题描述、根因分析、涉及文档路径、优先级、对应复盘报告路径、对应反思备忘录路径。

### Step 2：逐项定位涉及文档

- 根据改进项内容，定位需要修改的 `docs/` 下具体文档和章节；
- 如果一个改进项涉及多个文档，逐个列出；
- 如果无法确定对应文档，标记为「待确认」，不进入下一步。

### Step 3：备份原文档

- 按「三、备份规则」将每个待修改文档复制到 `技能迭代/History/` 下；
- 确认备份文件存在且内容与原文档一致后再进入下一步。

### Step 4：修改文档

- 逐项修改 `docs/` 下的文档；
- 修改内容应与复盘结论严格对应，不做超出复盘结论范围的扩展修改；
- 修改方式：在原文档对应章节中增补、修订或删除条款；
- 修改后在文档对应位置标注变更来源（如 `<!-- 迭代 2026-08-07：见复盘报告 复盘记录/2026-08-07/xxx.md -->`）。

### Step 5：写变更日志

在 `技能迭代/History/` 下创建当日的变更日志文件 `CHANGELOG_YYYY_MM_DD.md`，记录本轮全部修改。格式见第六节。

## 六、数据依据

迭代前必须通过 **vnpy_mcp** 拉取以下数据，作为修改的事实依据：

| 数据项 | vnpy_mcp 工具 | 用途 |
|--------|--------------|------|
| 账户状态 | `get_accounts` | 确认当前账户余额、可用资金 |
| 策略列表与状态 | `cta_strategies_get_all` / `cta_strategy_get_status` | 确认策略运行状态和参数 |
| 交易历史 | `cta_strategy_get_trade_history` | 核对实际交易行为与复盘结论 |
| 分析报告 | `cta_report_list` / `cta_report_get` | 读取大盘报告和策略分析报告 |
| 持仓 | `get_positions` | 确认当前持仓 |

- 拉取的数据用于**验证复盘结论是否成立**，而非直接修改策略参数；
- 如果数据与复盘结论矛盾，应暂停迭代并标注「数据矛盾，待人工确认」。

复盘常见的改进类型及其对应的 `docs/` 子目录：

| 网格加仓逻辑 | `Martingale-Grid-Trading-Strategy/02-Grid-Operations.md`、`Tiger-Grid-Template/06_grid_martin.md` | 超卖区继续加仓、亏损加仓开关被重开 |
| 开仓入场规则 | `Martingale-Grid-Trading-Strategy/00-Router.md`、`Martingale-Grid-Trading-Strategy/01-Entry-Rules.md` | 追高开仓、首仓区间未满足即入场 |

| 多信号趋势策略 | `Multi_Signal_Treand_Strategy.md` | 信号权重、开仓/平仓条件 |
| 调仓 | `调仓/` | 板块轮动调仓逻辑、选股池维护 |

## 九、验证要求

1. **即时验证**：修改完成后，通过 vnpy_mcp 重新拉取策略状态，确认修改逻辑与实际运行参数一致。
2. **延迟验证**：无法即时验证的改进项，在变更日志中标注「待下轮复盘确认」，并在下一轮复盘时重点核查。
3. **回归检查**：修改一个文档后，检查是否影响其他文档的引用一致性（如 `00-Router.md` 中的铁律是否与 `01-Entry-Rules.md` 的条件一致）。

# 00 索引（AI 执行索引）—— 板块多空选股跟随

> 读法：§1 输入与定位 → §2 铁则 → §3 执行四步 → §4 计划 JSON 模板 → §5 落地执行（须用户确认）→ §6 边界与失败。
> **原理来源**：[ReadME.md](ReadME.md)（多空选股回测报告）。本功能把回测验证过的原则落到实盘策略上：AI 选股报告（≥4.0 分）出标的，大盘报告出方向闸门（看多 80/20、震荡 50/50、看空 20/80，可用户覆盖），`PAIR-GRID-*` 策略出持仓；资金分配 = 多空独立额度 + 单票最大投入上限 + **等权削减**；执行纪律 = **10 日强平** + **开盘跳空>2% 机械跳过（不追，按方向：多高开/空低开）**。
> 策略类：`multi_purpose_grid_Strategy`（多用途网格，vnpy_mcp `cta_strategy_get_classes` 确认在册）；策略命名铁律：**`PAIR-GRID-<vt_symbol>-<股票中文名>`**，vt_symbol 为 `conid.SMART` 格式（严禁 ticker.SMART）。

---

## 1 输入与定位

| 项 | 内容 |
|---|---|
| **必填入参** | **可用持仓总金额**（美元，如 `1000000`）。用户未提供 → 先问，**不得猜、不得用账户余额顶替** |
| 可选入参 | **多空配比**（多占比, 空占比，两者之和=1）。用户显式指定 → 用用户值（覆盖分档默认）；未指定 → 按铁则 2 分档。计划中须注明配比来源 |
| 可选入参 | **单票最大投入**（P，美元，默认 `200000`）：单票目标金额硬顶（铁则 4） |
| 可选入参 | **偏差阈值**（默认 `10%`）：已有持仓金额与单票目标金额的容忍带，带内一律"保持"，避免频繁改参 |
| 输出 | 仓位调整计划 JSON（**说明性**，不自动落地） |
| 落地 | 计划经用户**明确确认**后才调用 vnpy_mcp 执行（§5） |
| 数据新鲜度 | 每次全量重跑：三份报告 + 策略清单只认 vnpy_mcp 实时返回，不缓存、不沿用上一轮计划 |

## 2 铁则（违反即判漂）

1. **分数门槛**：以选股报告 `评分卡结果[*].反方审查.调整后总分` ≥ **4.0** 为准；无 `反方审查` 段时退回 `总分`。低于 4.0 一律不进目标清单（含观察清单）。
2. **方向配比（分档为默认、可被用户覆盖）**：默认只认大盘报告 `macro_summary.direction`（或顶层 `direction`）**前两字** —— `看多`→多 80%/空 20%、`震荡`→50%/50%、`看空`→多 20%/空 80%。用户显式指定配比（之和=1）→ **用用户值**，计划注明"配比来源=用户指定"。前两字不在此三字之内（如"中性"）→ 未指定配比时**中止并报告**，不得自选配比；已指定用户配比则照常使用并在 `风险提示` 注明"direction 无法分档，按用户指定配比执行"。
3. **多空独立额度、互不挪用**：多头额度 = 可用持仓总金额 × 多占比，空头额度同理；总敞口 = 两额度之和（恒 100%），额度**只约束新建仓与目标金额**；已有持仓不直接因本轮计划被平仓（唯一例外是 10 日强平，铁则 10）。等权削减（铁则 4）只调整 `start_asset`（资金基数），不直接发卖单。
4. **单票目标金额（等权）** = `min(P, 该方向额度 ÷ N_after)`；P = "单票最大投入"（入参，默认 $200,000 硬顶），N_after = 本轮执行后该方向持仓只数（已有保留持仓 + 本轮新入场，不含人工确认/非目标桶）。**等权削减**：该方向本轮有新入场（新建/调整入场/重入）时，将超目标（偏差>阈值）的已有持仓 `start_asset` 削减至目标金额——**只削不增**（对应回测 equal 再平衡）；该方向无新入场则不触发削减。
5. **conid 是唯一匹配键**：报告 ticker ↔ 已持仓策略的匹配，一律经 conid 对照（`search_vt_symbol` 正向 / `vt_symbol_info.json` 双向），**禁止按中文名、英文名匹配**（报告是英文名，策略名是中文名，必错）。
6. **持仓期不做方向翻转**：已持仓策略方向与本轮目标相反 → 标 `人工确认`，**不自动反向、不自动平仓**（多用途网格铁则：方向只在仓位=0 翻转）。
7. **只读实时**：策略清单/持仓/参数只认 vnpy_mcp 当轮返回；`运行状态` ≠ 运行中的 PAIR-GRID 策略不算"已持仓"，单独列备注。
8. **计划必须闭合**：取不到的字段填 `missing` 并说明，不得删字段；额度、目标数、分配合计三者对不上（Σ分配 ≠ 目标额度和）= 计划无效，重算。
9. **空壳策略清理**：运行中的 PAIR-GRID 策略 `实际持仓=0` 且标的**不在**本轮 ≥4.0 目标内 = "没必要存在" → 列入 `删除清单`（`cta_strategy_delete` 要求 pos=0，可直删；执行仍需用户确认）。**有持仓**的非目标策略：持有天数 <10 → 不动（由策略自身止损接管）；持有天数 ≥10 → 按铁则 10 十日强平。
10. **10 日强平**：持仓持有期按 `开仓时间` 起以**自然日**计，**满 10 日强制平仓**（对应回测强平）。多用途网格**无内置** 10 日强平机制，这是**本功能的跟踪义务**：每轮计划做到期检查，持有天数 ≥10 一律列入 `到期强平清单`（无论是否在本轮目标内），用户确认后平仓、下一轮复核 pos=0；若该标的仍在本轮目标内，平仓后按新一轮**重入**（对应回测 MU 两次入场）。
11. **不追（机械，按方向）**：新入场（新建/调整入场/重入）的**执行日**，**多单**开盘**高于前收 2% 以上**（追高）或**空单**开盘**低于前收 2% 以上**（追低）→ **机械跳过该标的本轮入场**（不新建/不激活），记入 `skipped_不追高` 与 `风险提示`；**不自动重试**（等下一轮报告信号）。反向跳空（多单低开 / 空单高开）不触发——对空头而言高开不是追高（入场价更高、至目标空间更大），对多头而言低开同理。首仓价格区间（报告建仓区间）是策略内第二道防线（多=上限、空=下限），本条是执行日前置闸门。

## 3 执行四步

### Step 1 拉信号（vnpy_mcp，3 次 `cta_report_get`）

```
cta_report_get(report_kind="美股大盘与板块和资金流向分析", report_index=-1)
cta_report_get(report_kind="美股做多选股结果",       report_index=-1)
cta_report_get(report_kind="美股做空选股结果",       report_index=-1)
```

- 大盘报告 → `direction`（前两字定档）、报告时间（`analysis_time`）；**无前视**：只采用发布时间 ≤ 当前时刻的报告。
- 两份选股报告 → 各自 `评分卡结果` 中 调整后总分 ≥4.0 的条目 → 目标标的，字段取：`ticker` / `name` / 分数 / `入场计划`（建仓区间、止损位、第一目标、第二目标）/ 报告时间戳。
- 核对两份选股报告的 `analysis_time`：若一大一新（跨天），在计划 `风险提示` 中注明"两份报告不同批"。
- 某报告 `cta_report_get` 返回"报告不存在" → 说明对应 AI 任务尚未跑（可用 `macro_task_run` 触发），**中止并报告**，不得用旧计划顶替。

### Step 2 盘点 PAIR-GRID 策略（vnpy_mcp）

```
cta_strategies_get_all()
```

1. 过滤 `策略名称` 以 `PAIR-GRID-` 开头 且 `运行状态` = 运行中 的策略；已停止的同名前缀策略单列 `备注`（不计入已持仓）。
2. 每个策略从返回中取（`cta_strategies_get_all` 返回自带，**不必逐个再查**）：
   - `vt_symbol`（`conid.SMART`）、`品种信息.conid` / `品种信息.ticker` / `品种信息.name_cn`
   - `实际持仓`、`持仓均价`、`操作方向`（多/空/无）
   - **当前持仓金额 = |实际持仓| × 持仓均价**（多空同口径，均按占用现金计）
   - `start_asset`（可用 `cta_strategy_get_status(策略名)` 的"策略基础参数设置和当前变量"读 `start_asset` 核对）
3. 匹配：本轮每个目标 ticker → `search_vt_symbol(market="IB", query=ticker)` 得 conid（或 `vt_symbol_info.json` 查 conid）→ 与 PAIR-GRID 策略集合按 conid 求交。
   - conid 查不到（返回空）→ 该标的标 `missing`，**不创建、不猜测**，写入计划说明。
4. **持有天数**（铁则 10 到期检查用）：对每个**有持仓**的 PAIR-GRID 调 `cta_strategy_get_status(策略名)` → "持仓上下文" → `开仓时间`，算 **持有天数 = 今天 − 开仓时间（自然日）**；`开仓时间` 取不到 → 标 missing，不列入强平清单，`风险提示` 注明（不猜持有天数）。

### Step 3 计算调整计划

1. **方向配比**：用户显式指定 → 用用户值；否则 direction 前两字 → 多/空占比（铁则 2）。无论哪种来源，`多头额度 + 空头额度 = 可用持仓总金额`。
2. **额度**：`多头额度 = 可用持仓总金额 × 多占比`；`空头额度 = 可用持仓总金额 × 空占比`。
3. **单票目标金额（等权）**：`T = min(P, 方向额度 ÷ N_after)`（多、空各算）；P = 单票最大投入（入参，默认 200000），N_after = 本轮执行后该方向持仓只数（已有保留持仓 + 本轮新入场，不含人工确认/非目标桶）。
4. **10 日到期检查（先于分类执行）**：每个有持仓的 PAIR-GRID，持有天数 ≥10 → 列 `到期强平清单`（铁则 10，**无论是否在本轮目标内**）：
   - 在本轮目标内 → 注明"平仓后按新一轮**重入**"（与同方向新入场标的共用同一等权基数 T）；
   - 非目标 → 注明"平仓后策略变空壳，列入下一轮删除清单（或本轮平仓后由用户确认直接删除）"。
5. **逐标的分类**（先虚拟平掉到期持仓，再分类；T = 单票目标金额，A = 该标的现有 PAIR-GRID 当前持仓金额，行按序判定）：

| 现有 PAIR-GRID | 有持仓 | 方向一致 | 条件 | 动作 |
|:--|:--|:--|:--|:--|
| 无 | — | — | — | **新建**：建策略 + 分配 T |
| 有 | 有 | ✅ | A > T 且该方向本轮有新入场 | **等权削减**：`start_asset` → T（只削不增，铁则 4） |
| 有 | 有 | ✅ | \|A−T\|/T > 偏差阈值 | **调整**：`start_asset` → T（策略网格自行收敛仓位） |
| 有 | 有 | ✅ | \|A−T\|/T ≤ 偏差阈值 | **保持**：不动 |
| 有 | 无 | ✅ | — | **调整/重入**：`start_asset` → T（空仓、方向对，策略自行入场；到期平仓后重入属此行） |
| 有 | 无 | ❌ | — | **调整**：仓位=0 可翻转 `base_direction` → 本轮方向，`start_asset` → T |
| 有 | 有 | ❌ | — | **人工确认**：持仓期不可翻转；保持现状，交用户决策 |

   - 偏差 = |A − T| / T，阈值 = 偏差阈值（入参，默认 10%），带内一律"保持"，避免频繁改参；
   - **等权削减（回测 equal）**：该方向本轮有新入场（新建/调整入场/重入）时，超目标的已有持仓削至 T，**只削不增**——低于 T 的持仓不因新入场而被补仓（偏差超阈值时仍按"调整"行独立处理）；该方向无新入场则不触发削减。
6. **非目标策略**：运行中的 PAIR-GRID 策略若 conid 不在本轮 ≥4.0 目标内：
   - `实际持仓 = 0` → 列 `删除清单`（铁则 9），用户确认后执行 `cta_strategy_delete`；
   - `实际持仓 ≠ 0` 且持有天数 <10 → 列 `保持不动_非目标`，**不操作、不关闭**（由策略自身止损接管），仅提示；
   - `实际持仓 ≠ 0` 且持有天数 ≥10 → 已列 `到期强平清单`（第 4 项），不重复列。
7. **闭合自检**：Σ(T × 该方向执行后持仓只数) ≤ 方向额度；总敞口 = Σ多分配 + Σ空分配；三者对不上即重算（铁则 8）。

### Step 4 输出计划 JSON

按 §4 模板输出，并附一段 ≤5 句的中文摘要（方向档、多/空各几只、新建/调整/等权削减/保持/人工确认/强平/删除各几只、总敞口）。

## 5 落地执行（仅当用户明确确认后）

> 用户未确认前，本功能**只输出计划**，不调任何写接口。确认后按"先强平（到期强平清单）→ 再调整（含等权削减）→ 再新建 → 最后删除"顺序执行，每步**设置后必须读回验证**（`cta_strategy_get_status` / `cta_strategy_get_parameters_info`）。
> **执行日闸门（铁则 11，不追，按方向）**：每个新入场标的（新建/调整入场/重入）执行前，核对当日开盘 vs 前收——**多单高开 >2%（追高）或空单低开 >2%（追低）→ 机械跳过该标的**，记入 `skipped_不追高`（ticker + 跳空幅度），**不自动重试**（等下一轮报告信号）。

| 动作 | MCP 调用 | 要点 |
|---|---|---|
| 强平（10 日到期） | `cta_strategy_close(策略名)` | 仅限 `到期强平清单` 内标的；平仓前复验 `实际持仓`（pos=0 则跳过并标记已平）；平仓后确认返回 success，**下一轮复核 pos=0**；标的在本轮目标内的按"重入"计划在其后执行 |
| 调整（start_asset / base_direction，含等权削减） | `cta_strategy_set_parameters(策略名, {"start_asset": T, ...}, reason="板块多空选股跟随 <日期>：大盘<方向档>→<方向>额度<额度>，<ticker> 目标<T>，现<A>，偏差<偏差>，<等权削减/偏差调整>")` | `reason` 必填（须注明触发来源）；改 `base_direction` 仅允许在 `实际持仓=0` 时；等权削减只削不增（A≤T 的标的不动）；改完读回核对 |
| 新建 | `cta_strategy_add_and_start(class_name="multi_purpose_grid_Strategy", strategy_name="PAIR-GRID-<conid>.SMART-<中文名>", vt_symbol="<conid>.SMART", setting={...})` | 先过执行日跳空闸门（多高开/空低开 >2% 跳过，铁则 11）；vt_symbol 必须 `conid.SMART`；setting 见下 |
| 删除（空壳策略） | `cta_strategy_delete(策略名)` | 仅限 `删除清单` 内（运行中 + 持仓=0 + 非目标）；**执行前再查一次 `实际持仓` 复验 pos=0**（防计划生成后刚建仓）；删除后确认返回 `success` 且策略不在 `cta_strategies_get_all` 中 |
| 人工确认 / 保持 / 非目标 | 不调用 | 原样转述给用户 |

## 6 边界与失败处理

| 情形 | 处理 |
|---|---|
| 用户未给可用持仓总金额 | 先问，不猜、不取账户余额 |
| 用户给的多空配比之和 ≠ 1 或某侧为 0 | 不采用，退回分档默认并在 `风险提示` 说明；如用户坚持则先确认再执行 |
| 用户给的单票最大投入 ≤0 或非数值 | 不采用，退回默认 200000 并在 `风险提示` 说明 |
| `开仓时间` 缺失、持有天数算不出 | 不列入 `到期强平清单`，`风险提示` 注明（不猜持有天数） |
| 任一报告不存在 | 中止，提示先跑对应 AI 任务（`macro_task_run`），不用旧数据顶替 |
| `direction` 前两字 ∉ {看多, 震荡, 看空} | 未指定用户配比 → 中止并报告，不自选配比；已指定 → 按用户配比执行并注明 |
| 某方向 ≥4.0 标的为 0 | 该方向额度为 0、不建不调整；计划照常输出并在 `风险提示` 说明 |
| 两方向都无标的 | 输出空计划（仅 `保持不动_非目标` 与说明），不执行任何操作 |
| ticker → conid 查不到 | 该标的 `conid: missing`、动作 `missing`，不创建不猜测，列入 `风险提示` |
| 现有 PAIR-GRID 策略名不合规（无法解析 vt_symbol） | 按"非目标"处理并列 `备注`，提示用户规范命名 |
| 已停止的 PAIR-GRID 策略 | 不计入已持仓；`备注` 列出，是否复活由用户定 |
| 额度不足（标的数 × 20 万 > 方向额度） | 正常发生：单票目标金额 = 额度 ÷ 标的数（自动低于 20 万上限），无需特判 |
| 删除执行时 `实际持仓 ≠ 0`（计划生成后刚建仓） | 不删除；把该标的移入 `人工确认` 并告知用户（`cta_strategy_delete` 本身也会因 pos≠0 拒绝） |

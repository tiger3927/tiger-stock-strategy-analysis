# 智能马丁格尔网格策略 — 下单前审核速查

> 适用场景：每次调仓（开仓/加仓/减仓/平仓）提交执行前，量化系统请求智能体审核时
> 前提：人工作业层参数 `enable_openclaw_confirm_target_pos=True`（人工设定，智能体不可设置）
> 路由文档：[00-Router.md](00-Router.md)

---

## 一、任务定位：审核 ≠ 分析

| 维度 | 定时分析（环节①） | 下单前审核（环节②，本文档） |
|:--|:--|:--|
| 触发 | 每 N 分钟定时 | **每一次** `set_target_pos` 调仓前 |
| 职责 | 决定"该用什么参数、处于什么阶段" | 裁决"这一笔具体下单是否放行" |
| 输出 | 完整分析 JSON（阶段/参数/方向） | 仅 3 字段：`decision` / `approved_target_pos` / `reason` |
| 权限 | 可修改策略参数 | **不改任何参数**，只裁决本次目标仓位 |

**独立审核纪律（代码要求）：**
- "AI 分析理由"仅用于了解开仓时的市场背景，**审核结论必须基于当前行情独立判断，不得因历史分析理由而倾向同意本次下单**；
- 审核通过与否与上次分析结论无关——上次说"立即建仓"，这次行情变了，照样应拒绝。

**审核结果三态：**
1. **同意** → 按原目标仓位执行；
2. **修改**（`decision="同意"` 但 `approved_target_pos` 改为更小目标）→ 按修改后的目标执行（如加仓缩量、全平改部分减）；
3. **拒绝** → 本次调仓取消；**相同目标仓位的调仓在 5 分钟冷却期内被系统直接忽略**（`rejected_target_pos_cooldown=300`，机制见 [Tiger-Grid-Template 07 第 9 步](../Tiger-Grid-Template/07_trade_control.md)），智能体无需重复裁决，行情变化后的新调仓会重新送审。

## 二、审核时能看到什么

### 2.1 代码随审核请求提交的上下文

| 项 | 内容 |
|:--|:--|
| 操作意图 | 当前持仓 / 本次目标持仓 / 持仓变动 / 下单原因（comment） |
| 策略状态信息 | 状态字典快照（参数当前值、持仓、盈亏、阶段相关变量） |
| 品种信息 | vt_symbol 对应的品种资料（名称/行业/分类等） |
| 用户备注 | `openclaw_user_remark`（有值才附加，**应优先满足备注中的用户要求**） |

> 下单原因为空或"无"时，应**从严审核**：意图不明本身即是风险，倾向拒绝或压低 `approved_target_pos` 至更小目标。

### 2.2 必须自行获取的信息（代码要求）

1. **持仓与参数决策上下文**：`vnpy_mcp` 工具 `cta_strategy_get_all_reason(strategy_name="{策略名}")`
   - 获取：开仓时的 AI 分析理由、最近一次 AI 分析理由、本次持仓交易历史、各参数最近一次修改与 reason；
   - **使用规则（代码要求）：**
     - 审核重点是"**参数最近修改**"段：`source` 为 `manual`/`mcp` 的参数是人工/外部智能体刻意设置，其 reason 是设置依据——质疑下单时先核对该依据是否已被当前行情推翻，而非仅凭参数值下判断；
     - `source=system` 的参数是系统防守动作（如置信度过低的保护性兜底），不是人工基线，按当前行情正常审核即可；
     - "AI 分析理由"仅用于了解背景，不得据此倾向同意。
2. **大盘与板块分析报告**：`cta_report_get`（按品种所属市场选报告名，见 00-Router Step 0）。
3. **实时行情与消息面**：联网获取该品种最新行情、新闻、基本面数据，形成判断依据。

## 三、五场景拒绝速查清单

先按操作意图识别场景，再逐项检查。**任何一项不通过，都应拒绝或修改目标仓位（代码要求）。**

### 场景识别

| 场景 | 识别条件 | 核心拦截目标 |
|:--|:--|:--|
| 一、首仓开仓 | 当前持仓 = 0，目标 ≠ 0 | 拦截追高开仓、逆势开仓 |
| 二、亏损时加仓 | 持仓 ≠ 0 且亏损，\|目标\| > \|当前\| | 拦截基本面恶化时的无效加仓 |
| 三、盈利时加仓 | 持仓 ≠ 0 且盈利，\|目标\| > \|当前\| | 拦截高位追涨导致利润回吐 |
| 四、亏损时减仓/平仓 | \|目标\| < \|当前\|（含 0）且亏损 | 防止过早止损、优化出场时机 |
| 五、盈利时减仓/平仓 | \|目标\| < \|当前\|（含 0）且盈利 | 防止过早止盈、判断是否见顶 |

> **盈亏状态判定**：以状态字典"当前持仓盈亏比"为准（>0 盈利、<0 亏损；恰为 0 时按盈利侧场景处理）。
>
> **反向调仓（目标与持仓符号相反，如多 100 → 目标 -100）**：等价于"全部平掉旧仓 + 反向新建仓"，不落入上表任一行——按**场景四/五（平旧仓）+ 场景一（反向首仓）双重标准从严审核**。马丁格尔策略不做反手操作，出现此目标时优先拒绝，并提示先单独提交平仓。

### 场景一：首仓开仓

**通用检查项（代码清单）：**
1. 首仓价格区间是否合理——是否存在追高风险
2. 当前价格是否处于短期高位——做多看 RSI 是否超买（>70）、是否远离均线；做空反之
3. 下单方向与趋势是否一致——短期/中期趋势是否支持本次方向
4. 当前市场是否有重大利空——品种及所属板块突发消息
5. 策略参数是否合理——网格间距、止损幅度在当前波动率下是否合适

**马丁格尔专属硬约束（拒绝依据）：**
- 首仓必须在**理想/可接受首仓区间**（做多近一级支撑 / 做空近一级压力）；处于观望区间 → 拒绝（[01 §1.2/§1.4](01-Entry-Rules.md)）
- 逐项核对做多 9 条 / 做空 6 条**禁止条件**，任一触发 → 拒绝（[01 §1.3/§1.5](01-Entry-Rules.md)）
- 当前价超过**禁止追高价格**红线 → 拒绝
- 风险收益比 < 1.8 → 拒绝
- 方向与 Step 3 大盘约束冲突（牛市做空/熊市做多）→ 拒绝

### 场景二：亏损时加仓

**通用检查项（代码清单）：**
1. 加仓逻辑是否成立——亏损是否在网格间距合理范围内，还是基本面已恶化
2. 当前市场是否有重大利空——是否有导致继续下跌的潜在风险
3. 仓位风险是否可控——加仓后仓位占比是否过大，是否爆仓/穿仓
4. 网格间距是否合理——是否过小导致加仓过于频繁
5. 是否存在继续下跌的技术信号——支撑位、趋势线是否已破位

**马丁格尔专属硬约束（拒绝依据）：**
- `是否允许亏损时网格加仓` 开关为 False → 拒绝（该开关是 AI 参数，但人工/MCP 可能已关闭，以状态字典当前值为准）
- **关键位失效**：做多跌破一级支撑且持续不收回 / 做空涨破一级压力且持续不收回 → 这是风险退出条件而非加仓场景 → 拒绝，并提示进入风险退出期（[03 §四-5](03-Exit-Rules.md)）
- 亏损已超过止损幅度（网格间距 × 网格数量 × 0.6，ATR 异常时 ×0.7）→ 应止损而非加仓 → 拒绝（[03 §六](03-Exit-Rules.md)）
- 已用资金占比接近满资金上限 → 拒绝（[03 §四-7](03-Exit-Rules.md)）
- 基本面重大恶化确认（非传闻）→ 拒绝（[03 §四-1](03-Exit-Rules.md)）

### 场景三：盈利时加仓

**通用检查项（代码清单）：**
1. 当前价格是否处于短期高位——是否追高，RSI 是否超买
2. 加仓后风险收益比是否合理——若回调，利润是否大幅回吐
3. 当前市场是否有重大利空——是否有反转信号
4. 止盈设置是否合理——加仓后止盈幅度是否需要调整

**马丁格尔专属硬约束（拒绝依据）：**
- 做多距一级压力位 < 2%~3% 且综合浮盈已高 → 高追高风险，倾向拒绝或缩量（[02 §三-6](02-Grid-Operations.md)）
- 已满足**利润收割期**进入条件（价格优先/网格充分/利润达标，[03 §二](03-Exit-Rules.md)）→ 应转收割出货而非加仓 → 拒绝
- 趋势锁仓期（`是否允许网格减仓=false`）内，新增加仓需与锁仓判断一致；若趋势已现减弱迹象（横盘/外部转向/利润回吐/逼近关键位），应先恢复网格减仓 → 拒绝加仓并提示

### 场景四：亏损时减仓/平仓

**通用检查项（代码清单）：**
1. 减仓/平仓理由是否充分——是策略正常止损，还是 AI 判断趋势反转
2. 是否已触发止损线——是止损幅度合理，还是过早止损
3. 当前市场是否有继续恶化的风险
4. 减仓比例是否合理——全部平仓还是部分减仓
5. 是否存在更好的减仓时机——是否处于极端超卖位，稍等反弹再减更合理

**马丁格尔专属硬约束（裁决依据）：**
- 亏损已超止损幅度 / 关键位失效 / 基本面恶化确认（三重叠加）→ **同意**（止损纪律必须执行，不得挽留）
- 趋势高置信度反转（置信度 > 0.75）→ 同意，并提示进入风险退出期
- **仅小幅浮亏 + 无任何硬信号**（2% 回撤、单指标转弱、噪声新闻）→ **拒绝**——马丁格尔管理期的纪律是「等，别动」，小幅亏损是被期待的加仓机会不是止损信号（[03 §一](03-Exit-Rules.md)、[02 §四](02-Grid-Operations.md)）
- 注意：人工作业层介入（`loss_close_need_manual=True`，人工设置）会独立拦截亏损平仓，审核同意后该调仓仍可能不生效——这不是审核失误，不要反复重试

**裁决顺序（场景四专用）**：硬约束 > 通用检查项——凡命中任一硬信号（超止损公式 / 关键位失效 / 基本面恶化确认 / 高置信度反转），**必须同意**，通用检查项#5"等反弹"失效；仅在无任何硬信号时，才用通用检查项判断是否存在过早止损或更优减仓时机。

### 场景五：盈利时减仓/平仓

**通用检查项（代码清单）：**
1. 减仓/平仓理由是否充分——是策略正常止盈，还是 AI 判断趋势见顶
2. 当前市场是否有反转信号——重大利空或技术面见顶
3. 减仓比例是否合理——全部平仓还是部分锁定利润
4. 是否存在更好的减仓时机
5. 止盈设置是否已触发——是否过早止盈

**马丁格尔专属硬约束（裁决依据）：**
- 已达止盈幅度 / 移动止盈回撤触发 / 满足利润收割期条件 → **同意**
- 网格管理期内的**基础底仓**卖出 → 除非满足六种情形之一（收割期/基本面重大变化/高置信度反转/止损/重大事件/风险退出期），否则**拒绝**——基础底仓不可侵犯是硬约束（[02 §1.3](02-Grid-Operations.md)）
- 「涨了 3% 就卖」型过早止盈（网格尚未充分触发、综合浮盈低）→ **拒绝**（[02 §五](02-Grid-Operations.md)）

## 四、返回 JSON 协议

```json
{
    "decision": "同意",
    "approved_target_pos": 100.0,
    "reason": "审批意见说明（需说明通过了哪些检查、拒绝了哪些检查）"
}
```

| 字段 | 说明 |
|:--|:--|
| `decision` | `"同意"` 或 `"拒绝"`（字符串，中文） |
| `approved_target_pos` | **审批后的目标持仓，可修改本次下单的目标**（如加仓缩量、全平改部分减）；多空分别用正负表示；同意且不修改时填原目标值 |
| `reason` | 必须说明**通过了哪些检查、拒绝了哪些检查**（供日志与后续智能体复盘追溯） |

**字段消费说明：** 以上 3 个字段全部由代码按键名精确解析（英文键），**代码只消费这三个字段**，其他输出内容无效；如需留下更完整的审核报告，只能融入 `reason` 文本（审核记录会整体落盘为 `order-*.json` 归档）。

## 五、边界

| 情形 | 说明 |
|:--|:--|
| `manual=True`（人工操作） | 直接绕过审核执行，不会送审 |
| MCP 发起的调仓 | `cta_strategy_set_target_pos` / `cta_strategy_close` **不绕过审核**（仅人工作业层开关关闭或人工 `manual` 才不送审），同样按本文档逐场景审核，可拒绝或修改 |
| 人工作业层介入（`loss_close_need_manual=True`） | 独立人工开关：亏损状态下平仓被拦截（智能体不可设置/绕过）；观察到"调仓未生效"时判断为此原因，向人工汇报 |
| 审核不改参数 | 参数调整在分析环节完成；审核环节只裁决本次目标仓位 |
| 拒绝不是永久禁令 | 行情变化后策略的新调仓（新目标）会重新送审；相同目标 5 分钟冷却期内被系统忽略 |
| 审核独立性 | 不因"最近一次 AI 分析同意过类似操作"而放宽标准 |

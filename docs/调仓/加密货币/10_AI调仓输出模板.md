## §11.2 字段说明

**通用规则**（与美股组一致）：

- 字段全部保留；取不到值填 `null` 或 `"missing"`，**不得删除字段**；
- 报告名固定「**加密货币板块轮动调仓**」，须与定时任务名、落盘文件夹名逐字一致（README §6 命名铁律）；
- 每个策略（含新增策略）必写「意图备注」（开仓目的/预期/退出条件），持仓期每轮更新；
- 调仓相关参数只写与本次调仓有关的项；数值字段纯净（只留数值/布尔/枚举，注解进 意图备注/调仓理由）；
- `操作模式` 为纯枚举，判定理由写「风控校验.大盘状态确认」；
- 前三大板块必须按调仓后板块 % 降序取最大三个，列三分项明细；
- 层级必须与动作一致（S1/S2 不得减仓清仓，S5 不得加仓，04 §6.2）；
- `失效代码`：只记录、任务内不改码，修复在任务外经用户批准；
- verify「通过」是任务唯一完成判据（00 §4.1-4）；assemble 骨架只装配数值与结构，填完仍必须 verify 复算；
- **两个资金口径的写法（2026-09-15 新增；v2.6.0 qty-first 修订）**：`调仓指令.槽位资金` ＝ **决策口径**（未取整＝1 个基准槽位；verify 门槛/缓冲基准，v2.6.0 新字段）；`调仓指令.目标资金` ＝ **落地口径**（= 目标持仓 × 现价）；`目标仓位占比_pct`、`资金汇总.买入使用 / 净额 / 剩余现金`、`分析摘要.调仓后总仓位_pct`、`目标分配.<板块>.目标_pct` ＝ 落地口径。两者差异 = 取整损失，属正常（06 §7.3.1.2 两口径落位表）。**verify 兼容模式**：指令含 `槽位资金` 字段 → 按 qty-first 判（门槛/缓冲基准 = 槽位资金）；无该字段的旧口径报告 → 按 v2.5.0 规则（`目标资金` = 决策口径，别名 `目标资金（决策口径，可选）` 仍被识别），历史报告可 verify；
- **AI 可写区收敛（v2.6.0，探索版命题①吸收）**：数值字段一律来自工具链产物（fund/gap/score/score2/leaders/map/cycle/gate.json），AI 只撰写**文本字段**：`意图备注` / `调仓理由` / 分批 `日期与说明` / `执行建议` / `数据缺失与冲突` / `待人工确认` 闭环文本 / `风控校验` 自报文本 / `数据溯源.备注`；gate 机判产出后，`风控校验.大盘状态确认` 直接引用 gate.json 逐条证据（不再手写千字论证——2026-09-16 实测「判定不可复算」的根治）；
- **`资金现状.策略资金` 条目（2026-09-15 验收复盘新增）**：除 06 §7.3.1.1 的三键（可用资金总量 / 已使用资金占比 / 可用空间）外，必须带 `运行状态`（运行中 / 已停止）与 `执行前置`（注资额度 / 启动策略 / 开关确认）。有指令时必须写明，否则外部验收无法判断「报告里的指令是否可执行」（13 §3.14 / §2.3）；
- 资金汇总中 策略初始资金合计/目标仓位总和/目标组合策略数 取自 fund 规划槽位（「从零建 N 仓」），须标注「规划值」，不得与「本轮目标」混读；
- **子板块字段命名权威**：`使用 强势子板块 / 弱势子板块`（与 `rebalance_tools.py score2/map` 输出一致）；`子维度` 仅作概念名（03 §5）使用，不得出现在报告字段名中（00 §4.6-2 命名权威）；
- **`数据溯源`（币版强制，第 18 顶层字段）**：`{"行情末根日期": "YYYY-MM-DD", "账户快照时间": "...", "大盘报告时间": "...", "备注": "口径与 as_of 说明"}`。K 线/快照/报告三种 as_of 一律在此声明，正文引用须一致；verify 会校验该块存在且字段齐全（美股组无此项）；
- **数据时效纪律（2026-09-15 复盘新增）**：行情日 K 来自网关，**实测滞后约 2 日**（12 §13.6），因此 ① 1d/5d/7d 等派生数字必须写明 as_of；② 时效 ≤ 1 日才可按「当期」口径表述，≥ 2 日必须改写为「截至 <末根日期>」并在 限制说明中降级；③ 末根收盘价与实时价偏差 > 1.5% 的标的，须在 数据缺失与冲突 逐条列出；
- **数字可溯源纪律**：报告正文（分析摘要/目标分配/执行建议/数据缺失与冲突）中出现的每个百分数、金额、条数，必须能指回「来源文件 + 字段 + as_of」；**禁止凭记忆写入**（`rebalance_audit.py` 会列出未命中工具输出的数字作为提示项，须逐条确认出处）；
- **手工覆盖留痕**：凡对 score/score2/map 输出做过改动（如 02 §4.2.5 龙头确认降档），须在 `数据缺失与冲突` 写「手工值 + 原因 + 依据条款 + 原始清单差异」；`rebalance_audit.py` 会把「清单与工具输出不一致但无手工留痕」判为不通过；
- **空报告（0 指令）必备留痕**：除 00 §4.1-1 的「无调仓」依据外，还须 ① `目标分配` 覆盖**全部 10 个板块**并逐条说明「目标 = 当前」的原因（含不可开/未确认的实测依据）；② 写明下一轮重评触发条件（事件/窗口/广度阈值）。

**分批计划规则**（按单条指令定，不强行拆 2-3 天）：

- 最少 1 条；必须拆多条的条件：单笔金额 > 该币 24h 成交额的 1% / 执行期跨越事件窗口（资金费率结算 / FOMC / 解锁日）/ 动作为 减仓/清仓；
- 维持/条件触发型：只写 1 条 + 触发条件，**禁止凑批**；
- 自洽规则：`目标持仓(i) = 目标持仓(i-1) − 本批数量`（加仓对称 +），各批数量之和 ≤ 当前持仓（减仓）/ 各批增量之和 = 目标−当前（加仓）；
- **数量单位（币版，2026-09-15 新增）**：各批 `目标持仓` 必须是该币 **`volume_min_unit`（最小交易单位）的整数倍**；**末批 = 指令目标持仓**（按比例取整产生的残差由末批补齐）；取整后为 0 个单位的批次并入下一批（**禁止空批**）；**禁止**非整数倍数量（如 0.135，即使 0.13 合法）；数量与拆单档位口径见 06 §7.3.1.2 / 08 §9.1；
- **数值形态（币版）**：`目标持仓` **可为小数**（如 `0.13` = 13 × 0.01），不是美股「整股」；不得因小数为 0 就断言「不可开」（须按 06 §7.3.1.2 判最小名义额）。

**调仓相关参数参考清单**（martin 参数组，标准中文名以 `Tiger-Grid-Template/02_parameters.md` 为准）：

| 组 | 字段 |
|----|------|
| 方向 | 操作方向 |
| 资金 | 建议首仓占比 |
| 止盈止损 | 是否允许止盈/止盈幅度、是否允许止损/止损幅度、是否允许移动止盈/启动幅度/回撤幅度、是否允许ATR动态止损/止盈、ATR周期/倍数 |
| 网格 | 是否允许网格主动开仓/盈利时网格加仓/亏损时网格加仓、网格间距、网格数量、是否允许卖出基础底仓/网格减仓、网格止盈、基础底仓分批出货比例 |

> 币场景默认参考：止损幅度 0.08 基准、网格间距 0.03 基准（04 §6.3 三道闸结果须反映在参数里，如高费率币不建议开网格）。

**数值字段纯净规则（输出前自检）**：

1. 数值字段只留数值/布尔/枚举；
2. `调仓后总仓位_pct` 的分子 = 调仓后持仓市值（= Σ 各持仓 目标仓位占比_pct × B）；`调仓后现金_pct = 100 − 调仓后总仓位_pct`；交叉核对 `调仓后总仓位_pct ≈ Σ调仓指令.目标仓位占比_pct + Σ未涉及持仓.仓位占比_pct + Σ未映射持仓.仓位占比_pct`；**禁止把 `调仓后现金_pct` 定义成 `剩余现金 ÷ B`**；现金类指标看 `资金现状.现金占比_pct（= 可用现金 ÷ 权益）`；
3. 资金闭环六条 = 06 §7.3.1.5（② 为币版 B ≤ available USDT × 2）。

**verify / assemble / audit 调用**：

```
python scripts/rebalance_tools.py verify --report <本报告.json> --balance <最新USDT权益> --available <最新可用USDT> [--params tests/params.json]
python scripts/rebalance_tools.py assemble --fund <fund.json> --gap <gap.json> [--score ..] [--score2 ..] [--map ..] [--gate tests/gate.json] [--analysis-time "..."] [--mode 积极|正常|防御] [--out 报告.json]
# v2.6.0：--params 继承 fund 一次解析参数（balance/available 省略时取 params.json 快照，显式传参优先）；
#         assemble --gate 省略 --mode/--cycle-stage 时继承 gate 机判结果并写入 待人工确认（留痕）
# 第 5 道闸（2026-09-15 新增）：源对账 + 时效审计——verify 只查报告内部自洽，
# 本步查「报告 ↔ 上游来源」是否一致、数据是否过期、手工改动是否留痕
python scripts/rebalance_audit.py --market 加密货币 --report <本报告.json> \
    --prices <K线原始.json> --fund <fund.json> --gap <gap.json> --score <score.json> \
    --score2 <score2.json> --map <map.json> --cycle <cycle.json> \
    [--live <实时价.json>] [--market-report <大盘报告.json>] [--asof-date YYYY-MM-DD]
```

> `audit` 判定与 `verify` 同级：`校验`= 通过（exit 0）才算交付；「提示项」（未溯源数字 / 末根价与实时价偏差）必须逐条人工确认，不得当作通过。

（币版调用一律加 `--market 加密货币`（v2.4 已落地，12 §13.5）；工具报错/崩溃按「失效代码」降级手工核对 05/06/07 阈值与闭环 6 条并留痕，10 §11。）

## §11.3 周度总结指令

周度执行（09 §10.2）时，报告须额外包含：

1. **本周执行偏差**：上一轮指令清单 vs 实际成交（`get_trades` 核对）的偏差与原因；
2. **下周触发条件监测清单**：07 §8.4 #2/#3/#4 的量化现状（如「L1 公链距 Top 5 边界 0.4 分」）；
3. **池校准状态**：分桶漂移 / 池外币补入 / 解锁日历变化。

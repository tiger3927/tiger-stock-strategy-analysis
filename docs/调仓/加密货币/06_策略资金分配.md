# 加密货币板块轮动调仓 — 06 策略资金分配

> §7.3.1。币版与美股版的关键差异：**USDT 单币种**（无汇率换算）、**无 IB 购买力 ×5**（币安账户层无该概念，杠杆是策略内部参数，组合层不叠加）、**阈值放大**、**base_capital 默认降到 1,000 USDT**。

---

## 任务参数（加密货币默认 | 范围）

| 参数 | 默认 | 范围 | 含义 |
|------|:---:|:---:|------|
| `invest_mult` 投入倍率 | **1** | 1–2 | 目标组合初始资金总和 = 账户 USDT 权益（balance）× 该值；1 = 账户层不加杠杆，2 = 账户层 2 倍（须在任务参数中显式声明，爆仓与资金费率风险放大） |
| `mode` 操作模式 | auto | auto / 积极 / 正常 / 防御 | auto = 由 01 §3.1 三档判定（正常→正常、中性偏弱→防御、收缩→「只卖不买」变体） |
| `max_delta_pct` 单轮调仓幅度上限 | **20** | 5–20 | 单轮 Σ\|目标−当前\| / B ≤ 该值；月度/全量 20，周度微调 5 |
| `max_new` 本轮新仓只数 | 2 | 0–3 | 同美股 |
| `max_single_pct` 单币上限 | 5 | 1–10 | 占总预算 % |
| `max_sector_pct` 单板块上限 | 20 | 10–30 | 占总预算 % |
| `base_capital` 每策略基准资金 | **1000** | 100–10000 | USDT；单币目标资金 < 1 个基准单位 → 不开，并入同板块其他币 |
| `max_strategies` 策略总数上限 | auto | ≤50 | auto = B ÷ base_capital，硬顶 50 |

> **统一口径（00 §4.6-3）**：所有仓位 % 分母一律为 **总预算 B = USDT 权益（get_accounts.balance）× invest_mult**；「总资产」仅指 balance 本身，不是分母。

## §7.3.1.1 资金现状（vnpy_mcp）

| 层级 | 工具 | 取什么 | 用途 |
|------|------|--------|------|
| 账户 | `get_accounts` | balance（USDT 权益）、available（可用 USDT） | B / 闭环 ②③ |
| 策略 | `cta_strategies_get_all` | 各策略可用资金总量、已使用资金占比 | 策略资金块（仅本次涉及策略） |
| 持仓 | `get_positions` | 账户级持仓交叉核对 | 与策略级核对 |

> **USDT 单币种**：基准币种 = USDT，无汇率换算（模板「换算汇率」字段值 = `不适用（单币种）`）；账户若混有非 USDT 条目，一律只取 USDT 条目，禁止跨币种相加或作分母。
> 可用空间 (USDT) ≈ 可用资金总量 × (1 − 已使用资金占比)。

## §7.3.1.2 目标分配（板块 → 币 → 策略）

- **总预算 B = USDT 权益 × invest_mult**；**目标仓位总和 = B ÷ 1.2**（1.2 = 每策略缓冲）；现金 ≥ 5%（仅 invest_mult=1 时，闭环 ④）；
- **板块目标 %（评分档 × 模式）**：

| 板块评分 | 正常 | 积极 | 防御 |
|---------|:---:|:---:|:---:|
| 强势（Top 3-4） | 12%–20% | 15%–20% | 5%–10% |
| 中性（中间） | 5%–12% | 8%–15% | 2%–8% |
| 弱势（Bottom 3） | 0%–5% | 0%–5% | 0%–3% |

- **弱势且当前有持仓的板块 → 目标 = 0**；
- **预算归一化**：系数 k = 目标仓位总和 / (S × B) 等比缩放；缩放后仍须满足 单板块 20% / 前三大板块 ≤ 50% / 单币 5%，触顶则截断、余额分给未触顶板块；
- **币目标**：每板块 1-2 只；T2 龙头目标 ≥ T3；单币目标资金 = 币目标 % × B ≥ base_capital；
- **自检**：`base_capital ≤ max_single_pct% × B`（默认 1000、5% → 要求 B ≥ 20,000；B < 20,000 → 优先调低 base_capital，如取 B ÷ 50；**B < 1,000 USDT → 终止本次调仓**，在执行建议注明）；
- **取整损失条款（2026-09-15 修订：按「最小交易单位」取整，禁止套用美股「整数取整」）**：目标持仓 = 决策口径目标资金 ÷ 现价，**按该币的最小交易单位向下取整**。最小交易单位的权威来源 = **策略参数 `volume_min_unit`**（说明：最小交易单位，程序运行时从交易所自动获取，手工填写只用于回测）；与 `get_contract.min_volume` **交叉核对（实测 30/30 一致）**，不一致时以策略参数为准并留痕。**30 个主流币实测分四档（逐币不同，20 个不是 1）**：

  | `volume_min_unit` | 币 |
  |---|---|
  | 0.001 | BTC、ETH、LTC、DASH |
  | 0.01 | BNB、SOL、LINK、ATOM、ETC、NEO |
  | 0.1 | XRP、DOT、SUI、APT、ARB、OP、INJ、FIL、QTUM、KAVA |
  | 1.0 | DOGE、ADA、AVAX、TRX、NEAR、UNI、VET、HBAR、IOTX、CKB |

  **把「1 枚」当作通用最小单位会得出错误的「不可开」结论**（事故：某币 1 枚 = 719 USDT 对 100 USDT 槽位被误判不可开，实际 0.13 枚 = 13×0.01 = 93.5 USDT 完全可开）；落地口径 < base_capital 而决策口径 ≥ base_capital → 补写 `目标资金（决策口径）` 字段；不得向上取整凑够门槛；
- **最小下单量（强制实测，2026-09-15 复盘新增）**：判定「不可开」必须**实际读回最小交易单位**（策略参数 `volume_min_unit`，或 `get_contract.min_volume`，二者交叉核对），并算出**最小名义额 = 最小交易单位 × 现价**，报告写明「实测值 + as_of + 来源」；**仅凭「整数取整 = 0」断言不可开不予采信**。只有当 **目标持仓 × 现价 < 最小名义额** 时才判不可开 → 并入同板块其他币并注明；同板块亦不可开 → 该板块本轮目标 = 当前值；
- **临界标注（2026-09-15 复盘新增）**：当「1 个最小变动单位的名义额」距 槽位资金 / 单币上限 的差 < 2%，或现价距「该币恰好填满槽位 / 触及上限」的临界价 < 2% 时，必须在 目标分配.依据 与 执行建议 标注「**临界**」并给出临界价，供人工下一轮复核；
- **取整后的口径**：目标持仓 = 决策口径目标资金 ÷ 现价，按 `min_volume` 向下取整；落地金额 = 目标持仓 × 现价，与决策口径不一致时按取整损失条款补写 `目标资金（决策口径）`。
- **两个口径的落位（2026-09-15 验收复盘新增，专治「同一笔钱两个数」）**：

  | 口径 | 定义 | 落在报告的哪个字段 |
  |---|---|---|
  | **决策口径** | 目标资金（未取整＝1 个基准资金槽位） | `调仓指令.目标资金`（**字段名就是 `目标资金`**；verify/audit 的「最小开仓门槛」与「初始资金 ≥ 目标×1.2 缓冲」一律以它为准） |
  | **落地口径** | 目标持仓 × 现价（可下单/可持仓的真实金额） | `调仓指令.目标仓位占比_pct`（＝落地 ÷ B × 100）、`资金汇总.买入使用 / 净额 / 剩余现金`、`分析摘要.调仓后总仓位_pct`、`目标分配.<板块>.目标_pct` |

  **`gap` 快照的 `目标资金` 字段一律填落地口径**（缺口＝落地目标 − 当前市值，才是可执行口径）；`gap` 的 买入使用/净额/剩余现金 与 `verify` 的组合重建、单票上限 亦按落地口径。
  例：决策 100 USDT、现价 717.62、单位 0.01 → 目标持仓 0.13 枚、落地 93.29 USDT＝9.33%×B；报告须同时出现 `目标资金: 100` 与 `目标仓位占比_pct: 9.33`，**两者不一致属正常**（差异＝取整损失）。

## §7.3.1.3 缺口计算（目标 − 当前 → 调仓方向）

- \|缺口\| < **2% × B** → 维持（防过度交易；自美股 1% 放大——加密日均波动 3-8%，1% 缺口属噪声）；
- Σ\|缺口\| / B ≤ max_delta_pct（默认 20%），超出 → 按缺口绝对值从大到小处理，其余币转「维持 + 触发条件」；
- 方向异常核对：缺口 > 0 但板块弱势 → 必须说明（gap 的 `快照告警` 通道）。
- **口径（2026-09-15 验收复盘新增）**：缺口一律按**落地口径**（目标持仓 × 现价）计算 —— 快照 `目标资金` 填落地金额（见 §7.3.1.2 两口径落位表）。取整后「落地 < base_capital」而「决策口径 ≥ base_capital」时，`gap` 会报一条**信息性** `异常`（「目标资金 X < 基准资金 Y」）——该情形正属取整损失条款覆盖范围，须在报告 `数据缺失与冲突` 留痕说明，**不得**据此判「不可开」或反向抬高目标资金。

## §7.3.1.4 策略资金定数（初始资金 / 资金调整）

| 情形 | 规则 |
|------|------|
| 每策略（含新增） | 初始资金 = 币目标资金 × 1.2（上限值，目标仓位 ≈ 初始资金的 83%） |
| 已有策略加仓 | 初始资金 > 策略现初始资金 → 差值 = 资金调整（写入指令 `资金调整`）；小于 → 不削减 |
| 减仓/清仓 | 不动初始资金，只调 持仓目标/操作方向 |
| 总量核对 | Σ 初始资金 = B（fund 槽位分配）；N ≤ B ÷ base_capital（硬顶 50），超出 → 保高弃低（T2 优先，60+ 分桶先弃） |

## §7.3.1.5 资金闭环自检（输出前必须全部通过）

1. Σ 初始资金 ≤ B；
2. **B ≤ 可用 USDT × 2**（账户层杠杆硬顶 = invest_mult 上限 2；invest_mult=1 时即 B ≤ available）——*替代美股的「available × 5」（IB 购买力）；币安账户层无该概念，策略层杠杆由 martin 策略自身参数管理，组合层不叠加*；
3. 买入使用 ≤ 卖出释放 + 可用 USDT × invest_mult；
4. invest_mult = 1 时 剩余现金 ≥ B × 5%；
5. 每条 初始资金 ≥ 币目标资金 × 1.2；
6. 每策略目标资金 ≥ base_capital，N ≤ B ÷ base_capital（硬顶 50）。

## §7.3.1.6 买入端执行约束（释放资金分配规则）

- 只流入当天排名 Top 2-3 的强势板块；每个强势板块只加仓 1-2 只；新开仓 ≤ `max_new`；
  **（2026-09-15 验收复盘新增 · 名额排序陷阱）** `gap` 的「新仓名额」是按 **\|缺口\| 降序**占用（不是按板块优先级）：因此**快照里只放本轮真正拟开的新仓、数量 ≤ `max_new`、并按板块优先级排列**；若把「非优先候选」也写进快照，它可能因落地金额更大而**挤掉优先板块的名额**（本节实测：BNB 落地 93.29 < SOL 99.20，把两者都放进快照会让 SOL 先占名额）。**币版推荐改传 `--open-priority order`（v2.4.1 落地）**：名额改为**按快照顺序**占用（＝板块优先级），于是快照里可以同时放多个候选、并让工具自己输出 `截断名单`（如「MARTIN-SOLUSDT：新仓名额（超出 max_new=1）」），证据链更完整；缺省 `amount` 仍为 \|缺口\| 降序（美股默认，行为逐字不变）。若不带该参数，则按前述「快照只放 ≤ max_new 个」处理；
- 跟涨币等广度确认（板块内上涨币占比 > 60%）后再配；
- 板块平均资金费率 > 0.1%/8h → 该板块不新开（05 §7.3.3）；
- 超预算 → 按「新仓名额 → 单币目标 → 板块目标」顺序压缩并记录压缩过程；不得为过门槛反向抬高币数或改写目标资金。

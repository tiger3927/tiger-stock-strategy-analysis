# 加密货币板块轮动调仓 — 13 验收要点（外部智能体对照用）

> 用途：把「生成加密货币调仓报告」当作一个**可验收任务**。外部智能体独立跑一遍，按本文件 §2/§3 逐项判定、§4 一票否决、§6 对照基准 diff。
> 口径权威：00 §4（完成标准）＋ 06 §7.3.1（资金）＋ 07 §8（风控）＋ 10 §11（字段）＋ 11 §12（陷阱）＋ 12 §13.6（时点/单位）；本文件只做**验收编排**，不改任何口径。
> 铁律：本任务**只产出报告**——不下单、不设目标持仓、不改策略参数、不启停策略；取数一律经 vnpy_mcp **只读**实时查询（不得用缓存/记忆/历史报告推断持仓）。

## §2 硬门（可机验；任一不过 → 任务未完成）

### 2.1 `verify`（报告内部自洽 + 硬上限 + 闭环）

```bash
python <skill>/scripts/rebalance_tools.py verify --market 加密货币 \
  --report <报告.json> --balance <最新USDT权益> --available <最新可用USDT>
```

| 判定项 | 通过标准 |
|---|---|
| exit code / `校验` | `0` 且 `"校验":"通过"`；`不通过项数=0`、`无法校验项数=0` |
| `不适用项数` | `=0`，或逐条确认真属条件不满足（**「不适用」≠「通过」**） |
| 空洞通过 | 若 `调仓指令=[]` 且 `新增策略=[]`，必须已在 `执行建议` 写明「本轮无调仓」及依据（≥80 字），否则不合格 |
| 模板完整性 | 17 顶层字段齐全（缺字段 → 不合格） |
| 报告名 | `report_name` = 「加密货币板块轮动调仓」（逐字） |
| 数据溯源块 | `数据溯源` 存在且 `行情末根日期 / 账户快照时间 / 大盘报告时间` 三键非空（币版） |

### 2.2 `rebalance_audit`（报告 ↔ 上游来源 + 时效；第 5 道闸）

```bash
python <skill>/scripts/rebalance_audit.py --market 加密货币 --report <报告.json> \
  --prices <K线原始.json> --fund <fund.json> --gap <gap.json> --score <score.json> \
  --score2 <score2.json> --map <map.json> --cycle <cycle.json> \
  --live <实时价.json> --market-report <大盘报告.json> --units <volume_min_unit.json> \
  [--leaders <leaders.json>] --asof-date <YYYY-MM-DD>
```

| 判定项 | 通过标准 |
|---|---|
| exit code / `校验` | `0` 且 `"校验":"通过"`；`不通过项数=0`、`无法校验项数=0` |
| 结构化对账 | 板块评分引用 ↔ score、强弱清单 ↔ score/score2、S1–S5 ↔ map、资金汇总 ↔ fund/gap 全一致（差异须有「手工」留痕）；**传 `--leaders` 时**：报告 `分析摘要.强势板块` ↔ leaders「确认后强势板块」，**漏降档（T2 首位 20 日超额 <0 却仍列强势）→ 不通过** |
| 行情时效 | 末根滞后 ≤1 日；**≥2 日必须显式声明 as_of 并降级说明**（网关日 K 实测滞后 ~2 日，12 §13.6） |
| 目标持仓整数倍 | 每条指令/新增的 `目标持仓` 必须是 `volume_min_unit` 的整数倍 |
| **提示项** | 「提示项」不计入判定，但**必须逐条人工确认**：未溯源数字（凭记忆写入的高危信号）、末根收盘 vs 实时价偏差 >1.5% 的标的 |

### 2.3 结构门（可直接用 JSON 断言）

| 判定项 | 通过标准 |
|---|---|
| 字段名 | 逐字一致，含币版键：`权益_balance(USDT)` / `可用现金(USDT)` / `总预算_B(权益×invest_mult,USDT)` / `总预算(权益×invest_mult,USDT)` / `换算汇率`=`不适用（单币种）` / `强势子板块` / `弱势子板块` |
| 枚举纯净 | `操作模式` ∈ {积极, 正常, 防御}；`动作` ∈ {开仓, 加仓, 减仓, 清仓, 维持}；`层级` ∈ {S1 强烈加仓, S2 适度加仓, S3 维持, S4 观察减仓, S5 优先减仓} |
| 数值纯净 | 数值字段只含数值/布尔/枚举；说明文字一律进 `意图备注` / `调仓理由` / `依据` |
| 顶层 % 互验 | `调仓后总仓位_pct + 调仓后现金_pct = 100`；且 `资金汇总.调仓后总仓位_pct = 分析摘要.调仓后总仓位_pct` |
| 组合重建 | Σ指令目标% + Σ未涉及持仓% + Σ未映射持仓% = `调仓后总仓位_pct`（**未映射持仓也须给 `仓位占比_pct`**） |
| 目标分配一致性 | 有指令的板块，`目标分配.<板块>.目标_pct` = 该板块个股指令 % 之和 |
| 层级 ↔ 动作 | S1/S2 不得减仓清仓；S5 不得加仓开仓 |
| 资金闭环 1–6 | ①Σ初始 ≤ B ②**B ≤ available×2** ③买入 ≤ 卖出释放 + available×倍率 ④剩余现金 ≥ B×5%（倍率=1 时）⑤每策略初始 ≥ 目标×1.2 ⑥目标资金 ≥ base_capital 且 N ≤ B÷base_capital（硬顶 50） |
| 硬上限 | 单板块 ≤20%×B；高弹性(31-60+60+) 合计 ≤15%×B；60+ 单币 ≤2%；31-60 单币 ≤3%；单币 ≤`max_single_pct`%；前三大板块 ≤50%；目标持仓>0 的指令 + 新增 ≤ 50 |

### 2.4 一键验收（推荐：外部智能体直接跑这一条）

```bash
python <skill>/scripts/rebalance_acceptance.py --dir <报告与中间产物目录> \
  --balance <最新USDT权益> --available <最新可用USDT> [--asof-date YYYY-MM-DD]
```

- 目录约定文件名：`报告.json` / `fund.json` / `gap.json` / `score.json` / `score2.json` / `map.json` / `cycle.json` / `crypto_prices_raw.json` / `live_prices.json` / `market_report.json` / `volume_min_unit.json`（缺哪个，对应项即判「无法校验」）＋ **可选 `leaders.json`**（`leaders` 产物；存在 → 自动传给 audit 做「龙头确认 ↔ 报告强势板块」对账）；
- 输出：输入文件清单 → 门 1 `verify` → 门 2 `audit` → 汇总表 → **总判定**；
- 判定：`PASS`（两门均 0 不通过 且 0 无法校验，退出码 0）/ `FAIL`（任一有「不通过」，1）/ `UNKNOWN`（无「不通过」但有「无法校验」，2）；
- **提示项不阻断判定，但必须逐条人工确认**（未溯源数字、末根价 vs 实时价偏差）。

## §3 内容门（AI 判断；必须在报告内**留下证据**，不能只给结论）

| # | 判定项 | 通过标准（证据要求） |
|:-:|---|---|
| 3.1 | **大盘三档**（01 §3.1） | 列出三档各自「满足条数 + 逐条满足/不满足」；**两档并列时取更保守档**并写明另一档的参数差异；与大盘报告 `市场风格.风险偏好` 标签不一致时**必须留痕**；判定所用 BTC 价/MA/BTC.D/山寨超额各自标 as_of（禁止跨时点混算） |
| 3.2 | **操作模式** | 防御/正常/积极与 3.1 结论一致；理由写在 `风控校验.大盘状态确认` |
| 3.3 | **轮动阶段**（01 §3.3） | 早期/中期/晚期逐条列「满足/未满足」（满足 2 条即判定）并标 as_of；与大盘报告不一致时留痕 |
| 3.4 | **板块评分与分层** | score 输出为唯一排序依据；**引用值与工具输出一致**；强势=Top3-4、弱势=Bottom3 |
| 3.5 | **龙头确认**（02 §4.2.5） | 每个强势板块的首位 T2 币 20 日超额 ≥0；<0 → 强制降中性并**手工留痕**（原因+条款+原始清单差异） |
| 3.6 | **子维度/分桶** | score2 组合名 = 「板块-分桶」；**早期阶段只加 top10，不碰 11-30 以下**；60+ 全天候受 2% 单币上限 |
| 3.7 | **可下单性（一票否决）** | 每个候选币给出：`volume_min_unit`（策略参数，30/30 与 `get_contract.min_volume` 一致）+ 目标持仓 ÷ 单位 = **整数** + 名义额 ≥ 最小名义额；**禁止**「整数取整=0 → 不可开」；临界（距槽位/上限 <2%）须标「临界」并给临界价 |
| 3.8 | **币级三闸 + 可下单性**（04 §6.3） | 费率闸（>0.1%/8h 不加仓）、解锁闸（30 天 >1% 不加仓；`unlock_unknown` → 降一档 + 注记）、分桶闸（60+ 声明极端高弹性；31-60 单币 ≤3%）、可下单性 |
| 3.9 | **买入端约束**（05 §7.3 / 06 §7.3.1.6） | 只流入当日 Top 2-3 强势板块；每板块 1-2 只；新开 ≤ `max_new`；**不追高（当日 >5%）/不买暴涨（5 日 >30%，7 日 50% 是顶部信号）**；**跟涨币需板块内上涨币占比 >60% 才配**（龙头先行）；板块平均费率 >0.1%/8h 不新开 |
| 3.10 | **资金分配**（06 §7.3.1.2） | B = 权益 × invest_mult；目标仓位总和 = B ÷ 1.2（防御时 ≤50%×B）；板块目标带按「评分档 × 模式」且中性偏弱上限 −1/3；单币目标 ≥ base_capital；参数自检（`base_capital ≤ max_single%×B`）有调整时**必须留痕** |
| 3.11 | **分批计划**（08 §9.1 / 10 §11.2） | 最少 1 条；拆多条的触发条件（>24h 成交额 1% / 跨事件窗口 / 减仓清仓）；**各批为 `volume_min_unit` 整数倍、末批 = 指令目标持仓（补差）、禁空批**；`目标持仓(i)` 为**累计口径**且单调；避开 00/08/16 UTC 费率结算 ±30min，优先 04–08 / 11–14 UTC；FOMC 等事件 ±1h 避让并标时区 |
| 3.12 | **时效与溯源** | `数据溯源` 三键齐全；正文派生数字与 as_of 一致；日 K 滞后 ≥2 日一律写「截至 <末根日期>」并降级说明；末根价 vs 实时价偏差 >1.5% 的标的列 `数据缺失与冲突` |
| 3.13 | **数字可溯源** | 正文每个数字可指回「来源文件 + 字段 + as_of」；audit 未溯源清单为空或逐条确认（禁止凭记忆写入） |
| 3.14 | **状态与前置披露** | 策略运行状态（已停止/运行中）与可用资金须在报告留痕；若有指令，须写明执行前置（注资/启动策略） |
| 3.15 | **无调仓情形** | 0 指令时：`执行建议` 写明依据链；`目标分配` 覆盖 10 个板块并逐条说明「目标=当前」原因；写明下一轮重评触发条件 |
| 3.16 | **`待人工确认` 闭环** | 骨架原样清单不得当最终状态交付；已解决删除、未解决保留并注明原因 |
| 3.17 | **`失效代码`** | 工具报错/崩溃只记录（工具/子命令/错误摘要/影响环节/降级处理），**任务内不改码** |

## §4 反模式（出现任一项 → 一票否决，不论 §2 是否全绿）

1. 只跑通工具链（fund/gap/score/map/…）就收工，未产出报告（00 §4.3-1）；
2. 只交付骨架（`调仓指令=[]`、`风控校验={}`）（00 §4.3-2）；
3. 把 `verify`/`audit` 的「无法校验 / 不通过」表述为"通过"（00 §4.3-3）；
4. 明细全「通过」但 0 指令 / 0 映射，且未按 §2.1「无调仓」留痕（00 §4.3-4）；
5. `待人工确认` 原样交付（00 §4.3-5）；
6. **按「1 枚」或美股整股取整 → 误判「不可开」**（11 §12.11）；
7. **用滞后行情按"当期"口吻写结论**，且未声明 as_of（11 §12.8）；
8. **正文数字与工具输出不一致**或凭空出现（11 §12.9）；
9. **工具明确"无法判定"被写成肯定句**（如月度窗口；11 §12.10）；
10. **手工改写 score/score2/map 输出无「手工值+原因+依据」留痕**（00 §4.6-4）；
11. 为通过校验反向调整数值/口径倒推理由（对门拟合，00 §4.6-6）；
12. 任何下单 / 设目标持仓 / 改参数 / 启停策略的动作（任务越界）。

## §13.6 行情时点与「源对账」铁律（2026-09-15 复盘新增）

### 1) `get_history_bars` 日 K 实测滞后（必须声明）

**实测（2026-09-15 20:19 +08:00）**：请求 `interval="d"`，`start=2026-08-06`、`end=2026-09-15` → 实际返回 **39 根，末根 = 2026-09-13**（缺 9/14、9/15），**滞后 2 日**（与工程既有经验一致：网关历史 K 线有滞后，1m ~11h、1h ~20h）。故：

- 日 K 派生的 1d/5d/7d 数字**默认是「截至末根日期」口径**，不是当期口径；
- 报告必须据此填写 `数据溯源.行情末根日期`，正文写「截至 <末根日期>」（10 §11.2 时效纪律）；
- 若末根滞后 ≥ 2 日而该项又直接支撑交易决策（如"跟涨币占比 < 60%"），须用实时口径复核后再下结论。

### 2) 取数后强制交叉核对（SOP）

1. 打印/记录**末根日期**（不是"取数时间"）；
2. `get_market_data.py --market crypto --batch crypto-all` 或 `cta_strategies_get_all` 的现价，与末根收盘价对比：**偏差 > 1.5%** 的标的，逐条列入 数据缺失与冲突；
3. `get_all_contracts` 定位 vt_symbol 后，判断"不可开"必须再取 `get_contract` 的 `min_volume` / 最小名义额（06 §7.3.1.2），并记录实测值 + as_of；
   3b. **买入端否决（不追高 5% / 不买暴涨 30%）与「临界价」判定一律用实时口径**（`get_tick` / 1h K 线），日 K 派生值只作兜底并写「截至 <末根日期>」（05 §7.3.3 / 13 §3.9）；
4. 三份报告（大盘 + 做多 + 做空）取不到 → 按缺失记入「数据缺失与冲突」，同时记录大盘报告的 `analysis_time` 与时效（< 3 日，01 §3.1）。

### 3) `scripts/rebalance_audit.py`（第 5 道闸，2026-09-15 新增）

- **定位**：`verify` 只做报告**内部**数值自洽；本工具做**报告 ↔ 上游来源**对账 + 时效审计（纯标准库、只读、确定性）；
- **覆盖**：`数据溯源块` / `行情时效（K线末根 vs 取数日）` / `时效留痕` / `结构化引用对账（板块评分·强弱清单·S1–S5 映射·资金汇总 ↔ score/score2/map/fund/gap）` / `空报告（0 指令）依据`；
- **判定**：`校验` = 通过 / 不通过 / 无法校验（exit 0/1/2）；**「提示项」不计入判定但必须逐条人工确认**（未溯源数字 = 凭记忆写入的高危信号；末根 vs 实时价偏差清单）；
- **局限（须知情）**：数字扫描只能发现"完全找不到出处"的数字；若错误数字恰好与某工具输出同值（如把 L1 的 7D 因子当成 BTC 跌幅），扫描无法识别——**必须配合"来源 + 字段 + as_of"的书写纪律**（11 §12.9）；
- **调用**：见 10 §11.2「verify / assemble / audit 调用」；把它与 verify 同等对待（都通过才交付，00 §4.1-6）。

### 5) 最小交易单位 `volume_min_unit` 的读取口径（2026-09-15 新增）

- **权威来源 = 策略参数**：`volume_min_unit`（说明：最小交易单位，**程序运行时从交易所自动获取**，手工填写只用于回测）；
- **可取路径（实测 2026-09-15，30/30 可取）**：

  | 工具 | 能否取到 `volume_min_unit` | 路径 / 说明 |
  |---|---|---|
  | `cta_strategy_get_parameters_info(策略名)` | **能（首选）** | `parameters.volume_min_unit.value`（返回结构 `{strategy_name, parameters{...}}`）；同节点带 `type / description / name_cn=最小交易单位 / mcp_control=false` |
  | `cta_strategy_get_status(策略名)` | 能（备选） | `策略基础参数设置和当前变量.最小交易单位`（中文键，值=0.01） |
  | `cta_strategies_get_all` | 不能 | 只有展示字段（策略名/类名/持仓/资金/运行状态…），无参数明细 |
  | `cta_strategy_get_class_parameters` | 不能 | 按设计只返回「新建策略必填关键参数」，实测（3 个候选类名）均不含该键 |

- **只读属性**：`mcp_control = false` → `cta_strategy_set_parameters` 会**拒绝修改**（单位由交易所决定，禁止 AI 改写；正是所需）；
- **失败形态**：策略名不存在 → `{"error": "未找到策略: MARTIN-NOTEXIST"}`（须先确保策略已创建/已加载）；
- **交叉核对**：`get_contract(vt_symbol).min_volume`；实测 30 个 `MARTIN-*USDT` **30/30 一致**，不一致时以策略参数为准并留痕；
- **实测分档（30 币，20 个不是 1）**：0.001 → BTC/ETH/LTC/DASH；0.01 → BNB/SOL/LINK/ATOM/ETC/NEO；0.1 → XRP/DOT/SUI/APT/ARB/OP/INJ/FIL/QTUM/KAVA；1.0 → DOGE/ADA/AVAX/TRX/NEAR/UNI/VET/HBAR/IOTX/CKB（+CAKE）；明细见 06 §7.3.1.2 表；
- **用途**：目标持仓取整（06 §7.3.1.2）、最小名义额判定、「不可开」结论、`rebalance_audit --units` 整数倍校验；
  **禁止假设「1 枚」是通用最小单位**（事故见 11 §12.11）；
- **复核**：`rebalance_fetch.py volume-unit`（币安 exchangeInfo 权威 minQty/tickSize，落盘 `tests/volume_min_unit.json`，可直接喂 `rebalance_audit --units`；与策略运行时自动获取同源，不一致时以策略参数为准并留痕）。

### 1) 数据通道分工（脚本零 MCP 直连、零 token）

铁律：
- **MCP 只能是工具调用方式**（AI 侧 `mcp_call_tool`）；脚本不直连 MCP、不含 token；
- 脚本是技能独立运行代码，**不读取 `.vntrader` 等任何项目配置**；
- 网络（fapi）：按 `--proxy` > 环境变量 `FAPI_PROXY` > **本机 10808（存在则优先）** > 10809 > 直连 的顺序用 `/fapi/ping` 自动探测，全程失败时输出各通道实测结果表；
- **探测→增量**：klines 先取基准币（BTC）已收盘 bar 定末根日期，再逐币只补新段；缓存已对齐末根的币直接跳过；**禁止删缓存全量重拉**（`--full` 仅限数据损坏时）。

### 2) stdout 契约（成本红线）

- `rebalance_fetch.py` 每个子命令输出固定 **≤30 行摘要**；全量数据只落盘，AI 只读 stdout，**永不回读** K线/合约等全量文件；
- `rebalance_tools.py`（v2.5.0）非 assemble 子命令支持全局 `--out <file>`：全量结果写文件、stdout 只留摘要（fund 实测 5.7KB → 0.4KB）；`assemble --out` 时 stdout 不再含报告全文；
- 无 `--out` 时行为与 v2.4.1 逐项一致（`rebalance_acceptance.py` 解析 verify/audit stdout 的契约不受影响）。

### 3) 上下文压缩后的恢复

跑一次 `rebalance_fetch.py status`：一屏输出各产物文件的存在性 / mtime / 关键事实（B、强势板块、周期、末根日期、K线滞后天数）。**不重读文档与工具源码**。

### 4) 失效与降级

- fapi 不可达（地域屏蔽 / 代理出口被币安屏蔽 403）：脚本打印各通道实测表；降级 = AI 用 `mcp_call_tool get_history_bars` 工具调用取 K 线（§13.6-1 的滞后声明照旧适用）；
- 工具报错 / 崩溃：按「失效代码」铁律（10 §11）降级手工，任务内不改脚本；
- 单币拉取失败：进 `数据缺失与冲突`，不阻断其余币（klines 输出 FAIL 清单）。

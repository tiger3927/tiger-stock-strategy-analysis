# 加密货币板块轮动调仓 — 11 常见失败陷阱

> §12。十个市场特有陷阱 + 一个管道陷阱（继承美股组 §12.7，示例换币场景）。
> §12.8–§12.11 为 2026-09-15 复盘新增（时效漂移 / 数字凭记忆写入 / 口径未定义 / 美股整数股口径误用于加密永续）。

---

## §12.1 陷阱一：追涨杀跌（加密放大版）

- **7 日 50% 涨幅 = 晚期顶部信号**（Meme 普涨 / 高弹性币补涨），不是轮入信号——此时买入是接「见光死」；
- 阈值：不追高 5%（当日）、不买暴涨 30%（5 日）（05 §7.3.3）；BTC.D 快速上行 + 板块跑赢 = 系统性避险开始，山寨跌幅大于 BTC；
- 对策：轮动预测只出自 01 §3.5 矩阵 + 拐点信号；涨幅榜只作确认，不作依据。

## §12.2 陷阱二：过度交易

- 7×24 诱导冲动操作；资金费率让「持有」本身有成本（正费率多头 = 持续付费）；
- **2% 不动阈值**（06 §7.3.1.3）就是为此存在：缺口 < 2%×B 一律「维持」；
- 单轮幅度 ≤ 20%、周度 ≤ 5%；「条件触发」型指令不得按日反复执行。

## §12.3 陷阱三：高相关与伪分散

- 所有山寨币与 BTC 高相关：「5 个板块各 20%」≠ 5 个独立风险源；BTC 跌破 MA200 → 全板块同步下跌且山寨跌幅更大；
- 对策：01 §3.1 总开关（收缩 → 只卖不买）；07 §8.2 总仓位 < 50%；**不要把板块分散当风险分散**——仓位 % 上限才是真分散。

## §12.4 陷阱四：解锁 / 事件抛压

- 解锁是加密**最确定**的利空：30 天解锁 > 流通量 1% → 不加仓（04 §6.3-2）；板块 30 天解锁 > 5% → 全板块停止新开（07 §8.4 #8）；
- 下币公告 / 协议安全事故 / 团队抛售 = 事件加速清仓（05 §7.2.2），不拆单；
- `unlock_unknown` 不得编造 → 降一档 + 注记（选币 00_index §四）。

## §12.5 陷阱五：过度集中叙事

- 叙事板块天然吸金（全市场都在做 AI 币 / Meme 币）：单一叙事过热 → 单币/单板块上限被击穿；
- 20% 单板块 / 50% 前三大 / 15% 高弹性（07 §8.1）是硬红线；「强势板块」也**不得超 20%**（触顶截断、余额给未触顶板块，06 §7.3.1.2）。

## §12.6 陷阱六：流动性与符号变体

- 60+ 深度薄：单日操作 > 24h 成交额 0.5% → 滑点爆炸；大单必须拆单 + 限价（08 §9.1/§9.3）；
- 符号变体（1000PEPE / 1000BONK / 1000SHIB）：自行拼接 vt_symbol 或用池中缓存值 → 下错合约 / 下单失败；vt_symbol 一律以 `get_all_contracts` 返回为准（04 §6.1.2）；
- 最小下单量：目标持仓 × 现价 < **最小名义额（= 最小交易单位 `volume_min_unit` × 现价）** → 该币「不可开」，并入同板块其他币（06 §7.3.1.2）；**单位逐币不同**（30 币中 20 个不是 1），详见 §12.11。

## §12.7 陷阱七（管道类）：把「工具跑通」当成「报告正确」

继承美股组 §12.7 六子项，币场景示例：

| # | 管道陷阱 | 对策 |
|:-:|---------|------|
| 7.1 | 重复定义漂移（同一概念多处定义） | 单一事实源：板块 = crypto_pool categories + domain_dict；矩阵 = 04 §6.2；口径 = 06 §7.3.1.2（00 §4.6） |
| 7.2 | 校验盲区（空洞通过） | verify 通过前确认指令数 > 0 或显式「无调仓」；「不适用」≠「通过」（00 §4.1-4） |
| 7.3 | 口径未定义 | 每个派生指标写明分子/分母/来源（顶层 % = $ ÷ B；`调仓后现金_pct` ≠ 剩余现金 ÷ B） |
| 7.4 | 单向管道 + 手工覆盖无回灌 | 手工值注明「手工值 + 原因 + 依据公式」并回写上游（00 §4.6-4） |
| 7.5 | 对门拟合 | 不得为过门槛把目标资金改成「N 币 × 现价」；币版例：不得为过「资金费率成本提示」而修改费率档位 |
| 7.6 | 兜底容器（`待人工确认` 塞一切） | 12 条是过程态，交付前逐条闭环或注明挂起原因（00 §4.1-3） |

**币场景特例（工具预设漂移）**：用美股阈值直接跑币报告 → 1% 不动阈值把正常波动全判「维持」（噪声），或不追高 3%（美股阈值）把币的正常建仓全否决。**阈值必须走币版预设**（06 §7.3.1.5 现状注记 / 12 §13.5）。

## §12.8 陷阱八：时效漂移（同一个"现价"其实有三个时点）

**症状（2026-09-15 实战事故）**：报告同时出现三种 BTC 口径且都写成"现价"——yfinance 现货快照 76,890（12:33Z）、策略口径 76,867（20:19 +08:00）、大盘报告 77,359（前两日）；再把 9/12 的 MA20（78,592）与 9/15 的价格混算得出"破 20D −1.6%"。更隐蔽的是**网关日 K 实测滞后 2 日**（请求到 9/15，实际末根 9/13），导致 1d/5d/7d 派生数字全部是两天前的口径，却按当期口吻写进报告与决策依据。

**根因**：`get_history_bars` 日 K 走网关（Lag 取决于网关同步），而 `get_tick` / `cta_strategies_get_all` / `get_market_data` 是另一套时点；三者混用无声明。

**对策**：
1. 报告必须填 `数据溯源`（第 18 字段：行情末根日期 / 账户快照时间 / 大盘报告时间）；
2. 派生数字与声明 as_of 绑定；**日 K 滞后 ≥ 2 日**时一律改写为「截至 <末根日期>」并降级说明（12 §13.6）；
3. 关键结论（不可开/临界/广度）尽量用**实时口径**（`get_tick` / `cta_strategies_get_all`）复核，末根收盘与实时价偏差 > 1.5% 的标的列入 数据缺失与冲突；
4. 大盘报告时效 < 3 日（01 §3.1）也要留痕，逼近 3 日时须评估是否改走 `price_structure_fallback` 降级闸门。

**检测手段**：`rebalance_audit.py` 的「行情时效」「时效留痕」「末根 vs 实时价偏差」三项（不通过 / 提示）。

## §12.9 陷阱九：数字凭记忆写入（报告自己"编"出证据）

**症状（实战事故）**：报告正文出现 `BTC 7 日 −2.35%`（实为 score 工具 L1 公链 7D 因子）、`BNB −1.40%`（我方数据 −1.54%）、`BTC 76,890`（有源但未标来源）——`verify` 全绿，因为这些数字不参与任何数值自洽校验。

**根因**：填写骨架时"顺手回忆"工具输出，而不是从落盘 JSON 里复制；`verify` 只查报告内部一致性，不查数字出处。

**对策**：
1. 正文每个数字给「来源文件 + 字段 + as_of」，禁止凭记忆（00 §4.6-9）；
2. 交付前跑 `rebalance_audit.py`，把「未溯源数字」清单清空或逐条确认；
3. 引用了 score/score2/fund/gap/map 的数值，一律走 audit 的结构化对账项（评分/清单/映射/资金逐项比对）。

**注意工具边界**：数字扫描只能发现"完全找不到出处"的数字；若错误数字恰好与某个工具输出数值相同（如把 L1 的 7D 因子当成 BTC 跌幅），扫描无法识别——所以必须配合"来源+字段+as_of"的书写纪律，而不是只依赖工具。

## §12.10 陷阱十：口径未定义（判不了却写成判了 / 同一数据两种读法）

**症状（实战事故）**：① 01 §3.1 三档中「BTC.D 走平或下降」与「BTC.D 上行」互斥但未定义窗口 → 3 个月读法得"中性偏弱"、7 日读法得"正常"，模式（防御/正常）与参数（max_new、目标仓位总和、板块目标带）随之漂移，报告未披露；② `cycle` 工具明确"未提供 --last-rebalance→无法判定月度窗口到期"，报告却写成"月度窗口已过期"。

**对策**：
1. 口径未定义先定义再判定（01 §3.1 已补：BTC.D 以 3 个月口径为准，7 日仅作并列提示）；
2. 判定并列时**取更保守档**并把另一档的参数差异写进 数据缺失与冲突；
3. 工具的"无法判定 / 无法校验"**不得改写成肯定句**；报告只能复述工具结论（cycle 已增 `月度窗口判定` / `月度窗口已过期可声明` 字段）；
4. 大盘报告的参考标签（如 风险偏好"中性"）与本表客观判定不一致 → 留痕，不得只引用有利字段（direction / 风险等级）。

**检测手段**：`verify` 的「大盘状态确认」自报项 + 人工复核 数据缺失与冲突 是否含"并列/分歧/无法判定"条目。

## §12.11 陷阱十一：把美股「整数股」口径套到加密永续（误判「不可开」）

**症状（2026-09-15 实战事故）**：按美股「目标持仓 = 目标资金 ÷ 现价 → 向下取整（整数）」算出某币 = 0.139 → 0 → 判「不可开」，据此写下「强势板块无可执行币 → 本轮不调仓」。实测该币最小交易单位 = **0.01**：0.13 枚 = 13 个单位 = 93.5 USDT **完全可开**——整份报告的结论因此错误。

**根因**：美股是整数股（1 股为最小单位）；加密永续**逐币有各自的最小交易单位**（策略参数 `volume_min_unit`，运行时自动从交易所获取；与 `get_contract.min_volume` 一致），30 个主流币实测分四档、**20 个不是 1**：

| 最小交易单位 | 币 |
|---|---|
| 0.001 | BTC、ETH、LTC、DASH |
| 0.01 | BNB、SOL、LINK、ATOM、ETC、NEO |
| 0.1 | XRP、DOT、SUI、APT、ARB、OP、INJ、FIL、QTUM、KAVA |
| 1.0 | DOGE、ADA、AVAX、TRX、NEAR、UNI、VET、HBAR、IOTX、CKB（+CAKE） |

币版的「取整损失条款」必须按该单位落地，不能照抄美股整数取整，也不能假设「1 枚」是通用单位。

**对策**：
1. 任何「不可开 / 装不下槽位 / 无法建仓」的结论，必须先 `get_contract` 取 `min_volume` 与 `pricetick`，并在 目标分配.依据 写出「目标持仓 × 现价 vs 最小名义额」的算式（06 §7.3.1.2）；
2. **禁止**「floor = 0 → 不可开」这类一句话结论；
3. 注意 `rebalance_audit.py` **不覆盖此类领域逻辑错误**（它只查一致性/时效）——该类判定只能靠"算式 + 实测值"的证据链供人工复核（本条即为此设）。

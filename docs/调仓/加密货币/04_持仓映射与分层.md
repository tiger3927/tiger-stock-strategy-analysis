# 加密货币板块轮动调仓 — 04 持仓映射与分层

> 第四层文档。加密的特殊性：**策略的 `品种信息` 通常为 `{}`**（BINANCE_LINEAR 策略不挂 ticker/行业），映射链 = 策略名 → 币 → 池 → 板块/分桶，`vt_symbol` 必须与 `get_all_contracts` 求交集。

---

## §6.1 策略 → 币 映射

### §6.1.1 持仓数据获取（vnpy_mcp 直读，不使用 Redis）

| 用途 | vnpy_mcp 工具 | 取什么 |
|------|--------------|--------|
| 策略主数据 | `cta_strategies_get_all` | 策略名称、实际持仓、持仓目标、操作方向、运行状态、品种信息（通常空 `{}`）、已使用资金占比 |
| 策略详情 | `cta_strategy_get_status` / `cta_strategy_get_all_reason` | 运行状态 / 异常原因 |
| 账户级持仓交叉 | `get_positions` | 按 vt_symbol 的持仓（与策略级交叉核对，不一致进「数据缺失与冲突」） |
| 账户 | `get_accounts` | balance（USDT 权益）/ available（可用 USDT）——总预算 B = balance × invest_mult（06 §7.3.1.2） |
| 可交易清单 | `get_all_contracts` | 全部 U 本位永续合约（700+），vt_symbol 唯一来源 |

**铁律**：

1. 一律走 vnpy_mcp，只以本次实时返回为准，不得用记忆 / 历史报告 / 推断值；
2. 不使用任何 Redis 方面的工具；
3. 映射依据 = 策略名解析 + `crypto_pool.json`；两者都定位不到 → 列入「未映射持仓」，**不得丢弃、不得凭印象归类**；
4. 取不到数据 → 停止调仓流程并如实上报，不得降级为估算值。

### §6.1.2 映射流程

```
策略名 "MARTIN-SOLUSDT" → 币 SOL
  → crypto_pool.json: SOL → {板块: "L1 公链", mcap_bucket: "top10", tier: "T2", chain: "Solana"}
  → get_all_contracts 交集: SOL → vt_symbol = "SOLUSDT_SWAP_BINANCE.GLOBAL"（以本次返回为准）
  → 命中 → 板块 + 分桶 双层映射；未命中 → 未映射持仓 [{策略名称, 原因}]
```

- **符号变体**：币安存在 `1000PEPE` / `1000BONK` / `1000SHIB` 类变体——策略名写 `MARTIN-PEPEUSDT`，但合约可能是 `1000PEPEUSDT_SWAP_BINANCE.GLOBAL`。交集时先精确匹配、再试 `1000` 前缀变体，**一律以 `get_all_contracts` 返回为准**；命中变体时在报告注明；
- 池中未收录的币（池外币）→ 记入「未映射持仓」并注明「池外币，按 选币操作手册 §3.4 补池」，不得凭印象归板块。

## §6.2 双层持仓分层（S1–S5，权威定义）

> 本矩阵是**唯一权威定义**（03 §5.3.2 / 05 §7 / 10 §11.2 均引用本篇，不得重述）。

| 层级 | 板块 | 子维度（分桶） | 操作策略 |
|:---:|:---:|:---:|---------|
| **S1 强烈加仓** | 强（Top 3-4） | 强（Top 6-8） | 加仓优先，释放资金首先使用 |
| **S2 适度加仓** | 强 | 中 / 强 | 可加仓，金额 ≤ S1 |
| **S3 维持** | 强 | 弱 / 中 | 持有观察，不加仓 |
| **S4 观察减仓** | 中 | 弱 / 弱 | 默认维持；触发 07 §8.2 条件才减 |
| **S5 优先减仓** | 弱（Bottom 3） | 中 / 弱 | 按 05 §7.2 节奏减仓；连弱 3 周清仓 |

**层级 ↔ 动作一致性**（verify 强制拦截）：S1/S2 不得出现减仓/清仓指令；S5 不得出现加仓指令。确需背离时，先改本层归属并在 `层级依据` 写明依据（如「板块弱但币级催化强，S5→S4」），再下指令。

## §6.3 币级二次筛选（确认 S1/S2 加仓前必过三道闸）

1. **资金费率闸**：该币费率 > 0.1%/8h → 加仓降级为「维持」（成本侵蚀，07 §8.2）；> 0.2%/8h → 转「减仓优先」（极端拥挤）；
2. **解锁闸**：未来 30 天解锁 > 流通量 1%（tokenomist）→ 不加仓；`unlock_unknown` → 加仓降一档并注记；
3. **分桶闸**：60+ 开新仓/加仓必须在 `意图备注` 显式声明「极端高弹性」，且受 07 §8.1 高弹性合计上限约束；31-60 单币目标 ≤ 3% × B。

> **可下单性校验（2026-09-15 新增；不属上述三闸，但一票否决）**：目标持仓必须是该币**最小交易单位 `volume_min_unit` 的整数倍**，且 目标持仓 × 现价 ≥ 最小名义额；不满足 → 「不可开」，并入同板块其他币（06 §7.3.1.2 / 08 §9.1）。**禁止**用「整数取整 = 0」当不可开依据（11 §12.11）。

## §6.4 选币池与分层

- 池：`scripts/crypto_pool.json`（55 币 / 10 板块 / T1–T3 + 市值分桶；**唯一数据源**，AI 直接修改该 JSON 更新池，改后跑 `scripts/sync_crypto_pool.py` 校验）；
- **T1（BTC/ETH）**：方向基准与流动性锚——不直接参与「买强」评分，只作总开关输入与超额基准；
- **T2（各板块龙头 1-3 只）**：超额收益主力，加仓/开仓首选；
- **T3（高弹性小市值 / 新叙事）**：高赔率高风险，受高弹性上限约束（07 §8.1）；
- **池是种子兜底，不是视野边界**：池外币（CoinGecko 前 300 中叙事在上升者）按 [../加密货币选择/选币操作手册.md](../加密货币选择/选币操作手册.md) §3.4 池外探测补池，**先补池再持仓**；
- 做多/做空选币报告的「下一轮动预测」只作**交叉印证**：方向一致 → 置信度上调；分歧 → 列入 `核心冲突` 并下调置信度，不直接作为调仓依据。

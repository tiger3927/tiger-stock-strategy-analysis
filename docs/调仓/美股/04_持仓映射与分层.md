### 6.1 个股 → 子板块映射

#### 6.1.1 持仓数据获取（vnpy_mcp 直读，不使用 Redis）

本层分析的对象是**量化系统中实际运行的策略持仓**，必须通过 **vnpy_mcp** 工具实时读取（前提：量化系统正在运行）：

| 用途 | vnpy_mcp 工具 | 取什么 |
|------|--------------|--------|
| 策略级持仓（主数据源） | `cta_strategies_get_all` | 每个策略的 `策略名称`、`vt_symbol`、`实际持仓`、`持仓目标`、`持仓均价`、`当前行情价格`、`当前持仓盈亏比`、`已使用资金占比`、`操作方向`、`运行状态`，以及 `品种信息`（含 ticker / 分类 / 行业） |
| 单策略细节核对 | `cta_strategy_get_status`（`strategy_name`） | 指定策略的完整状态字典（参数 + 运行变量） |
| 持仓决策上下文 | `cta_strategy_get_all_reason`（`strategy_name`） | 开仓 AI 理由、最近一次 AI 理由、本次持仓交易历史、各参数最近一次修改与 reason —— 写「意图备注」「调仓理由」的依据 |
| 账户级持仓核对 | `get_positions` | 账户维度的品种、数量、成本价、盈亏 |
| 仓位分母 | `get_accounts` | 总预算 B = `balance`（权益）× `invest_mult`，`available`（可用资金）——板块/个股权重百分比以 B 为准（见 [06_策略资金分配.md](06_策略资金分配.md) §7.3.1.2 统一口径）；**须美元口径**（多币种账户取 USD 条目，无则按汇率换算，见 06_策略资金分配.md §7.3.1.1 币种规则） |
| 策略级资金 | `cta_strategies_get_all` | 每策略 `可用资金总量`、`已使用资金占比` —— 报告「资金现状」块的数据源（见 06_策略资金分配.md §7.3.1.1），**必须写入报告** |

> **完整取数清单**（分析报告 / 账户 / 持仓 / 策略 / 成交委托 / 行情合约 / 系统状态）见 **12_数据源与工具.md §13.4**。

**铁律**：

1. **一律走 vnpy_mcp**：持仓、成本、盈亏、可用资金只以上述工具**本次实时返回**为准，不得用记忆、历史报告或推断值。
2. **不使用 Redis 方面的工具**：不得通过 Redis 状态板（`enable_publish_status_redis` 发布的状态）、Redis HTTP 代理（`http_redis_proxy_url`）、Redis 缓存或任何 Redis 相关通道读取持仓/账户数据。
3. **映射依据**：以 `cta_strategies_get_all` 返回的 `品种信息`（ticker / 分类 / 行业）+ `scripts/stock_pool.json` 的 ticker→子板块反向索引做映射；两者都定位不到的持仓 → 列入「未映射持仓」，**不得丢弃、不得凭印象归类**。
4. **取不到数据**：量化系统未运行或工具报错 → 停止调仓流程并如实上报，不得降级为估算值。

#### 6.1.2 映射流程

将每个持仓个股映射到 GICS Level 2 子板块：

```
输入：cta_strategies_get_all 返回的策略持仓（get_positions 核对）
输出：双层映射表
  Sector 层：
    - 科技: [AAPL, MSFT, NVDA, ...]
    - 金融: [JPM, GS, BAC, ...]
    - ...
  Industry Group 层：
    - 半导体与设备: [NVDA, AMD, INTC, ...]
    - 软件与服务: [MSFT, ORCL, CRM, ...]
    - 银行: [JPM, BAC, WFC, ...]
    - 制药与生物科技: [JNJ, PFE, MRK, ...]
    - ...
  未映射持仓：
    - {ticker}: {原因：品种信息无行业 / 不在 stock_pool.json}
```

### 6.2 双层持仓分层

根据 Sector 评分 + 子板块评分，将所有持仓分为五层：

> **本表是 S1–S5 分层的唯一权威矩阵**，覆盖 板块 × 子板块 的**全部 9 种组合**（工具 `s_layer` 逐条实现）。
> 03 §5.3.2「双层评分决策矩阵」是本表的等价复述，**以本表为准**，不得另立第二套（2026-09-15 事故：两张矩阵不等价，同一持仓在两个模块得到不同结论）。
> **层级与动作必须一致**：若判断确需减仓/清仓，正确做法是**先把本表层级下调**并写明依据，而不是保留 S1/S2 层级却下达清仓指令——verify 有「层级 ↔ 动作 一致性」项强制拦截。

| 层级 | Sector | 子板块 | 操作策略 |
|------|--------|--------|---------|
| **S1 强烈加仓** | 强势 | 强势 | 优先加仓，最高权重 |
| **S2 适度加仓** | 强势 | 中性 | 小幅加仓优质标的 |
| **S3 维持** | 强势 | 弱势 | 仅保留，不加仓（板块强但细分弱） |
| **S3 维持** | 中性 | 任意 | 维持权重，不做调整 |
| **S4 观察减仓** | 弱势 | 强势 | 保留底仓，不加仓（子板块可能逆势） |
| **S4 观察减仓** | 弱势 | 中性 | 保留底仓，按弱势板块减仓节奏（07 §8.2）；**不得据此加仓** |
| **S5 优先减仓** | 弱势 | 弱势 | 阶梯减仓/清仓（双重弱势） |

### 6.3 个股层面的二次筛选

在子板块内部，对个股进行二次评分：

```
个股评分 = 0.30 × Sector 得分 + 0.30 × 子板块得分
         + 0.20 × 个股动量 + 0.15 × 个股质量 + 0.05 × 个股流动性

S1 层级内：
  - 个股评分 Top 60% → 可加仓
  - 个股评分 Bottom 40% → 仅保留，不加仓

S5 层级内：
  - 个股评分 Top 20% → 保留底仓观察
  - 个股评分 Bottom 80% → 优先减仓/清仓
```

### 6.4 个股选股池与分层

#### 6.4.1 个股 → 子板块映射

个股归属 GICS 子板块的确定方式（按优先级）：

```
方式一：GICS 官方分类（最准确）
  - 数据源：Bloomberg、FactSet、MSCI 的 GICS 分类接口
  - 每个股票有唯一的 GICS 代码（8 位数字，如 45301020 = 半导体）
  - 每季度更新一次（GICS 年度调整在 3 月/9 月）

方式二：ETF 成分股反推（次优）
  - 子板块 ETF（如 SMH）的成分股 = 该子板块的核心股票
  - 适用于有独立 ETF 的子板块

方式三：行业关键词匹配（兜底）
  - 通过公司财报中的 SIC/NAICS 代码或业务描述匹配
  - 精度较低，仅作为补充
```

#### 6.4.2 三层选股池

对每个 GICS 子板块，维护一个 **分层选股池**：

| 层级 | 定位 | 数量 | 操作策略 |
|------|------|------|---------|
| **Tier 1 龙头股** | 板块风向标，流动性最好 | 3-5 只 | 板块配置的主要工具，加仓/减仓首选 |
| **Tier 2 中盘成长** | 超额收益来源，弹性好 | 5-10 只 | 板块强势时优先加仓 |
| **Tier 3 潜力小盘** | 高赔率品种，高风险 | 5-15 只 | 总仓位 ≤ 5%，单只 ≤ 1% |

#### 6.4.3 选股评分公式

```
个股综合评分 = 0.25 × 子板块得分 + 0.20 × 个股动量
             + 0.15 × 个股质量 + 0.15 × 个股估值
             + 0.10 × 个股流动性 + 0.10 × 催化剂信号
             + 0.05 × 小盘溢价（仅 Tier 3 适用）
```

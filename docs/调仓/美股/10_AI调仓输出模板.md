> **字段完整性**：模板字段全部保留；取不到值填 `null` 或 `"missing"`，不得删除字段。
> **报告名**：固定为 `美股板块轮动调仓`，须与定时任务名、落盘文件夹名逐字一致（命名铁律见 README §6）。
> **意图备注必写**：每个策略（含新增策略）都要写「意图备注」——开仓目的 / 预期 / 退出条件；持仓期每轮更新，作为后续复盘的依据。
> **调仓相关参数**：只写与本次调仓有关的项（止盈止损、网格、首仓占比、价格保护等），键名用 `Tiger-Grid-Template/02_parameters.md` 的标准中文名；与本次无关的项可以不写。
> **新增策略**：`class_name` 取自 `cta_strategy_get_classes`、`vt_symbol` 取自 `search_vt_symbol`（**严禁自行拼接**）、`setting` 必填项用 `cta_strategy_get_class_parameters` 查得。
> **失效代码（工具出错只记录、不改码）**：调仓任务中 `rebalance_tools.py`（或 scripts 下其他工具）任一子命令报错 / 崩溃 / 输出不可用（含"无法校验"）→ 在「失效代码」逐项如实记录（工具、子命令、命令行、错误摘要、影响环节、降级处理），受影响环节改由 AI 手工计算 / 判断并交叉复核，必要时同时列入「待人工确认」；**任务内不修改工具代码**，修复一律在任务外经用户批准后进行。无失效填 `[]`。
> **校验门（verify）**：报告输出 / 落盘前必须执行 `python scripts/rebalance_tools.py verify --report <本报告 JSON 文件> --balance <最新 get_accounts.balance> --available <最新 available>`；判定 = 工具输出 JSON 的「校验」字段（通过/不通过/无法校验，退出码 0/1/2 仅辅助，**无输出 ≠ 通过**）。工具独立复算是唯一准，不信任报告自带「风控校验」结论；「不通过」→ 按明细修正后重跑；「无法校验」→ 补齐数据后重跑或列「待人工确认」。**只有「通过」报告才算完成**——这是整个任务「生成调仓报告」的唯一完成判据，任务必须一次执行完（取数 → fund → gap → 评分/映射 → assemble → AI 填指令/映射/文本 → verify 通过 → 交付最终报告），assemble 骨架与中间子命令 JSON 均非任务完成（00_index §4 任务执行与完成标准：完成判据 5 条 / 标准执行顺序 / 反模式清单）。

> **骨架装配（assemble，可选）**：`python scripts/rebalance_tools.py assemble --fund <fund输出.json> --gap <gap输出.json> [--score <score输出.json>] [--score2 <score2输出.json>] [--map <map输出.json>] [--analysis-time "YYYY-MM-DD HH:MM:SS +08:00"] [--mode 积极|正常|防御] [--cycle-stage 周期阶段] [--out 报告.json]` 生成 17 顶层字段齐全的骨架：任务参数（fund 自动调参后值，中键→英键）、资金现状/资金汇总数值（取自 fund/gap，**顶层 调仓后总仓位/现金_pct = $ ÷ B，构造上满足规则 4 互验**）、目标分配（按 gap 明细板块聚合 当前/目标 %）、持仓映射（map 输出归层）、强/弱板块与子板块（score/score2 输出）；调仓指令/新增策略/风控校验/各文本字段留 AI 填，未填项逐条进「待人工确认」。assemble 只装配数值与结构，**不产生任何判定**；AI 填完仍必须 verify 复算（verify 独立复算不信任骨架自带结论，避免自我闭环）。

#### 分批计划规则（按单条指令定，不强行拆 2-3 天）

- **最少 1 条**（单日 / 单笔即可）；**满足以下任一条件才必须拆多条**：
  1. 单笔金额 > 该股日均成交额的 1%（流动性约束，见 08_拆单与执行优化.md §9.1）
  2. 执行期跨越事件窗口（FOMC / 财报等）——事件前只锁定高置信部分，其余留给事件后情景
  3. 动作为减仓 / 清仓——第二批保留条件分支（按第一批后的市场反馈决定是否继续，见 05_调仓执行流程.md §7.2.1）
- **维持 / 条件触发型**：只写 1 条 + 触发条件，**禁止凑批**
- **自洽规则**：`目标持仓(i) = 目标持仓(i-1) − 本批数量`，且各批数量之和 ≤ 当前持仓；出现"扩大某批"情形时，目标持仓必须同步修正

#### 调仓相关参数（按需选填，参考清单）

只写与本次调仓有关的项——例如"本次要减仓"，就写动作涉及的止盈止损/网格开关与数值，不涉及的不必写。键名统一用标准中文名（下为常用清单）：

| 组 | 字段（标准名） |
|----|--------------|
| 方向 | `操作方向` |
| 资金 | `初始资金`、`建议首仓占比` |
| 止盈止损 | `是否允许止盈`、`止盈幅度`、`是否允许止损`、`止损幅度`、`是否允许移动止盈`、`移动止盈启动幅度`、`移动止盈回撤幅度`、`是否允许ATR动态止损`、`是否允许ATR动态止盈`、`止盈止损用ATR周期`、`止盈止损用ATR倍数` |
| 网格 | `是否允许网格主动开仓`、`是否允许盈利时网格加仓`、`是否允许亏损时网格加仓`、`网格间距`、`网格数量`、`是否允许卖出基础底仓`、`是否允许网格减仓`、`网格止盈`、`基础底仓分批出货比例` |
| 价格保护 | `是否限制首仓价格区间`、`首仓最低价`、`首仓最高价`、`是否禁止追高`、`禁止追高价格红线` |

> 本报告是说明性的：参数写清"本次调仓后该策略应处于什么状态"即可，不必铺满全部参数；与当前实盘一致时也可只写变化项。

#### 数值字段纯净规则（输出前自检）

1. **`调仓相关参数` 的值只留数值 / 布尔 / 枚举**（如 `false`、`0.056`）；说明性注解（当前状态、钳制逻辑、维持原因）一律进「意图备注」或「调仓理由」，不得混进参数值
2. **`操作模式` 为纯枚举**：只允许 `积极` / `正常` / `防御`（依据 01_宏观环境定基调.md §3.4）；判定理由全部写「风控校验.大盘状态确认」，不得在枚举值后附加句子
3. **`风控校验` 百分比必须自洽**：板块% = 该板块下所有个股% 之和（同一价格时点计算）；"前三大板块"必须**按调仓后板块%降序取最大的三个**（不得用其他板块顶替），列出三分项明细（板块名 + %），合计 = 分项之和，不得只给模糊区间
4. **顶层 % 与 $ 互验（含分子定义）**：`调仓后总仓位_pct` 的**分子 = 调仓后持仓市值**（= Σ 各持仓 目标仓位占比_pct × B），`调仓后现金_pct = 100 − 调仓后总仓位_pct`；`资金汇总.调仓后总仓位_pct` 必须与 `分析摘要.调仓后总仓位_pct` 相等；
   **必做交叉核对（组合重建）**：`调仓后总仓位_pct` 必须 ≈ `Σ调仓指令.目标仓位占比_pct` + `Σ未涉及持仓.仓位占比_pct` + `Σ未映射持仓.仓位占比_pct`；
   - **未映射持仓必须计入**（其 `仓位占比_pct` 不得留空），否则总仓位口径不完整、该核对无法执行；
   - **禁止**把 `调仓后现金_pct` 定义成"剩余现金 ÷ B"——剩余现金是资金记账量，与"仓位占比"不是同一维度的互补量（2026-09-15 事故：报告显示总仓位 49.16%，实际持仓仅 3.86%）。现金类指标请看 `资金现状.现金占比_pct`（= 可用现金 ÷ 权益）。
5. **资金闭环（六条，见 06_策略资金分配.md §7.3.1.5）**：Σ `初始资金` ≤ 总预算 B = 权益 `balance` × `invest_mult`（任务参数，默认 2 倍）且 ≤ 购买力 `available` × 5（IB 保证金物理上限，非百分比分母）；本轮 `买入使用` ≤ `卖出释放` + 可用现金 `available` × `invest_mult`；`invest_mult = 1` 时剩余现金 ≥ B × 5%（>1 时现金可为负）；每条 `初始资金` ≥ 个股目标资金 × 1.2；每策略目标资金 ≥ `base_capital`（最小开仓门槛），策略总数 ≤ 总预算 B ÷ `base_capital`（硬顶 50）。任一不成立 → 按「新仓名额 → 单票目标 → 板块目标」顺序压缩至成立，并在「执行建议」中记录压缩过程

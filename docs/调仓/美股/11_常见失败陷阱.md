# 美股板块轮动调仓 — 常见失败陷阱

> 美股板块轮动调仓文档组 · [索引](00_index.md)
> 纪律与复盘：六大失败陷阱与对策

---

### 12.1 陷阱一：追涨杀跌

**表现**：看到板块大涨就追入，大跌就割肉。

**对策**：
- 只用相对强弱（RS）而非绝对涨幅做决策
- 设置确认条件：RS 曲线必须处于上行趋势
- 买入不追高（当日涨幅 > 3% 不买）

### 12.2 陷阱二：过度交易

**表现**：每天大规模调仓，换手率过高。

**对策**：
- 固定月度大再平衡 + 周度微调的双周期机制（见 [09_双周期再平衡机制.md](09_双周期再平衡机制.md)）
- 单次调仓幅度限制（月度 ±10%，周度 ±3%）
- 计算交易成本，纳入决策

### 12.3 陷阱三：滞后指标陷阱

**表现**：等经济数据确认后才调仓，已经晚了。

**对策**：
- 使用领先指标（收益率曲线、信用利差）而非滞后指标（GDP）
- 关注价格信号（价格是最快的领先指标）
- 分批调仓，边确认边调整

### 12.4 陷阱四：过度集中

**表现**：重仓押注一两个板块。

**对策**：
- 硬性单板块上限 20%
- 前 3 大板块合计不超过 50%
- 定期检查集中度

### 12.5 陷阱五：忽视交易成本

**表现**：频繁换手导致交易成本侵蚀收益。

**对策**：
- 月度再平衡为主，减少非必要交易
- 大单拆分为小单执行
- 计算预期滑点，超过阈值则调整

### 12.6 陷阱六：对抗长期趋势

**表现**：在长期下行趋势的板块中反复抄底。

**对策**：
- 尊重长期趋势（200 日均线方向）
- 弱势板块连续 3 周 Bottom 3 必须清仓
- 不逆势加仓

### 12.7 陷阱七（管道类）：把「工具跑通」当成「报告正确」

> 12.1–12.6 是**交易行为**层面的陷阱。本节补的是**流水线**层面的陷阱——2026-09-15 实盘事故的根因全部落在这一节，而 12.1–12.6 一条都覆盖不到。
> 本方法论已从「一套交易策略」变成「一条数据流水线」，失败模式目录必须同步升级。

| # | 管道陷阱 | 表现 | 对策 |
|:-:|---------|------|------|
| 7.1 | **重复定义漂移** | 同一概念在文档/代码里被定义多次且互相不一致（板块命名 3 套、决策矩阵 2 张、目标资金 2 口径、目标仓位总和 3 个含义） | 每个概念只保留**一处权威定义**（单一事实源，如 `scripts/domain_dict.json`），其余位置只引用、不重述 |
| 7.2 | **校验盲区** | 交叉核对项在特定输入下被静默跳过（如存在"未映射持仓"时组合重建判"不适用"），而汇总只报"0 不通过" | verify 汇总必须给出「不适用项数 / 未执行检查项」；**"不适用"不得视为"通过"**，须逐条核对确属条件不满足 |
| 7.3 | **口径未定义** | 规范只写"总仓位 %（分母 = B）"却没说分子，工具自造恒等式，指标与实际持仓脱钩（报告 49.16% vs 实际 3.86%） | 每个派生指标必须写明**分子、分母、数据来源**；口径变更走单一事实源，不做全文人工同步 |
| 7.4 | **单向管道 + 手工覆盖无回灌** | AI 手工改了中间结论（榜单 / 分类），未回改上游产物，报告内部自相矛盾（同一子板块既"弱势"又"中性"） | 手工覆盖必须留 provenance 并回写上游；把**一致性**升为第一类校验（层级↔动作、摘要↔映射、总仓位↔持仓） |
| 7.5 | **对门拟合** | 为了让 verify 变绿而调整数值/口径，再倒推理由（为使门槛通过而把目标资金改成"9 股×现价"） | 先按文档决策 → 再让校验门验证；verify 与文档冲突时记入「数据缺失与冲突」并暴露，**不得静默迁就工具** |
| 7.6 | **兜底容器** | 「待人工确认 / 数据缺失与冲突」被当成免责容器，把矛盾写进去就当作闭环 | 闭环 = 形成**内部一致的决定**；矛盾项要么修正，要么作为**单一提案**上交，不得带着互斥结论交付 |

### 13.4 vnpy_mcp 取数清单（只读，不使用 Redis）

> 本模块所需的量化系统数据**全部经 vnpy_mcp 实时查询**（前提：量化系统正在运行）；查询类工具无需用户名参数。
> **不使用任何 Redis 方面的工具**（Redis 状态板 / Redis HTTP 代理 / Redis 缓存）。
> 完整工具定义、参数与返回格式以 `get_guide` 及工具实际返回为准；本节只列本模块用得到的只读部分。

#### A. 分析报告

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `cta_report_list` | 列出全部分析报告目次（分析报告 + 策略分析记录） | 无 |
| `cta_report_get` | 取指定报告内容 | `report_kind`（分析任务名，如 `美股大盘与板块和资金流向分析`、`美股做多选股结果`、`美股做空选股结果`）、`strategy_name`（查策略分析记录）、`report_index`（默认 -1 取最新） |

> 调仓前先取三份报告：大盘报告作宏观输入（见 01_宏观环境定基调.md §3），`美股做多选股结果` / `美股做空选股结果` 用于轮动预测交叉印证（见 01_宏观环境定基调.md §3.5 / 04_持仓映射与分层.md §6）；任何一份取不到则按缺失处理并记入「数据缺失与冲突」。

#### B. 账户与持仓

| 工具 | 用途 |
|------|------|
| `get_accounts` | 账户余额：`accountid`（可能带币种标识）、`gateway_name`、`balance`（**权益**，含持仓占用与可用现金，**不能加持仓市值**）、`frozen`、`available`（购买力）—— 板块/个股仓位百分比的分母 = 总预算 B = balance × invest_mult（06_策略资金分配.md §7.3.1.2 统一口径）；**IB 多币种账户须取 USD 币种条目或换算为美元**（见 06_策略资金分配.md §7.3.1.1 币种规则） |
| `get_positions` | 账户级持仓：品种、数量、成本价、盈亏 |

#### C. 策略

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `cta_strategies_get_all` | 全部策略概况（中文键名）：策略名称、策略类型、vt_symbol、实际持仓、持仓目标、持仓均价、当前行情价格、当前持仓盈亏比、可用资金总量、已使用资金占比、网格已用/最大、操作方向、自动开仓、止盈、止损、移动止盈、网格间距、亏损加仓、运行状态、品种信息（ticker / conid / 分类 / 行业） | 无 |
| `cta_strategy_get_status` | 单策略完整状态：vt_symbol、策略类型、实际持仓、持仓目标、持仓均价、历史累计盈亏、当前持仓盈亏比、当前行情价格、已使用资金占比、已有网格仓数量、持仓交易历史、上次平仓价/平仓冷静期截止/上次平仓方向（条件：全平/转向后才有）、策略基础参数设置和当前变量、`is_trading`、品种信息 | `strategy_name` |
| `cta_strategy_get_all_reason` | 持仓决策上下文：开仓 AI 理由、最近一次 AI 理由、本次持仓交易历史、各参数最近一次修改与 reason | `strategy_name` |
| `cta_strategy_get_trade_history` | 策略完整交易历史（读本地 `.trades_txt`，含全部轮次与已平仓） | `strategy_name`、`limit`（不传=全部） |
| `cta_strategy_get_parameters_info` | 关键参数说明（名称 / 类型 / 当前值 / 描述） | `strategy_name` |
| `cta_strategy_get_classes` | 可用 CTA 策略类列表（「新增策略」时选 class_name） | 无 |
| `cta_strategy_get_class_parameters` | 指定策略类的初始化必填参数 | `class_name` |

> **策略级资金**：`cta_strategies_get_all` 的每策略 `可用资金总量 / 已使用资金占比` 是报告「资金现状」块的数据源，**必须写入报告**（仅本次调仓涉及的策略，见 06_策略资金分配.md §7.3.1.1）；已有策略加仓时必须与 `资金调整` 指令互相核对（可用空间 < 缺口 → 附增资金额）。

#### D. 成交与委托

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `get_trades` | 系统本次启动后的成交记录 | `limit`（默认 50） |
| `get_active_orders` | 活动委托（未成交或部分成交） | 无 |

#### E. 行情与合约

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `get_tick` | 指定合约最新 Tick 行情 | `vt_symbol` |
| `get_history_bars` | 历史 K 线。**推荐直接传 `vt_symbol`** 由服务端解析；或传 `symbol` + `exchange` + `gateway_name`（须取自 `get_contract` / `get_all_contracts`，**严禁自行猜测**） | `vt_symbol` / `symbol`、`exchange`、`gateway_name`、`interval`（默认 1m）、`start`、`end` |
| `get_contract` | 指定合约信息 | `vt_symbol` |
| `get_all_contracts` | 全部合约 | 无 |
| `search_vt_symbol` | 搜索 vt_symbol / 查 ConID | `query`（ticker / 名称 / conid）、`market`（`IB` 时实时向网关查询以确保 conid 最新） |
| `subscribe_contract` | 订阅合约 Tick 行情（策略创建时自动订阅，通常无需手动调用；仅用于提前看行情或未被策略使用的合约） | `vt_symbol`、`gateway_name` |

> **vt_symbol 纪律**：IB 合约必须使用 `search_vt_symbol` 返回的形式（如 `265598.SMART`），**严禁 `ticker.SMART` 自行拼接**；币安 U 本位为 `SYMBOL_SWAP_BINANCE.GLOBAL`。
> **板块 ETF / 宏观行情不在 vnpy_mcp 内**：用 `scripts/get_market_data.py`（用法见 §13.1 与 README §5）。

#### F. 系统状态

| 工具 | 用途 |
|------|------|
| `get_gateways` | 已注册网关及连通状态（名称、是否连通、支持的交易所、已订阅合约数、账户数）—— 判断数据源是否可用 |
| `ping` | 健康检查（返回 `pong`） |
| `get_guide` | vnpy_mcp 工具集完整指南（工具分类、调用格式、返回示例、核心业务流程） |

#### G. 本地计算工具（scripts/）

| 工具 | 用途 | 关键用法 |
|------|------|---------|
| `scripts/rebalance_tools.py` | 调仓计算与校验工具 v2.2（输出中文键 JSON；纯标准库、无第三方依赖、确定性；**fund 为计算基准，见 06 §7.3.1 Step 0**）。9 个子命令：`fund` 资金框架（参数自检+自动调参 → 总预算 B → 策略槽位 → 每策略目标/初始资金 → 闭环 6 条，旧式 `python scripts/rebalance_tools.py --balance <权益> --available <可用现金>` 不带子命令亦兼容）；`gap` 缺口计算+资金匹配（06 §7.3.1.3/§7.3.1.5：`--snapshot 快照.json --balance --available`，1% 不动阈值/幅度截断/max_new 名额/方向异常 + 卖出释放/买入使用/剩余现金 → 闭环第 3/4 条）；`verify` 报告 JSON 校验门（10 §11.2 + 07 §8 + 闭环 6 条独立复算，`--report 报告.json [--balance --available]`，判定 = 输出「校验」字段 通过/不通过/无法校验，退出码 0/1/2 仅辅助）；`score` 板块评分（02 §4：`--prices 收盘价序列.json [--cycle 周期阶段] [--top-strong 4] [--bottom3-history 历史.json]`，动量 4 窗口 + 周期查表 + 分层 + 连弱风控）；`map` 持仓映射 S1–S5 分层（04 §6：`--strategies 快照.json --classifications 分层.json --balance`，映射以 stock_pool.json 为准 + T3 统计）；`exec` 执行约束与拆单（05 §7.3.3 + 07 §8.3 + 08 §9：`--plan 计划.json [--liquidity-pct 1]`，不追高/不买暴涨否决、流动性 1% 日均成交额上限、小/中/大单分档、滑点=规模÷日均成交额×价差×2、执行时段提示）；`cycle` 双周期判定（09 §10 + 07 §8.4：`--date YYYY-MM-DD [--last-rebalance ...] [--trigger ...]`，月度±10%/周五±3%/事件驱动，输出 max_delta_pct 建议）；`score2` 双层子板块评分（03 §5.3/§5.4：`--prices 子板块等权合成序列.json [--sector-score score输出.json] [--cycle 周期]`，最终=0.5×板块+0.5×独立，双层决策矩阵、Top7/Bottom6 分层、超板块 1σ 钳制）；`assemble` 报告骨架装配（10 §11.1：`--fund fund.json --gap gap.json [--score ..] [--score2 ..] [--map ..] [--out 报告.json]`，17 顶层字段骨架 + 数值字段自洽（顶层 % = $ ÷ B），文本/指令留 AI，填完必须 verify 复算） | 工具失效按 10「失效代码」铁律：只记录、任务内不改码 |

## 1. 核心理念

### 1.1 什么是板块轮动

板块轮动是一种**主动组合管理策略**，根据经济周期阶段在不同行业板块之间动态配置资金，超配有望跑赢的板块，低配可能跑输的板块。

### 1.2 与追涨杀跌的本质区别

| 维度 | 追涨杀跌 | 机构级轮动 |
|------|---------|-----------|
| 决策依据 | 当日涨幅榜 | 多因子综合评分 + 相对强弱 |
| 时间窗口 | 日线级别 | 周/月线级别中期动量 |
| 仓位管理 | 满仓进出 | 分批加减、资金闭环 |
| 风控 | 无 | 硬性仓位上限、止损规则 |
| 执行节奏 | 一次性 | 分多日拆单执行 |

### 1.3 核心原则（不可违反）

1. **永远先卖弱，再买强** — 不同时进行买卖操作，资金必须闭环
2. **分批执行（约束在轮次，不约束单条指令）** — 一轮调仓（整体）至少分 2-3 天完成，不单日大规模换仓；**单条指令是否拆分由 金额 / 事件窗口 / 动作类型 三个条件决定（§11.2），"维持 / 小单 / 条件触发"型指令不得强行拆成多日**
3. **单板块上限 20%，单票上限 5%** — 硬性风控红线
4. **中期动量优于短期爆发** — 6-12 个月相对强弱比 5 日涨幅更有意义
5. **宏观是总开关** — 大盘系统性风险时只卖不买
6. **持仓只认 vnpy_mcp 实时返回** — 板块持仓分析一律通过 vnpy_mcp 工具直读量化系统（量化系统必须正在运行）；**不使用任何 Redis 方面的工具**（含 Redis 状态板、`enable_publish_status_redis` 发布的状态、Redis HTTP 代理、Redis 缓存），也不得凭记忆或历史报告推断当前持仓
7. **轮动预测不当后视镜** — 方向来自「宏观驱动 → 领先板块 → 滞后板块」映射 + 拐点信号（§3.5），只抓拐点或初期；涨幅榜只作确认，不作依据

## 3. 第一层：宏观环境定基调

### 3.1 经济周期四阶段与板块映射

| 周期阶段 | 宏观特征 | 领涨板块 | 防御板块 | 核心指标 |
|---------|---------|---------|---------|---------|
| **早期复苏** | 利率下降、信用扩张、PMI 回升 | 金融(XLF)、消费可选(XLY)、工业(XLI)、材料(XLB) | — | 收益率曲线斜率、PMI 拐点 |
| **中期扩张** | 稳定增长、温和通胀 | 科技(XLK)、能源(XLE)、工业(XLI) | — | GDP 增速、失业率 |
| **晚期过热** | 通胀上升、加息、增长放缓 | 能源(XLE)、材料(XLB) | 必需消费(XLP)、医疗(XLV)、公用事业(XLU) | CPI、美联储利率决议 |
| **衰退** | GDP 负增长、失业上升 | — | 公用事业(XLU)、必需消费(XLP)、医疗(XLV) | 信用利差、失业率 |

> 各阶段领涨 / 防御板块在**机会发现中的应用**统一记录在 **§3.5 场景库（场景 A）**；本节只负责"周期状态判定"（判定规则见 §3.3）。

### 3.2 宏观信号监测清单

| 信号类别 | 具体指标 | 数据来源 | 更新频率 |
|---------|---------|---------|---------|
| 利率 | 美联储基准利率、2Y/10Y 利差 | FRED | 每日 |
| 信用 | 投资级/高收益信用利差 | FRED / Bloomberg | 每日 |
| 经济景气 | ISM 制造业/非制造业 PMI | ISM | 每月 |
| 就业 | 非农就业、失业率、初请失业金 | BLS | 每周/每月 |
| 通胀 | CPI、PPI、PCE | BLS / BEA | 每月 |
| 市场情绪 | Fear & Greed Index | CNN Money | 每日 |

### 3.3 宏观状态判定规则

```
IF 收益率曲线陡化 AND PMI 连续 2 月回升 AND 信用利差收窄:
    周期阶段 = 早期复苏
ELIF GDP 正增长 AND 失业率低位 AND 通胀温和:
    周期阶段 = 中期扩张
ELIF CPI > 3% AND 美联储加息 AND 收益率曲线平坦化:
    周期阶段 = 晚期过热
ELIF GDP 负增长 AND 失业率上升 AND 信用利差扩大:
    周期阶段 = 衰退
```

### 3.4 大盘总开关规则

```
IF 大盘处于系统性风险（S&P 500 跌破 200 日均线 OR VIX > 30）:
    操作模式 = 防御模式（只卖不买，逐步减仓至 50% 以下）
ELIF 大盘震荡（S&P 500 在 50-200 日均线之间）:
    操作模式 = 正常轮动（小范围调仓）
ELIF 大盘趋势向上（S&P 500 在 50 日均线上方）:
    操作模式 = 积极模式（适度加仓强势板块）
```

### 3.5 机会发现（轮动预测）：场景库 + 拐点信号

> **轮动预测不靠"谁涨得好"**：涨幅榜是后视镜。机会发现 = **场景库**（钱下一步流向哪，3.5.1）+ **拐点信号**（何时进场，3.5.2），**只抓轮动拐点或初期**；已走完的行情只减不加。
> **所有预测（发现机会）场景统一记录在本节（场景 A–D）**，其余章节只引用、不另设。

#### 3.5.1 机会场景库（钱下一步流向哪）

**场景 A：周期阶段切换**（长周期维度；判定规则见 §3.1 / §3.3）

| 周期阶段 | 领涨板块（机会） | 防御板块（避风港） |
|---------|---------|---------|
| 早期复苏 | 金融 (XLF)、可选消费 (XLY)、工业 (XLI)、材料 (XLB) | — |
| 中期扩张 | 科技 (XLK)、能源 (XLE)、工业 (XLI) | — |
| 晚期过热 | 能源 (XLE)、材料 (XLB) | 必需消费 (XLP)、医疗 (XLV)、公用事业 (XLU) |
| 衰退 | — | 公用事业 (XLU)、必需消费 (XLP)、医疗 (XLV) |

> 机会点 = **周期判定切换后的前几周进入领涨板块**；周期已被充分定价后不追。

**场景 B：宏观事件驱动 → 领先/滞后**（中周期维度）

| 宏观驱动（已知/可预期） | 领先板块（先兑现） | 滞后板块（后兑现） | 兑现时滞 |
|------------------------|-------------------|-------------------|---------|
| FOMC 加息（预期概率高，如 66%） | 金融（净息差扩张先行） | 可选消费 | 政策落地后数周 |
| Brent > 100（油价高企） | 能源（业绩当期兑现，往往已走完） | 材料 / 化工（成本传导滞后） | 1-2 个月业绩兑现 |
| 10Y 贴近 5%（利率高位） | — | 利率敏感组受压：REITs / 公用事业 / 长久期成长 | 持续压制，直至利率拐头 |

> 上表是**映射框架**：具体驱动每次以当期数据为准（FOMC 概率、油价、10Y、IWM 等取自大盘报告与 web-indicators）；驱动变了，映射就重算。

**场景 C：均值回归**（短周期维度）

- 小盘塌陷（如 IWM 大跌）后**利率企稳** → 小盘修复弹性最大，并向联动的中盘 / 周期外溢
- 超跌板块 + 驱动压力解除（如利率拐头）→ 放量修复（确认信号见 3.5.2 第 4 条）

**场景 D：龙头领涨 → 跟涨扩散**（板块内 / 跨板块维度）

- 龙头股率先放量突破创新高 → 中盘 / 跟风股跟涨、板块广度打开（>60% 上涨）→ 主线板块领涨 → 关联板块 / 小盘补涨
- **龙头不动、只有杂毛股乱涨的板块行情不可信**（时机见 3.5.2 第 5/6 条）

#### 3.5.2 拐点信号清单（时机：何时进场，满足任一类才认定"拐点或初期"成立）

1. **事件拐点**：重大宏观事件落地或预期剧变（FOMC 决议 / 点阵图、CPI、非农），且事件后首日-首周相关板块出现确认性相对强弱变化
2. **价格拐点**：领先指标拐头——如 10Y 收益率连续回落 / 企稳、油价跌破关键均线
3. **相对强弱拐点**：滞后板块的 RS 曲线由下行转为走平 / 上翘（尚未创新高，属初期）
4. **均值回归触发**：超跌板块（如小盘 IWM）在驱动压力解除（利率企稳）后出现放量修复
5. **龙头领涨 → 跟涨传导**：板块内**龙头股率先突破**（放量创新高），随后中盘 / 跟风股跟涨、板块广度打开（>60% 上涨）；再向外传导为「主线板块领涨 → 关联板块 / 小盘补涨」
6. **广度扩散**：资金从单一领先板块扩散到关联滞后板块（联动板块同涨）

#### 3.5.3 反后视镜纪律

- **禁止**把"近期涨幅榜 Top"直接当作轮动方向——必须能回答"驱动是什么、处在领先→滞后的哪一段"
- **已走完**（驱动已充分兑现、涨幅透支，如油价高位时的能源）→ 不加仓，只减仓或持有
- **滞后受益板块**在驱动确认后分批布局（对应 §7.3.3 分档建仓），不等涨起来再追
- 评分模型（§4）的动量因子只用于**确认**拐点，不用于**发现**方向；发现方向靠本节场景库

## 4. 第二层：板块评分与排序

### 4.1 板块分类体系

采用 GICS 11 大行业板块，对应 ETF 如下：

| 板块 | ETF 代码 | 周期属性 |
|------|---------|---------|
| 信息技术 | XLK | 成长/周期 |
| 金融 | XLF | 周期 |
| 医疗保健 | XLV | 防御 |
| 消费可选 | XLY | 周期 |
| 消费必需 | XLP | 防御 |
| 能源 | XLE | 周期 |
| 工业 | XLI | 周期 |
| 材料 | XLB | 周期 |
| 公用事业 | XLU | 防御 |
| 房地产 | XLRE | 防御 |
| 通信服务 | XLC | 成长 |

### 4.2 多因子评分模型

```
板块综合得分 = 0.30 × 动量因子 + 0.25 × 经济周期因子
              + 0.20 × 价值因子 + 0.15 × 质量因子 + 0.10 × 情绪因子
```

#### 4.2.1 动量因子（权重 30%）

| 子指标 | 权重 | 计算方式 |
|-------|------|---------|
| 6 个月相对强弱 (RS) | 40% | 板块价格 / SPY 价格，取 6 个月变化率 |
| 3 个月相对强弱 (RS) | 30% | 同上，3 个月窗口 |
| 12 个月相对强弱 (RS) | 20% | 同上，12 个月窗口 |
| 20 日 ROC | 10% | 20 日变化率，捕捉短期趋势 |

**RS 计算**：
```
RS = 板块 ETF 价格 / SPY 价格
RS_ROC = (RS_today / RS_n_days_ago - 1) × 100
```

**信号质量确认（四位一体）**：
- 龙头领涨：板块内**龙头股**（选股池 T1 / 板块市值 Top）率先放量突破创新高——龙头是板块行情的第一确认，**龙头不动的普涨不可信**
- 价格突破：板块价格突破关键阻力位
- RS 突破：RS 曲线同步走强
- 市场广度：板块内大部分成分股上涨（>60%）——即龙头领涨后的**跟涨扩散**是否发生

> 动量因子只做**确认**不做**发现**：轮动方向靠 §3.5 的「宏观驱动 → 领先/滞后映射 + 拐点信号」；纯动量排名 = 后视镜。

#### 4.2.2 经济周期因子（权重 25%）

根据当前宏观阶段，给板块打分：

| 板块 | 早期复苏 | 中期扩张 | 晚期过热 | 衰退 |
|------|---------|---------|---------|-----|
| 金融 (XLF) | +2 | +1 | -1 | -2 |
| 科技 (XLK) | +1 | +2 | 0 | -2 |
| 消费可选 (XLY) | +2 | +1 | -1 | -2 |
| 工业 (XLI) | +2 | +1 | 0 | -1 |
| 材料 (XLB) | +1 | +1 | +1 | -2 |
| 能源 (XLE) | -1 | +1 | +2 | -1 |
| 医疗 (XLV) | 0 | 0 | +1 | +2 |
| 消费必需 (XLP) | -1 | 0 | +1 | +2 |
| 公用事业 (XLU) | -2 | -1 | +1 | +2 |
| 房地产 (XLRE) | -1 | 0 | 0 | +1 |
| 通信 (XLC) | +1 | +1 | 0 | -1 |

#### 4.2.3 价值因子（权重 20%）

| 子指标 | 权重 | 计算方式 |
|-------|------|---------|
| 板块 P/E 历史分位 | 50% | 当前 PE 在 5 年历史中的百分位（越低越好） |
| 板块 P/B 历史分位 | 30% | 当前 PB 在 5 年历史中的百分位 |
| 股息率 | 20% | 板块股息率相对历史水平 |

#### 4.2.4 质量因子（权重 15%）

| 子指标 | 权重 | 计算方式 |
|-------|------|---------|
| ROE 中位数 | 40% | 板块内个股 ROE 中位数 |
| 盈利增长稳定性 | 30% | 过去 3 年盈利增长的标准差（越低越好） |
| 负债率 | 30% | 板块整体 D/E 比率（越低越好） |

#### 4.2.5 情绪因子（权重 10%）

| 子指标 | 权重 | 计算方式 |
|-------|------|---------|
| 资金流 | 50% | 板块 ETF 过去 5 日资金净流入 |
| 期权偏度 | 30% | 板块看跌/看涨期权比率 |
| 分析师情绪 | 20% | 板块内上调/下调评级比率 |

### 4.3 板块排序与分层规则

```
每周/每月对所有 11 个板块进行综合评分并排序：

强势板块（Top 3-4）：综合得分最高 → 超配 / 加仓
中性板块（中间 4-5）：综合得分中等 → 维持权重
弱势板块（Bottom 3）：综合得分最低 → 低配 / 减仓

附加条件：
- 强势板块必须满足 RS 曲线处于上行趋势
- 弱势板块若连续 2 周排名 Bottom 3 → 强制减仓
- 弱势板块若连续 3 周排名 Bottom 3 → 强制清仓
```

## 5. 第三层：子板块评分体系（GICS Level 2）

### 5.1 为什么需要子板块粒度

GICS Level 1（11 个 Sector）在某些场景下粒度太粗：

```
示例：2023-2024 AI 行情
  信息技术 (XLK) 整体强势
  但内部：半导体设备 +80%，软件 +20%，硬件 +10%

### 5.3 双层评分模型

```
最终子板块得分 = 0.50 × 所属 Sector 得分 + 0.50 × 子板块独立得分
```

#### 5.3.1 子板块独立得分

与 Sector 评分使用相同的多因子模型，但数据源为子板块级别：

```
子板块独立得分 = 0.30 × 子板块动量 + 0.25 × 经济周期因子
               + 0.20 × 子板块价值 + 0.15 × 子板块质量 + 0.10 × 子板块情绪
```

**动量因子计算**：

```
子板块 RS = 子板块价格（等权合成）/ SPY 价格
子板块 RS_ROC = (RS_today / RS_n_days_ago - 1) × 100
```

对于没有独立 ETF 的子板块，使用成分股等权合成价格指数：

```
子板块价格 = 成分股价格等权平均
成分股选择：该子板块内市值 Top 5 或流动性 Top 5 的个股
```

#### 5.3.2 双层评分决策矩阵

| Sector 评分 | 子板块评分 | 最终决策 |
|------------|-----------|---------|
| 强势 (Top 3-4) | 强势 | **强烈加仓** — 板块和子板块共振 |
| 强势 (Top 3-4) | 弱势 | **仅保留，不加仓** — 板块强但细分弱 |
| 弱势 (Bottom 3) | 强势 | **保留底仓观察** — 子板块可能逆势 |
| 弱势 (Bottom 3) | 弱势 | **优先减仓/清仓** — 双重弱势 |

### 5.4 子板块排序与分层

```
对所有 25 个子板块进行评分并排序：

强势子板块（Top 6-8）：综合得分最高 → 超配
中性子板块（中间 10-12）：维持权重
弱势子板块（Bottom 5-7）：低配 / 减仓

附加规则：
- 子板块评分不得高于其所属 Sector 评分超过 1 个标准差
  （防止子板块过度偏离板块基本面）
- 若 Sector 为弱势但子板块为强势 → 子板块仓位上限减半
```

### 5.5 子板块轮动的典型场景

```
场景一：科技板块 (XLK) 内部轮动
  Sector 评分：科技 = 强势（排名第 2）
  子板块评分：
    - 半导体与半导体设备 = 强势（排名第 1）
    - 软件与服务 = 中性（排名第 10）
    - 技术硬件与设备 = 弱势（排名第 20）
  操作：加仓半导体，维持软件，减仓硬件

场景二：医疗板块 (XLV) 内部轮动
  Sector 评分：医疗 = 中性（排名第 6）
  子板块评分：
    - 制药与生物科技 = 强势（排名第 5）
    - 医疗设备与服务 = 弱势（排名第 18）
  操作：加仓生物科技，减仓医疗设备
```

> 注：本节的"场景"是**评分应用示例**（评分出来之后怎么操作），**不是机会发现场景**；预测（发现机会）的场景库统一在 §3.5。

**铁律**：

1. **一律走 vnpy_mcp**：持仓、成本、盈亏、可用资金只以上述工具**本次实时返回**为准，不得用记忆、历史报告或推断值。

3. **映射依据**：以 `cta_strategies_get_all` 返回的 `品种信息`（ticker / 分类 / 行业）+ `scripts/stock_pool.json` 的 ticker→子板块反向索引做映射；两者都定位不到的持仓 → 列入「未映射持仓」，**不得丢弃、不得凭印象归类**。
4. **取不到数据**：量化系统未运行或工具报错 → 停止调仓流程并如实上报，不得降级为估算值。

### 6.2 双层持仓分层

根据 Sector 评分 + 子板块评分，将所有持仓分为五层：

| 层级 | Sector | 子板块 | 操作策略 |
|------|--------|--------|---------|
| **S1 强烈加仓** | 强势 | 强势 | 优先加仓，最高权重 |
| **S2 适度加仓** | 强势 | 中性 | 小幅加仓优质标的 |
| **S3 维持** | 中性 | 任意 | 维持权重，不做调整 |
| **S4 观察减仓** | 弱势 | 强势 | 保留底仓，不加仓 |
| **S5 优先减仓** | 弱势 | 弱势 | 阶梯减仓/清仓 |

### 6.3 个股层面的二次筛选

在子板块内部，对个股进行二次评分：

```
个股评分 = 0.30 × Sector 得分 + 0.30 × 子板块得分
         + 0.20 × 个股动量 + 0.15 × 个股质量 + 0.05 × 个股流动性

S1 层级内：
  - 个股评分 Top 60% → 可加仓
  - 个股评分 Bottom 40% → 仅保留，不加仓

S5 层级内：
  - 个股评分 Top 20% → 保留底仓观察
  - 个股评分 Bottom 80% → 优先减仓/清仓
```

### 6.4 个股选股池与分层

#### 6.4.1 个股 → 子板块映射

个股归属 GICS 子板块的确定方式（按优先级）：

```
方式一：GICS 官方分类（最准确）
  - 数据源：Bloomberg、FactSet、MSCI 的 GICS 分类接口
  - 每个股票有唯一的 GICS 代码（8 位数字，如 45301020 = 半导体）
  - 每季度更新一次（GICS 年度调整在 3 月/9 月）

方式二：ETF 成分股反推（次优）
  - 子板块 ETF（如 SMH）的成分股 = 该子板块的核心股票
  - 适用于有独立 ETF 的子板块

方式三：行业关键词匹配（兜底）
  - 通过公司财报中的 SIC/NAICS 代码或业务描述匹配
  - 精度较低，仅作为补充
```

#### 6.4.2 三层选股池

对每个 GICS 子板块，维护一个 **分层选股池**：

| 层级 | 定位 | 数量 | 操作策略 |
|------|------|------|---------|
| **Tier 1 龙头股** | 板块风向标，流动性最好 | 3-5 只 | 板块配置的主要工具，加仓/减仓首选 |

| **Tier 3 潜力小盘** | 高赔率品种，高风险 | 5-15 只 | 总仓位 ≤ 5%，单只 ≤ 1% |

#### 6.4.3 选股评分公式

```
个股综合评分 = 0.25 × 子板块得分 + 0.20 × 个股动量
             + 0.15 × 个股质量 + 0.15 × 个股估值
             + 0.10 × 个股流动性 + 0.10 × 催化剂信号
             + 0.05 × 小盘溢价（仅 Tier 3 适用）

## 7. 第五层：调仓执行流程

### 7.1 总体流程

```
Step 1: 宏观判定 → cta_report_get 拉取大盘 + 美股做多/做空报告（见 §6），确定操作模式（积极/正常/防御），轮动预测与做多/做空报告交叉印证（§3.5）
Step 2: 板块评分 → 输出 11 板块排序
Step 3: 持仓映射 + 资金盘点 → 用 vnpy_mcp `cta_strategies_get_all`（+ `get_positions` 核对）读取实际策略持仓，映射到板块并分层（详见 6.1）；同时读取账户级与策略级资金（见 §7.3.1.1）
Step 4: 目标分配与缺口 → 确定板块/个股/策略目标分配（见 §7.3.1.2/.3），缺口 = 目标 − 当前
Step 5: 先处理弱势持仓（减仓/清仓，缺口中的减/清部分）
Step 6: 计算释放资金，再处理强势持仓（加仓/新开，缺口中的加/开部分；资金闭环自检 §7.3.1.5）
Step 7: 风控校验（含资金闭环，§7.3.1.5）
Step 8: 输出调仓报告 JSON（含任务参数、资金现状、目标分配、分批计划、调仓相关参数与意图备注，模板见 §11.1）
```

### 7.2 处理弱势持仓（先卖）

**原则：先卖后买，资金闭环，绝不同时操作**

#### 7.2.1 减仓节奏

```
Day 1: 弱势板块持仓统一减仓 30%-50%
Day 2: 若板块评分仍为弱势 → 再减 30%（剩余仓位的 30%）
Day 3: 若板块评分连续 3 周 Bottom 3 → 清仓
```

#### 7.2.2 减仓优先级

```
优先减仓顺序：
1. 板块评分最低的板块中的个股
2. 个股评分最低的个股
3. 仓位最重的个股（降低集中度）
4. 流动性最好的个股（容易卖出）
```

#### 7.2.3 特殊情况处理

```
IF 个股处于盈利状态:
    正常减仓，锁定利润
IF 个股处于亏损状态:
    若板块持续弱势 → 止损减仓（不因亏损而持有）
    若板块只是短期回调 → 可保留底仓观察
IF 个股有重大利好（财报超预期、新产品获批等）:
    即使板块弱势，可保留底仓
```

### 7.3 处理强势持仓（后买）

#### 7.3.1 任务参数与资金分配（从现状到目标）

> **资金分配是调仓计算的核心**："先卖弱、再买强"只是执行节奏，"配多少、配给谁"由本节决定。五步：① 资金盘点 → ② 目标分配 → ③ 缺口 → ④ 策略资金定数 → ⑤ 资金闭环自检。
> 注意：①–③ 必须在 §7.1 的 Step 5（卖）之前完成——卖/买只是缺口的执行。

**任务参数**（在任务提示词中给出，省略用默认值；本次实际取值必须写入报告「任务参数」块）：

| 参数 | 默认 | 范围 | 含义 | 作用 |
|------|------|------|------|------|
| `invest_mult` 投入倍率 | 2 | 1–5 | 目标组合初始资金总和 = 账户可用现金 × 该值；1 = 不用保证金，>1 = 使用 IB 保证金（IB 上限 5 倍） | 7.3.1.2/.4/.5 |
| `mode` 操作模式 | auto | auto / 积极 / 正常 / 防御 | auto = 跟随大盘报告（§3.4）；手动指定则覆盖 | 7.3.1.2 板块目标区间表 |
| `max_delta_pct` 单轮调仓幅度上限 | 10 | 3–10 | 单轮 Σ\|目标−当前\| / 总资产 ≤ 该值；周度微调 3，月度/全量 10 | 7.3.1.3 |
| `max_new` 本轮新仓只数 | 2 | 0–3 | 本轮允许的新开仓数量 | 7.3.1.3/.6 |
| `max_single_pct` 单票上限 | 5 | 1–10 | 单只个股仓位上限（占总资产 %） | 7.3.1.2 |
| `max_sector_pct` 单板块上限 | 20 | 10–30 | 单个板块仓位上限（占总资产 %） | 7.3.1.2 |
| `base_capital` 每策略基准资金 | 10000 | 5000–50000 | 每策略基准资金额度 (USD)：最小开仓门槛 + 分配单位；单票目标资金 < 1 个基准单位 → 不开，并入同板块其他票 | 7.3.1.2/.3 |
| `max_strategies` 策略总数上限 | auto | ≤50 | 目标组合策略总数（股票只数）；auto = 总预算 B ÷ base_capital（例：B=30万、基准=1万 → 30 个，平均每个 1 个基准单位），硬顶 50（§8.1 管理复杂度） | 7.3.1.2/.3/.4 |

> 所有仓位 %（板块 / 个股 / 总仓位）分母一律为**总资产**（`get_accounts.balance`）；`invest_mult > 1` 时总仓位可超过 100%（保证金买入）。

##### 7.3.1.1 资金现状（vnpy_mcp，工具见 §6.1.1 / §13.4）

| 层级 | 工具 | 取什么 | 用途 |
|------|------|--------|------|
| 账户级 | `get_accounts` | `balance`（总资产）、`available`（可用现金）、`frozen` | 仓位百分比分母、现金缓冲来源 |
| 策略级 | `cta_strategies_get_all` | 每策略 `可用资金总量`、`已使用资金占比`、`实际持仓`、`持仓目标` | 各策略资金池与可用空间 |

- 必须写入报告「资金现状」块（模板 §11.1）：账户级全写；策略级只列**本次调仓涉及的策略**（加仓 / 新开 / 减仓 / 清仓 / 维持），其余一行"N 只未涉及策略"
- 可用空间 (USD) ≈ `可用资金总量` × (1 − `已使用资金占比`)
- 已有策略要加仓而资金池不足（可用空间 < 缺口）→ 除"加仓"指令外必须附 `资金调整`（见 7.3.1.4）

**币种规则（IB 账户）**：
- `get_accounts` 返回可能含**多币种条目**（IB 多币种账户：accountid / currency 字段区分，如 USD / HKD / CNY）
- **本模块所有金额一律美元口径**（美股以美元计价）：优先取 **USD 币种条目**的 `balance` / `available` 作基准
- 无独立 USD 条目、只有本位币（如 HKD）→ 按当前 USD/本位币汇率换算为美元，并在「资金现状」块记录所用汇率与时点（汇率来源：web-indicators / 行情数据脚本或联网查询，须可查证）
- **禁止**把不同币种条目直接相加，或用非 USD 条目作仓位百分比分母

##### 7.3.1.2 目标分配（板块 → 个股 → 策略）

**总预算**（由 `invest_mult` 驱动，IB 保证金账户）：

```
总预算 B = 可用现金（get_accounts.available）× invest_mult        # 目标：Σ 各策略初始资金
目标仓位总和 = B ÷ 1.2                                            # 1.2 为每策略缓冲（见 7.3.1.4）
保证金占用 = max(0, 目标仓位总和 − 可用现金)                       # invest_mult>1 且现金占比低时启用
```

**板块目标 %**（操作模式 × 板块评分档；`mode=auto` 未触发 §8.2 防御时默认"正常"列，均受 §8.1 硬上限约束）：

| 板块评分 | 正常 | 积极 | 防御 |
|---------|------|------|------|
| 强势（Top 3） | 12%–20% | 15%–20% | 5%–10% |
| 中性 | 5%–12% | 8%–15% | 2%–8% |
| 弱势（Bottom 3） | 0%–5% | 0%–5% | 0%–3% |

- 区间内取值由机会场景强度（§3.5 场景库置信度、与做多/做空报告交叉印证程度）决定；**分配依据必须写入报告「目标分配」块**（板块 + 当前 % + 目标 % + 依据）
- **预算归一化**：各板块目标 % 之和 = S；若 S × 总资产 ≠ 目标仓位总和 → 系数 k = 目标仓位总和 / (S × 总资产) 等比缩放全部板块；缩放后仍须满足 `max_sector_pct` / 前三大板块 ≤50% / 单票 `max_single_pct`，触顶则截断、余额分给未触顶板块
- 弱势且当前有持仓的板块 → 目标 = 0（卖出，见 §7.2）

**个股目标 %**（板块内）：
- 每板块 1-2 只（见 7.3.1.6），T1 龙头目标 ≥ T2 中盘
- 硬上限：单票 ≤ `max_single_pct`（单只 Tier 3 ≤1%，§8.1）；板块内个股目标之和 = 板块目标 %（必须相等）
- **最小开仓门槛**：单票目标资金 = 个股目标 % × 总资产 ≥ `base_capital`（1 个基准单位）；不足 1 单位 → 不开，并入同板块其他票（原因写入「意图备注」）
- **策略总数**：目标组合策略总数 ≤ `max_strategies`（= B ÷ base_capital，硬顶 50）；超出 → 按个股评分保高弃低（T1 优先），其余并入或不开

**策略目标资金 (USD)** = 个股目标 % × 总资产（`get_accounts.balance`）——即该股票策略 `初始资金` 参数的目标值（见 7.3.1.4）

##### 7.3.1.3 缺口计算（目标 − 当前 → 调仓方向）

```
对每只股票：缺口 = 策略目标资金 − 当前持仓市值
  缺口 > 0 且板块强势       → 加仓（新仓占本轮 ≤ max_new 个名额，且目标资金 ≥ base_capital，见 7.3.1.6）
  缺口 < 0 且板块弱/中性   → 减仓 / 清仓（见 §7.2）
  |缺口| < 总资产 1%       → 维持（不动，防过度交易，见 §12.2）
```

- **幅度上限**：Σ\|缺口\| / 总资产 ≤ `max_delta_pct`（默认 10%）；超出 → 按缺口绝对值从大到小处理，达到上限的其余票转「维持 + 触发条件」
- 各板块个股指令的目标 % 之和必须与「目标分配」块一致（防个股指令与板块目标漂移）

##### 7.3.1.4 策略资金定数（初始资金 / 资金调整）

| 情形 | 规则 |
|------|------|
| 所有策略（已有加仓 / 新增） | `初始资金` = 个股目标资金 × 1.2（上限值，目标仓位 ≈ 初始资金的 83%，余量为手续费/滑点/止损缓冲），取整 |
| 已有策略加仓 | 若 `初始资金` 大于该策略当前 `可用资金总量` → 差值即增资金额（写入 `资金调整`）；若小于 → 不削减（资金不收回，富余写入「说明」） |
| 减仓 / 清仓 | 不动 `初始资金`，只调 `持仓目标` / `操作方向` |

- **总量核对**：Σ `初始资金` = B = 可用现金 × `invest_mult`（任务参数），天然 ≤ 可用现金 × 5（IB 保证金上限）
- **策略数核对**：目标组合策略总数 N ≤ `max_strategies` = B ÷ `base_capital`（硬顶 50，§8.1）；即平均 B/N ≥ base_capital（每个策略 ≥ 1 个基准单位），单策略 ≥ 1 单位
- 防御模式（或 S&P 破 200 日线，§8.2）：目标仓位总和另压至 ≤ 总资产 × 50%，即 B 取 min(可用现金 × invest_mult, 总资产 × 50% × 1.2)
- 超预算 → 按「新仓名额 → 单票目标 → 板块目标」顺序压缩，并在「执行建议」中记录压缩过程

##### 7.3.1.5 资金闭环自检（输出前必须全部通过，对应 §11.2 规则 5）

1. **预算**：Σ 各策略 `初始资金` ≤ 账户可用现金 × `invest_mult`（任务参数，默认 2 倍）
2. **IB 保证金上限**：Σ 各策略 `初始资金` ≤ 账户可用现金 × 5（invest_mult ≤ 5 时自动满足）
3. **资金来源**：本轮 `买入使用` ≤ 本轮 `卖出释放` + 可用现金 × `invest_mult`；「资金来源」必须写清（卖出哪只 / 可用现金 / 保证金）
4. **现金下限（仅无保证金）**：`invest_mult = 1` 时，剩余现金 = 可用现金 + 卖出释放 − 买入使用 ≥ 总资产 × 5%（§8.1）；`invest_mult > 1` 时现金可为负（保证金占用），此项不适用
5. **每策略缓冲**：每条指令 / 新增策略的 `初始资金` ≥ 个股目标资金 × 1.2（防满仓无缓冲）
6. **基准与数量**：每策略目标资金 ≥ `base_capital`（最小开仓门槛）；策略总数 N ≤ B ÷ `base_capital`（硬顶 50）

##### 7.3.1.6 买入端执行约束（释放资金分配规则）

```
释放资金分配规则：
1. 只流入当天排名 Top 2-3 的强势板块
2. 每个强势板块只加仓 1-2 只个股
3. 优先加仓已持有的优质标的（不开过多新仓）
4. 新开仓不超过 2 只（防止持仓数量爆炸）
5. 板块内**优先加仓已放量突破的龙头**（选股池 T1 / 市值 Top）；跟涨股等广度确认（>60% 上涨）后再配
```

## 8. 第六层：仓位约束与风控

### 8.1 硬性仓位上限

| 约束项 | 上限 | 说明 |
|-------|------|------|
| 单个板块 (Sector) 总仓位 | ≤ 20% | 防止板块系统性风险 |
| 单个子板块 (Industry Group) 总仓位 | ≤ 12% | 防止子板块过度集中 |
| 单只个股仓位 | ≤ 5% | 防止个股黑天鹅 |
| Tier 3 小盘股总仓位 | ≤ 5% | 小盘股高风险，总量控制 |
| 单只 Tier 3 小盘股仓位 | ≤ 1% | 单只小盘股严格限制 |
| 前 3 大板块合计 | ≤ 50% | 防止过度集中 |
| 现金最低比例 | ≥ 5% | 仅无保证金（invest_mult=1）适用；保证金（invest_mult>1）时现金可为负，改按 §7.3.1.5 预算/上限校验 |
| 最大持仓数量 | ≤ 50 只 | 管理复杂度上限 |

### 8.2 止损规则

| 触发条件 | 操作 |
|---------|------|
| 个股亏损 > 8% | 强制止损 |
| 板块评分连续 2 周 Bottom 3 | 板块内持仓减仓 50% |
| 板块评分连续 3 周 Bottom 3 | 板块内持仓清仓 |
| S&P 500 跌破 200 日均线 | 总仓位降至 50% 以下 |
| VIX > 30 | 停止所有买入操作 |

### 8.3 流动性风控

```
单日单只个股买卖金额 ≤ 该股日均成交额 × 1%
（防止冲击成本过大）

示例：
  AAPL 日均成交额 = 100 亿美元
  单日最大买卖 AAPL 金额 = 1 亿美元（对散户 AI 可放宽）
```

### 8.4 再平衡触发条件

满足以下任一条件即触发再平衡：

2. 板块评分发生重大变化（Top 3 板块变更）
3. 子板块评分发生重大变化（Top 6 子板块变更超过 3 个）

5. 单板块仓位超过 20% 上限
6. 单子板块仓位超过 12% 上限
7. 大盘进入防御模式
```

## 9. 第七层：拆单与执行优化

> 拆单在报告中的表达方式：JSON 的「分批计划」字段（同一目标仓位拆成多日/多笔目标值，对应 §7.2.1/§7.3.2 的节奏）。

### 9.1 拆单策略

| 订单规模 | 拆单方式 | 执行周期 |
|---------|---------|---------|
| 小单（< 5% 日均成交额） | 一次性市价单 | 当日 |
| 中单（5%-20% 日均成交额） | 分 3-5 笔，每 30 分钟一笔 | 当日 |
| 大单（> 20% 日均成交额） | 分 2-3 天，每天均匀拆单 | 2-3 天 |

### 9.2 执行时间窗口

```
美股最佳执行时段（美东时间）：
- 开盘后 30 分钟（9:30-10:00）：流动性最好，但波动大
- 午盘（11:00-14:00）：流动性稳定，适合拆单
- 收盘前 30 分钟（15:30-16:00）：机构调仓密集，流动性好

避免执行时段：
- 开盘前 15 分钟（9:30-9:45）：波动剧烈，价差大
- 午休前后（12:00-12:30）：流动性下降
```

### 9.3 滑点控制

```
预期滑点 = 订单规模 / 日均成交额 × 平均价差 × 2

IF 预期滑点 > 0.3%:
    缩小单笔订单规模
    延长执行周期
    改用限价单
```

## 10. 双周期再平衡机制

### 10.1 月度大再平衡

```
每月第一个交易日执行：
1. 全面重新计算 11 板块多因子评分
2. 全面重新计算 25 子板块多因子评分
3. 重新排序并确定强势/中性/弱势板块及子板块
4. 全面调整板块及子板块权重至目标配置
5. 调仓幅度控制在 ±10% 以内（避免过度换手）
```

### 10.2 周度小幅微调

```
每周五执行：
1. 更新板块评分（仅更新动量因子和情绪因子）
2. 更新子板块评分（仅更新动量因子和情绪因子）
3. 检查是否有板块排名发生重大变化
4. 检查是否有子板块排名发生重大变化
5. 如有板块从强势跌出 Top 5 → 小幅减仓
6. 如有板块新进入 Top 3 → 小幅加仓
7. 如有子板块从强势跌出 Top 8 → 小幅减仓
8. 单次调仓幅度不超过 ±3%
```

### 10.3 异常事件触发

```
以下事件触发即时评估（非固定周期）：
1. 美联储利率决议
2. 重大经济数据发布（非农、CPI、GDP）
3. 地缘政治事件
4. 板块内重大并购/监管变化
```

#### 分批计划规则（按单条指令定，不强行拆 2-3 天）

- **最少 1 条**（单日 / 单笔即可）；**满足以下任一条件才必须拆多条**：
  1. 单笔金额 > 该股日均成交额的 1%（流动性约束，见 §9.1）
  2. 执行期跨越事件窗口（FOMC / 财报等）——事件前只锁定高置信部分，其余留给事件后情景
  3. 动作为减仓 / 清仓——第二批保留条件分支（按第一批后的市场反馈决定是否继续，见 §7.2.1）
- **维持 / 条件触发型**：只写 1 条 + 触发条件，**禁止凑批**
- **自洽规则**：`目标持仓(i) = 目标持仓(i-1) − 本批数量`，且各批数量之和 ≤ 当前持仓；出现"扩大某批"情形时，目标持仓必须同步修正

#### 数值字段纯净规则（输出前自检）

1. **`调仓相关参数` 的值只留数值 / 布尔 / 枚举**（如 `false`、`0.056`）；说明性注解（当前状态、钳制逻辑、维持原因）一律进「意图备注」或「调仓理由」，不得混进参数值
2. **`操作模式` 为纯枚举**：只允许 `积极` / `正常` / `防御`（依据 §3.4）；判定理由全部写「风控校验.大盘状态确认」，不得在枚举值后附加句子
3. **`风控校验` 百分比必须自洽**：板块% = 该板块下所有个股% 之和（同一价格时点计算）；"前三大板块"必须**按调仓后板块%降序取最大的三个**（不得用其他板块顶替），列出三分项明细（板块名 + %），合计 = 分项之和，不得只给模糊区间
4. **顶层 % 与 $ 互验**：`调仓后总仓位_pct / 调仓后现金_pct` 必须 = 对应 `$ 字段（资金汇总）÷ 总资产`，并与各票%之和交叉核对；三者不一致即为算错，停止输出并修正（防"分项加总正确但顶层数错"的二阶错误）
5. **资金闭环（六条，见 §7.3.1.5）**：Σ `初始资金` ≤ 可用现金 × `invest_mult`（任务参数，默认 2 倍）且 ≤ 可用现金 × 5（IB 保证金上限）；本轮 `买入使用` ≤ `卖出释放` + 可用现金 × `invest_mult`；`invest_mult = 1` 时剩余现金 ≥ 总资产 × 5%（>1 时现金可为负）；每条 `初始资金` ≥ 个股目标资金 × 1.2；每策略目标资金 ≥ `base_capital`（最小开仓门槛），策略总数 ≤ 总预算 ÷ `base_capital`（硬顶 50）。任一不成立 → 按「新仓名额 → 单票目标 → 板块目标」顺序压缩至成立，并在「执行建议」中记录压缩过程

## 12. 常见失败陷阱

### 12.1 陷阱一：追涨杀跌

**表现**：看到板块大涨就追入，大跌就割肉。

**对策**：
- 只用相对强弱（RS）而非绝对涨幅做决策
- 设置确认条件：RS 曲线必须处于上行趋势
- 买入不追高（当日涨幅 > 3% 不买）

### 12.2 陷阱二：过度交易

**表现**：每天大规模调仓，换手率过高。

**对策**：
- 固定月度大再平衡 + 周度微调的双周期机制
- 单次调仓幅度限制（月度 ±10%，周度 ±3%）
- 计算交易成本，纳入决策

### 12.3 陷阱三：滞后指标陷阱

**表现**：等经济数据确认后才调仓，已经晚了。

**对策**：
- 使用领先指标（收益率曲线、信用利差）而非滞后指标（GDP）
- 关注价格信号（价格是最快的领先指标）
- 分批调仓，边确认边调整

### 12.4 陷阱四：过度集中

**表现**：重仓押注一两个板块。

**对策**：
- 硬性单板块上限 20%
- 前 3 大板块合计不超过 50%
- 定期检查集中度

### 12.5 陷阱五：忽视交易成本

**表现**：频繁换手导致交易成本侵蚀收益。

**对策**：
- 月度再平衡为主，减少非必要交易
- 大单拆分为小单执行
- 计算预期滑点，超过阈值则调整

### 12.6 陷阱六：对抗长期趋势

**表现**：在长期下行趋势的板块中反复抄底。

**对策**：
- 尊重长期趋势（200 日均线方向）
- 弱势板块连续 3 周 Bottom 3 必须清仓
- 不逆势加仓

### 13.4 vnpy_mcp 取数清单（只读，不使用 Redis）

> 本模块所需的量化系统数据**全部经 vnpy_mcp 实时查询**（前提：量化系统正在运行）；查询类工具无需用户名参数。
> **不使用任何 Redis 方面的工具**（Redis 状态板 / Redis HTTP 代理 / Redis 缓存）。
> 完整工具定义、参数与返回格式以 `get_guide` 及工具实际返回为准；本节只列本模块用得到的只读部分。

#### A. 分析报告

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `cta_report_list` | 列出全部分析报告目次（分析报告 + 策略分析记录） | 无 |
| `cta_report_get` | 取指定报告内容 | `report_kind`（分析任务名，如 `美股大盘与板块和资金流向分析`、`美股做多选股结果`、`美股做空选股结果`）、`strategy_name`（查策略分析记录）、`report_index`（默认 -1 取最新） |

> 调仓前先取三份报告：大盘报告作宏观输入（见 §3），`美股做多选股结果` / `美股做空选股结果` 用于轮动预测交叉印证（见 §3.5 / §6）；任何一份取不到则按缺失处理并记入「数据缺失与冲突」。

#### B. 账户与持仓

| 工具 | 用途 |
|------|------|
| `get_accounts` | 账户余额：`accountid`（可能带币种标识）、`gateway_name`、`balance`（总资产，含持仓占用与可用现金，**不能加持仓市值**）、`frozen`、`available` —— 板块/个股仓位百分比的分母；**IB 多币种账户须取 USD 币种条目或换算为美元**（见 §7.3.1.1 币种规则） |
| `get_positions` | 账户级持仓：品种、数量、成本价、盈亏 |

#### C. 策略

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `cta_strategies_get_all` | 全部策略概况（中文键名）：策略名称、策略类型、vt_symbol、实际持仓、持仓目标、持仓均价、当前行情价格、当前持仓盈亏比、可用资金总量、已使用资金占比、网格已用/最大、操作方向、自动开仓、止盈、止损、移动止盈、网格间距、亏损加仓、运行状态、品种信息（ticker / conid / 分类 / 行业） | 无 |
| `cta_strategy_get_status` | 单策略完整状态：vt_symbol、策略类型、实际持仓、持仓目标、持仓均价、历史累计盈亏、当前持仓盈亏比、当前行情价格、已使用资金占比、已有网格仓数量、持仓交易历史、策略基础参数设置和当前变量、`is_trading`、品种信息 | `strategy_name` |
| `cta_strategy_get_all_reason` | 持仓决策上下文：开仓 AI 理由、最近一次 AI 理由、本次持仓交易历史、各参数最近一次修改与 reason | `strategy_name` |
| `cta_strategy_get_trade_history` | 策略完整交易历史（读本地 `.trades_txt`，含全部轮次与已平仓） | `strategy_name`、`limit`（不传=全部） |
| `cta_strategy_get_parameters_info` | 关键参数说明（名称 / 类型 / 当前值 / 描述） | `strategy_name` |
| `cta_strategy_get_classes` | 可用 CTA 策略类列表（「新增策略」时选 class_name） | 无 |
| `cta_strategy_get_class_parameters` | 指定策略类的初始化必填参数 | `class_name` |

> **策略级资金**：`cta_strategies_get_all` 的每策略 `可用资金总量 / 已使用资金占比` 是报告「资金现状」块的数据源，**必须写入报告**（仅本次调仓涉及的策略，见 §7.3.1.1）；已有策略加仓时必须与 `资金调整` 指令互相核对（可用空间 < 缺口 → 附增资金额）。

#### D. 成交与委托

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `get_trades` | 系统本次启动后的成交记录 | `limit`（默认 50） |
| `get_active_orders` | 活动委托（未成交或部分成交） | 无 |

#### E. 行情与合约

| 工具 | 用途 | 关键参数 |
|------|------|---------|
| `get_tick` | 指定合约最新 Tick 行情 | `vt_symbol` |
| `get_history_bars` | 历史 K 线。**推荐直接传 `vt_symbol`** 由服务端解析；或传 `symbol` + `exchange` + `gateway_name`（须取自 `get_contract` / `get_all_contracts`，**严禁自行猜测**） | `vt_symbol` / `symbol`、`exchange`、`gateway_name`、`interval`（默认 1m）、`start`、`end` |
| `get_contract` | 指定合约信息 | `vt_symbol` |
| `get_all_contracts` | 全部合约 | 无 |
| `search_vt_symbol` | 搜索 vt_symbol / 查 ConID | `query`（ticker / 名称 / conid）、`market`（`IB` 时实时向网关查询以确保 conid 最新） |
| `subscribe_contract` | 订阅合约 Tick 行情（策略创建时自动订阅，通常无需手动调用；仅用于提前看行情或未被策略使用的合约） | `vt_symbol`、`gateway_name` |

> **vt_symbol 纪律**：IB 合约必须使用 `search_vt_symbol` 返回的形式（如 `265598.SMART`），**严禁 `ticker.SMART` 自行拼接**；币安 U 本位为 `SYMBOL_SWAP_BINANCE.GLOBAL`。
> **板块 ETF / 宏观行情不在 vnpy_mcp 内**：用 `scripts/get_market_data.py`（用法见 13.1 与 README §5）。

#### F. 系统状态

| 工具 | 用途 |
|------|------|
| `get_gateways` | 已注册网关及连通状态（名称、是否连通、支持的交易所、已订阅合约数、账户数）—— 判断数据源是否可用 |
| `ping` | 健康检查（返回 `pong`） |
| `get_guide` | vnpy_mcp 工具集完整指南（工具分类、调用格式、返回示例、核心业务流程） |

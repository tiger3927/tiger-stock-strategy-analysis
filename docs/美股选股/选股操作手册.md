# 美股候选股池定义

> **文档定位**：本文档是美股选股模块（**做多/做空通用**）的**候选股池生成操作手册**，定义候选池的生成方式（板块衍生、全网扫描、用户指定）、筛选规则与质量控制，而非固定列表。AI 执行选股流程时，由 [00_index.md](00_index.md) Step 2 引用本文档获取候选池，按本文档规则**动态生成**；做空方向按 Step 2 的做空适配调整搜索词。
>
> **⚠️ 代码化执行（2026-09-26 修订）**：候选池生成与池外探测的量化规则已固化为代码，**必须先执行 `scripts/generate_candidate_pool.py`**（入口清单唯一权威 = `scripts/pool_entries.json`）。AI 的职责：确定 `--direction` / `--sector` 参数 → 执行脚本 → 读取输出 JSON → 做**定性判断**（负面新闻排除、命中标准最终判定、新板块归类）→ 把 `统计`/`审计`/`排除` 字段抄录进报告 `候选池摘要`。**本文档中的阈值数字仅为说明，唯一权威是脚本常量（修改阈值须两处同步）。**
>
> **⚠️ 脚本失败时的降级纪律**：只允许"固定池兜底 + 留痕"（`--mode seed --no-network`），**禁止 AI 按旧流程手工 web_fetch 扫描网页生成候选池、自造入口、手工计算差集/截断**（教训：2026-09-25 两期做空报告因手工扫描导致池子组成随机——78 只未截断、单次并入 24、自造"当日大涨榜"入口）。
>
> **核心原则**：候选池是筛选出来的，不是预设出来的。固定列表会限制视野，错过小盘股和新兴机会。
>
> **⚠️ 取数与发现纪律（2026-09-13 修订）**：本环境 `web_search` **只返回标题与链接、不返回正文** → 本文档所有"搜索候选股"的动作，一律改为 **`web_fetch` 直取页面**（筛选页 / 指数成分页 / ETF holdings 页）或 `get_market_data.py`；`web_search` 仅用于发现 URL。
>
> **⚠️ 每次生成候选池都必须执行 §七「池外探测」**：固定池 `scripts/stock_pool.json` 只是**种子兜底**，不是视野边界。

## 一、候选池生成方式（按优先级）

AI 按以下优先级依次尝试生成候选池。**该优先级链由脚本 `--mode auto` 硬执行**："候选数不足"已硬定义为 **< 15 只**（脚本常量 `ACCEPT_MIN`）；AI 只负责确定 `--sector` 参数，不手工挑选方式。

| 优先级 | 方式 | 适用场景 | 预期候选数 |
|--------|------|---------|-----------|
| **1** | 板块衍生 + 基本面筛选 | 大盘分析已识别出明确主线板块 | 15-30 |
| **2** | 全网基本面扫描 | 无明确板块主线，或用户要求全市场 | 20-40 |
| **3** | 用户指定 ticker 列表 | 用户已有自己的观察列表 | 按用户提供 |
| **兜底** | **固定池过滤**（`scripts/stock_pool.json`） | **搜索 / 取数失败时降级使用**，或需要与调仓池保持一致（不依赖网络） | 20-40 |

> 无论走哪一档，**都必须补齐 §七 池外探测**：池子是"起点"，不是"边界"。

## 二、方式一：板块衍生 + 基本面筛选

### 2.1 确定目标板块

从大盘分析报告的 `板块轮动.主线板块` 字段获取当前主线板块。如果用户指定了板块偏好，优先使用用户指定的板块。

**板块 → 检索关键词映射表**（关键词用于筛选页条件或作为 `web_search` 入口线索；**取数必须 `web_fetch` 直取页面**）：

| 板块 | 检索关键词 |
|------|------------------------------------------|
| AI / 科技 | `"AI software stocks PEG under 1.5 revenue growth 2026"` |
| 半导体 | `"semiconductor stocks undervalued PEG under 1.5 2026"` |
| 金融 | `"financial stocks low P/E ratio strong earnings growth 2026"` |
| 能源 | `"energy stocks undervalued free cash flow yield 2026"` |
| 医疗 | `"healthcare stocks GARP growth at reasonable price 2026"` |
| 消费（必需） | `"consumer staples stocks undervalued defensive 2026"` |
| 消费（可选） | `"consumer discretionary stocks growth value 2026"` |
| 工业 | `"industrial stocks strong balance sheet growth 2026"` |
| 通信服务 | `"communication services stocks undervalued 2026"` |
| 公用事业 | `"utility stocks dividend growth reasonable valuation 2026"` |
| 房地产 | `"REIT stocks undervalued 2026"` |

### 2.2 搜索候选股（由脚本执行）

入口抓取由脚本完成，AI **不得使用 `pool_entries.json` 清单外的入口**（教训：2026-09-25 AI 自造"当日大涨榜"入口导致池子组成随机）：

```bash
python scripts/generate_candidate_pool.py --mode auto --direction <long|short> --sector "<手册板块名>" --output json
# 脚本内部顺序（对应 pool_entries.json，AI 不感知细节）：
# ① 板块 ETF holdings（sector_etfs 固定映射，如 半导体 → SMH/SOXX）
# ② 板块核心+卫星种子表保底（sector_seed，§2.3）
# ③ 不足 15 只 → 自动降级方式二（scan_entries 固定清单）
# ④ 仍不足 → 固定池 stock_pool.json 兜底（全程留痕）
```

**AI 对脚本输出的处理规则**：
- 读取输出 JSON 的 `候选池` / `排除` / `统计` / `审计` 字段
- §5.4 的可计算项（股价 < $3 / 日均成交量 < 20 万股）已由脚本硬排除；AI 补充**定性排除**：近 30 日重大负面 / 近 90 日退市警告
- 目标 15-30 只由脚本数量控制保障，AI 不手工增删

### 2.3 板块核心+卫星种子表（已迁入配置）

种子表唯一权威：`scripts/pool_entries.json` 的 `sector_seed` 字段（11 个手册板块 × 核心/卫星两档），脚本方式一保底自动引用（core + satellite 各取前 5）。本手册不再维护副本；增删种子直接改 JSON（由「美股选股池维护」任务或 AI 经确认后修改）。

### 2.4 小盘股检查（由脚本自动执行）

小盘（市值 $1B - $10B）占比 ≥ 20% 的检查与补充由脚本 `supplement_small_cap` 自动完成（不足时自动从小盘入口补充并留痕）。AI 只需检查输出 JSON 的 `统计.small_cap_insufficient`：为 `true` 时说明当前市场小盘标的稀缺，在报告 `数据缺失与冲突` 中如实标注即可。

## 三、方式二：全网基本面扫描

当无明确板块主线或用户要求全市场扫描时，使用此方式。

### 3.1 按市值分层取数（由脚本执行）

分层入口由 `pool_entries.json` 的 `scan_entries`（S&P 500 / Nasdaq 100 / SPY / MDY / IWM holdings）与 `small_cap_entries`（small-cap 列表 / IWM）固定提供，脚本按顺序抓取、失败自动降级并留痕。

分层口径（脚本 `bucket_of` 实现）：大盘 > $200B；中盘 $10B-$200B；小盘 $1B-$10B（小盘占比须 ≥ 20%）。

### 3.2 按策略维度筛选（供 AI 在 00_index Step 4 基本面过滤使用）

入口抓取由脚本完成，以下条件不再用于 AI 自选筛选页，而是 AI 对脚本候选池做基本面过滤时的判定标准：

```text
# 价值+成长混合（GARP）
筛选条件：PEG < 1.5、营收增速 > 10%、ROE > 10%
# 价值型
筛选条件：P/E 低于行业中位数、负债率低、FCF 收益率为正
# 成长型
筛选条件：营收 / EPS 增速 > 20%、估值未极端
# 动量型
筛选条件：价格在 MA50 上方、近 20 日相对 SPY 超额 > 5%
```

### 3.3 搜索结果合并（由脚本执行）

去重、§5.4 硬排除、数量控制（20-40 只，>40 按市值截断）、小盘占比 ≥20% 补充——全部由脚本自动完成并留痕；AI 只处理其定性部分（见 §2.2 处理规则）。

## 四、方式三：用户指定列表

如果用户直接提供了 ticker 列表，直接使用。但仍需按以下规则校验：

| 校验项 | 规则 |
|--------|------|
| 流动性 | 近 20 日日均成交量 ≥ 20 万股 |
| 股价 | ≥ $3 |
| 负面排除 | 近 30 日无重大负面新闻 |

不符合条件的标的从候选池中移除，并告知用户原因。

## 五、候选池质量控制

### 5.1 数量控制（脚本 `enforce_max_pool` 硬执行：<10 补充、>40 按市值截断至 40）

| 候选池大小 | 处理方式 |
|-----------|---------|
| < 10 只 | 补充搜索，直到 ≥ 10 只 |
| 10-40 只 | 正常进入下一轮筛选 |
| > 40 只 | 按市值从大到小截断至 40 只 |

### 5.2 多样性控制（脚本 `supplement_diversity` 硬执行：板块 <3 自动从固定池补充）

候选池应覆盖至少 **3 个不同板块**，避免过度集中于单一板块。如果搜索结果集中在 1-2 个板块，补充搜索其他板块。

### 5.3 小盘股保障（脚本 `supplement_small_cap` 硬执行：占比 <20% 自动补充，仍不足标记 `small_cap_insufficient`）

**小盘股（市值 $1B - $10B）在候选池中占比不低于 20%**。占比不足时由脚本自动从 `pool_entries.json` 的 `small_cap_entries`（small-cap 列表 / IWM holdings）补充，来源耗尽仍不足时输出 `small_cap_insufficient`，AI 在报告 `数据缺失与冲突` 中如实标注。

### 5.4 排除规则（可计算项由脚本 `apply_exclusion_rules` 硬执行）

- 股价 < $3（脚本硬排除）
- 近 30 日有重大负面新闻（SEC 调查、财务造假、CEO 被捕等）——**AI 定性排除**
- 近 90 日内被退市警告——**AI 定性排除**
- 日均成交量 < 20 万股（流动性太差）（脚本硬排除）

## 六、候选池生成流程总结

```text
用户请求选股
    │
    ├─ 用户提供了 ticker 列表？──→ --mode user（脚本做 §5.4 硬校验，AI 做定性校验）
    │
    └─ 需要 AI 筛选？
         │
         ├─ AI 确定板块方向（Step 1.5 预测 / 大盘主线 / 用户偏好）→ --sector 参数
         │        ↓
         ├─ 执行 generate_candidate_pool.py --mode auto --direction --sector
         │        │
         │        ├─ 内部自动执行：§一 优先级链（板块衍生→全网扫描→固定池兜底）
         │        │   + §五 质量控制（截断/小盘/多样性/排除，全程留痕）
         │        ↓
         └─ AI 读取输出 JSON：定性排除 + 新板块归类 → 抄录 统计/审计 进报告
                                  （small_cap_insufficient 为 true 时如实标注）
```

## 七、池外探测（每次生成候选池必做）

> **为什么必须有**：候选池若只从"搜索结果 + 固定池种子"里取，会形成自我封闭——池外的当期新机会（新上市、市值跃升、新叙事）永远进不来。**池子是起点，不是边界。**

**触发**：每次生成候选池都执行（不受"搜索是否成功"影响）。与 `docs/调仓/美股/美股选股池管理.md` §6.4 是**同一动作的两个使用面**：那边维护调仓池（落盘），这边服务选股候选池（不落盘）。

**执行（一条命令，AI 不手工算差集、不手工挑入口）**：

```bash
# 传入当前候选池（上次 generate 输出保存的 JSON 文件）：
# 脚本自动完成：固定入口清单取当期全市场清单（网络层自动走 10808 代理，失败降级留痕）
# → 差集（扣除固定池重复标的）→ 指标验证与 §5.4 硬排除 → 并入（单次上限 10，超出留痕"未并入原因"）
python scripts/generate_candidate_pool.py --probe-only <当前候选池.json> --output json
```

**AI 的两件事**：

1. 传参：提供当前候选池来源（上次 generate 输出，或用户指定列表）
2. 对差集候选做**定性判定**（脚本已给指标预检，最终判定留 AI）：
   - 做多：GARP 标准（PEG < 1.5、营收增速 > 10%、ROE > 10%、FCF 收益率 > 4%）
   - 做空：估值泡沫 + 基本面恶化标准（见 00_index.md Step 4 做空口径）
   - 命中 → 并入（按板块归类，标注来源「池外探测」）；归不进任何板块 → 记入 `核心冲突`/`风险提示`（新板块候选）
   - 脚本标 `data_missing` 的标的 → 定性判定时注明，**不得凭印象入池**

**留痕**：脚本输出的 `入口数` / `入口尝试` / `差集候选数` / `并入` / `未并入`（含原因）/ `排除` / `与固定池重复` 原样写入报告 `候选池摘要.池外探测`，AI 不得手填数字。

**与固定池的关系**：

| | 固定池 `stock_pool.json` | 池外探测 |
|---|---|---|
| 角色 | 种子兜底（离线可用、维护成本低） | 边界对齐（每次必做，覆盖当期新标的） |
| 维护 | 由「美股选股池维护」任务按 `美股选股池管理.md` §6.4 更新 | 每次选股即时执行，不落盘 |
| 数据源 | `scripts/stock_pool.json` | 指数成分 / ETF holdings / 筛选页 |

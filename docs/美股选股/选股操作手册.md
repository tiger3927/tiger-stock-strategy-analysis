# 美股候选股池定义

> **文档定位**：本文档是美股选股模块（**做多/做空通用**）的**候选股池生成操作手册**，定义候选池的生成方式（板块衍生、全网扫描、用户指定）、筛选规则与质量控制，而非固定列表。AI 执行选股流程时，由 [00_index.md](00_index.md) Step 2 引用本文档获取候选池，按本文档规则**动态生成**；做空方向按 Step 2 的做空适配调整搜索词。
>
> **核心原则**：候选池是筛选出来的，不是预设出来的。固定列表会限制视野，错过小盘股和新兴机会。
>
> **⚠️ 取数与发现纪律（2026-09-13 修订）**：本环境 `web_search` **只返回标题与链接、不返回正文** → 本文档所有"搜索候选股"的动作，一律改为 **`web_fetch` 直取页面**（筛选页 / 指数成分页 / ETF holdings 页）或 `get_market_data.py`；`web_search` 仅用于发现 URL。
>
> **⚠️ 每次生成候选池都必须执行 §七「池外探测」**：固定池 `scripts/stock_pool.json` 只是**种子兜底**，不是视野边界。

---

## 一、候选池生成方式（按优先级）

AI 按以下优先级依次尝试生成候选池，**前一种方式生成的候选数不足时，才使用下一种**。

| 优先级 | 方式 | 适用场景 | 预期候选数 |
|--------|------|---------|-----------|
| **1** | 板块衍生 + 基本面筛选 | 大盘分析已识别出明确主线板块 | 15-30 |
| **2** | 全网基本面扫描 | 无明确板块主线，或用户要求全市场 | 20-40 |
| **3** | 用户指定 ticker 列表 | 用户已有自己的观察列表 | 按用户提供 |
| **兜底** | **固定池过滤**（`scripts/stock_pool.json`） | **搜索 / 取数失败时降级使用**，或需要与调仓池保持一致（不依赖网络） | 20-40 |

> 无论走哪一档，**都必须补齐 §七 池外探测**：池子是"起点"，不是"边界"。

## 二、方式一：板块衍生 + 基本面筛选

### 2.1 确定目标板块

从大盘分析报告的 `板块轮动.主线板块` 字段获取当前主线板块。如果用户指定了板块偏好，优先使用用户指定的板块。

**板块 → 检索关键词映射表**（关键词用于筛选页条件或作为 `web_search` 入口线索；**取数必须 `web_fetch` 直取页面**）：

| 板块 | 检索关键词 |
|------|------------------------------------------|
| AI / 科技 | `"AI software stocks PEG under 1.5 revenue growth 2026"` |
| 半导体 | `"semiconductor stocks undervalued PEG under 1.5 2026"` |
| 金融 | `"financial stocks low P/E ratio strong earnings growth 2026"` |
| 能源 | `"energy stocks undervalued free cash flow yield 2026"` |
| 医疗 | `"healthcare stocks GARP growth at reasonable price 2026"` |
| 消费（必需） | `"consumer staples stocks undervalued defensive 2026"` |
| 消费（可选） | `"consumer discretionary stocks growth value 2026"` |
| 工业 | `"industrial stocks strong balance sheet growth 2026"` |
| 通信服务 | `"communication services stocks undervalued 2026"` |
| 公用事业 | `"utility stocks dividend growth reasonable valuation 2026"` |
| 房地产 | `"REIT stocks undervalued 2026"` |

### 2.2 搜索候选股

```bash
# 示例：主线板块为 AI/科技/金融
# ① 首选：web_fetch 直取筛选页（stockanalysis.com / finviz / Yahoo Screener，按板块 + 市值 + PEG 排序）
# ② 备选：web_fetch 对应板块 ETF holdings 页（如 XLK / SMH / XLF，含 ticker 与权重）
# ③ 兜底：读 scripts/stock_pool.json 中该板块的 tier 列表（§七 固定池兜底）
# ④ web_search 仅作入口线索（本环境只返回标题与链接、无正文）
```

**搜索结果处理规则**：
- 从搜索结果中提取 ticker 和简要基本面数据
- 去重，并按 §5.4 排除规则过滤（股价 < $3 / 近 30 日重大负面 / 近 90 日退市警告 / 日均成交量 < 20 万股）——**不依赖外部"排除列表"文件，技能内不存在该文件**
- 保留 15-30 只作为候选池

### 2.3 板块核心+卫星种子表

如果搜索结果不足 15 只，从以下**板块核心+卫星种子表**中补充。此表不是固定候选列表，而是**搜索失败时的保底种子**。

每个板块分为两档：
- **核心**（Core）：大市值龙头，板块风向标，流动性好
- **卫星**（Satellite）：中小市值优质标的，弹性更大，结构化行情中可能跑赢龙头

AI 从目标板块中取 **核心 + 卫星各选 3-5 只** 补充到候选池。

| 板块 | 核心（Core，大市值龙头） | 卫星（Satellite，中小市值弹性标的） |
|------|------------------------|----------------------------------|
| AI / 科技 | NVDA, MSFT, META, GOOG, AMZN | CRM, ORCL, NOW, DDOG, MDB, SNAP, RDDT |
| 半导体 | NVDA, AVGO, TSM, AMD | MU, MRVL, CRDO, ON, WOLF, ARM, MTSI |
| 金融 | JPM, GS, BAC, MS, SCHW | C, MET, PRU, KEY, FITB, HBAN, SYF |
| 能源 | CVX, COP, PSX, EOG | OXY, FANG, CTRA, MRO, CHK, AR, PR |
| 医疗 | UNH, DHR, TMO, ISRG, ZTS | CNC, ZBH, DXCM, PODD, MEDP, EXAS, ALNY |
| 消费（必需） | COST, WMT, DEO, STZ | CLX, CPB, TSCO, CAG, K, SJM, CELH |
| 消费（可选） | AMZN, NKE, SBUX, TJX | DECK, YUMC, LULU, DKS, AEO, BOOT, ONON |
| 工业 | CAT, HON, GE, RTX | FAST, CTAS, GFF, EMR, ROK, IR, ETN |
| 通信服务 | META, GOOG, DIS, CMCSA | T, VZ, ROKU, SNAP, WBD, NYT, IAC |
| 公用事业 | NEE, DUK, SO, AEP | EXC, XLU, PEG, ES, ETR, LNT, AEE |
| 房地产 | PLD, AMT, EQIX, WELL | O, DLR, AVB, EQR, INVH, MAA, CUBE |

### 2.4 方式一完成后必须执行：小盘股检查

> **⚠️ 强制步骤：方式一生成的候选池以中大市值为主，AI 必须执行以下检查，不得跳过。**

1. 统计候选池中**小盘股（市值 $1B - $10B）的数量和占比**
2. 如果小盘股占比 **< 20%**，立即执行【五、候选池质量控制 5.3 小盘股保障】中的补充搜索
3. 补充搜索的结果合并到候选池后，**再次检查小盘占比**，直到满足 ≥ 20%
4. 如果多次补充搜索后仍无法满足（说明当前市场小盘GARP标的稀缺），在输出中标注 `small_cap_insufficient`

> 小盘股补充搜索的具体命令见 5.3 节，不要自己编造搜索词。

## 三、方式二：全网基本面扫描

当无明确板块主线或用户要求全市场扫描时，使用此方式。

### 3.1 按市值分层取数（大 / 中 / 小盘全覆盖）

**同时覆盖大、中、小盘三个层次**，确保不遗漏小盘股。入口（`web_fetch` 直取，关键词仅作筛选条件）：

```bash
# ① 首选：筛选页（可自定义市值 / PE / 增速条件）
web_fetch：stockanalysis.com/stocks/screener、finviz.com/screener.ashx、Yahoo Screener
# ② 指数成分页（分层最省事）
web_fetch：S&P 500（大盘）/ S&P MidCap 400（中盘）/ Russell 2000（小盘）成分页
# ③ ETF holdings（含 ticker 与权重）
web_fetch：SPY / QQQ（大盘）、MDY（中盘）、IWM（小盘）的 holdings 页
# ④ 兜底：scripts/stock_pool.json 的 T1/T2/T3（调仓池按分层筛选，见 §七）
# ⑤ web_search 仅作入口线索（本环境只返回标题与链接、无正文）
```

分层口径：大盘 > $200B；中盘 $10B-$200B；小盘 $1B-$10B（小盘占比须 ≥ 20%）。

### 3.2 按策略维度筛选

根据用户指定的风格，在筛选页上设置条件（或作为 `web_search` 入口线索）：

```text
# 价值+成长混合（GARP）
筛选条件：PEG < 1.5、营收增速 > 10%、ROE > 10%
# 价值型
筛选条件：P/E 低于行业中位数、负债率低、FCF 收益率为正
# 成长型
筛选条件：营收 / EPS 增速 > 20%、估值未极端
# 动量型
筛选条件：价格在 MA50 上方、近 20 日相对 SPY 超额 > 5%
```

### 3.3 搜索结果合并

- 合并所有搜索结果，去重
- 按 §5.4 排除规则过滤（不依赖外部列表文件）
- 保留 20-40 只作为候选池
- **确保小盘股占比不低于 20%**（如果搜索结果中小盘股不足，补充搜索）

## 四、方式三：用户指定列表

如果用户直接提供了 ticker 列表，直接使用。但仍需按以下规则校验：

| 校验项 | 规则 |
|--------|------|
| 流动性 | 近 20 日日均成交量 ≥ 20 万股 |
| 股价 | ≥ $3 |
| 负面排除 | 近 30 日无重大负面新闻 |

不符合条件的标的从候选池中移除，并告知用户原因。

## 五、候选池质量控制

### 5.1 数量控制

| 候选池大小 | 处理方式 |
|-----------|---------|
| < 10 只 | 补充搜索，直到 ≥ 10 只 |
| 10-40 只 | 正常进入下一轮筛选 |
| > 40 只 | 按市值从大到小截断至 40 只 |

### 5.2 多样性控制

候选池应覆盖至少 **3 个不同板块**，避免过度集中于单一板块。如果搜索结果集中在 1-2 个板块，补充搜索其他板块。

### 5.3 小盘股保障

**小盘股（市值 $1B - $10B）在候选池中占比不低于 20%**。如果候选池中小盘股不足，用以下入口补充：

```bash
# ① web_fetch 筛选页：市值 $1B-$10B + PEG < 1.5 + 营收增速 > 10%
web_fetch：stockanalysis.com/stocks/screener、finviz.com/screener.ashx（小盘股口径）
# ② web_fetch 指数成分：Russell 2000 成分页 / IWM holdings 页
# ③ 兜底：scripts/stock_pool.json 的 T3（潜力小盘）列表，按目标板块过滤
# ④ web_search 仅作入口线索（本环境只返回标题与链接、无正文）
```

### 5.4 排除规则

以下标的自动排除：

- 股价 < $3
- 近 30 日有重大负面新闻（SEC 调查、财务造假、CEO 被捕等）
- 近 90 日内被退市警告
- 日均成交量 < 20 万股（流动性太差）

## 六、候选池生成流程总结

```text
用户请求选股
    │
    ├─ 用户提供了 ticker 列表？──→ 方式三：直接使用 + 校验
    │
    └─ 需要 AI 筛选？
         │
         ├─ 大盘分析有明确主线板块？──→ 方式一：板块搜索 + 核心+卫星保底
         │                                │
         │                                └─ 小盘股占比 < 20%？──→ 是 → 执行 5.3 小盘补充搜索
         │                                        │                      │
         │                                        └─ 否                  └─ 再次检查，直到 ≥ 20%
         │                                                                    │
         │                                                                    ↓
         │                                                              仍不足 → 标注 small_cap_insufficient
         │
         └─ 无明确主线或全市场扫描？──→ 方式二：分层搜索（大/中/小盘）
                                              │
                                              └─ 小盘股占比 < 20%？→ 补充小盘搜索
                                                      │
                                                      ↓
                                              合并去重 → 数量/多样性检查 → 输出候选池
```

## 七、池外探测（每次生成候选池必做）

> **为什么必须有**：候选池若只从"搜索结果 + 固定池种子"里取，会形成自我封闭——池外的当期新机会（新上市、市值跃升、新叙事）永远进不来。**池子是起点，不是边界。**

**触发**：每次生成候选池都执行（不受"搜索是否成功"影响）。与 `docs/调仓/美股/美股选股池管理.md` §6.4 是**同一动作的两个使用面**：那边维护调仓池（落盘），这边服务选股候选池（不落盘）。

```text
Step 1: 取当期全市场清单（web_fetch 直取）
  ① 指数成分：S&P 500 / S&P MidCap 400 / Russell 1000 / Russell 2000
  ② ETF holdings：SPY / QQQ / MDY / IWM，以及目标板块 ETF（XLK / SMH / XLF / XLV / XLE …）
  ③ 筛选页：stockanalysis.com、finviz、Yahoo Screener（按市值 / 成交额 / 增速排序）
  ④ 种子兜底：读 scripts/stock_pool.json（调仓池，31 个 GICS 子板块 / T1·T2·T3；池子可能会更新和增减，以文件最新版本为准）

Step 2: 与当前候选池做差集
  - 差集 = 上述清单 ticker − 候选池已有 ticker − §5.4 排除规则过滤掉的标的
  - 注：排除项一律按 §5.4 判定，**不依赖外部"排除列表"文件**（技能内不存在该文件）

Step 3: 逐个判定（按本模块标准）
  - 做多：GARP 标准（PEG < 1.5、营收增速 > 10%、ROE > 10%、FCF 收益率 > 4%）
  - 做空：估值泡沫 + 基本面恶化标准（见 00_index.md Step 4 做空口径）
  - 用 python scripts/get_market_data.py --market us_stocks --tickers <候选列表> --output json 验证：
    market_cap / price / avg_volume / pe_ratio / pb_ratio / roe / revenue_growth / sector / industry

Step 4: 归类与合流
  - 命中标准 → 并入候选池（按板块归类，标注来源「池外探测」）
  - 归不进当前任何板块 → 记入「新板块候选」，并在输出的 `核心冲突` 或 `风险提示` 中说明
  - 与固定池 `stock_pool.json` 重复的标的 → 标注来源「固定池」，不重复计数

Step 5: 留痕
  - `候选池摘要` 中记录：池外探测入口数 / 差集候选数 / 并入数 / 未通过原因
```

**取数纪律（本环境强制）**：

- 所有"发现 / 取榜单"动作必须 `web_fetch` 直取页面或 `get_market_data.py`；`web_search` 仅用于发现 URL（只返回标题与链接、无正文）
- 取不到数据的标的 → 记入输出的 `数据缺失与冲突`（含原因），**不得静默丢弃，也不得凭印象入池**

**规模约束**：

- 池外并入后，候选池总量仍受 §5.1 控制（20-40 只；> 40 按市值截断）
- 小盘股占比仍需 ≥ 20%（§5.3）；若并入的全是大盘，需同步补小盘
- 单次并入建议 ≤ 10 只，避免候选池被"新鲜度"主导

**与固定池的关系**：

| | 固定池 `stock_pool.json` | 池外探测 |
|---|---|---|
| 角色 | 种子兜底（离线可用、维护成本低） | 边界对齐（每次必做，覆盖当期新标的） |
| 维护 | 由「美股选股池维护」任务按 `美股选股池管理.md` §6.4 更新 | 每次选股即时执行，不落盘 |
| 数据源 | `scripts/stock_pool.json` | 指数成分 / ETF holdings / 筛选页 |

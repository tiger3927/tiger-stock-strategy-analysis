# 加密货币选币模块（AI 智能体作业指导书）

> **文档定位**：本文档是 `tiger-stock-strategy-analysis` 技能的子模块。当用户请求加密货币选币（做多或做空）机会分析时，本技能会加载此文档作为 AI 的执行指令。AI 应根据用户指定的 `direction` 参数选择做多或做空分支，严格按本文档的流程逐步执行，最终输出结构化 JSON 结果。
>
> **⚠️ 输出格式铁律**：最终输出必须是【六、输出模板】规定的 JSON 格式。分析过程中的中间结论是用于填入 JSON 字段的，**不得直接输出给用户**。用户只看到最终 JSON 结果。

---

## 一、模块目标

根据用户指定的方向（`direction`），加载对应的选币逻辑文档：

- **做多方向**：参照 [加密货币做多选择.md](加密货币做多选择.md)，结合当前大盘环境（BTC.D / ETH-BTC / 板块轮动），**预测下一个轮入板块**，从选币池中筛选出「叙事成长」型做多标的，输出评分卡和入场计划。
- **做空方向**：参照 [加密货币做空选择.md](加密货币做空选择.md)，结合当前大盘环境，在**板块过热、解锁抛压、叙事衰竭**的标的中筛选做空标的，输出评分卡和入场计划（含**轧空风险评估**与**做空成本核算**）。

回答五个核心问题：

```text
1. 当前大盘环境是否适合交易？  →  复用加密大盘分析报告（缺失时降级为价格结构闸门）
2. 下一个可能轮入/流出的板块是什么？ →  板块轮动预测
3. 哪些标的值得关注？          →  选币池筛选（含可交易性校验）
4. 每个标的的评分和入场计划？  →  评分卡打分
5. 风险在哪里？               →  风险提示（含轧空/解锁/流动性）
```

**与美股选股模块的本质差异（务必先读）**：

| 维度 | 美股 | 加密货币 |
|------|------|---------|
| "基本面" | PE/PB/ROE/营收/管理层/护城河 | **代币经济学**（通胀率·解锁曲线·销毁）+ **协议基本面**（TVL·收入·活跃地址·质押率）+ 叙事强度 |
| 板块体系 | GICS 29 个子板块 | L1 / L2 / DeFi / Meme / AI / 基础设施 / RWA / GameFi / 交易所平台币 / 隐私支付 / DePIN模块化 |
| 做空机制 | 借券做空（借券成本 + up-tick 限制） | **永续合约原生做空**：成本 = 资金费率；风险 = **轧空**、深度不足、下币 |
| 交易时段 | 6.5 小时/日 + 休市 | 7×24（受美股时段牵引，见加密大盘文档 Step 1 第 4 点） |
| 波动量级 | 日均 1-2% | **3-8%+** → 止损/仓位/门槛整体放大 |
| 事件驱动 | 财报、SEC | **解锁（最确定）**、上/下币公告、SEC 裁决、升级/硬分叉、空投 |
| 可交易性 | vt_symbol_info.json / IB 合约 | **必须与 `get_all_contracts` 求交集**——系统里没有的币不能选 |
| 数据源 | us-all + ICI + web-indicators | crypto-all + us-all（跨市场）+ calendar + CoinGecko API / web_fetch；**无 ICI、无 web-indicators** |

## 二、执行流程（AI 请严格按此顺序执行）

### Step 0：获取用户输入

在执行任何数据获取前，必须先与用户确认以下参数。如果用户已在上一次对话中提供，直接引用，无需重复询问。

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `direction` | **做多** / **做空** | 做多 |
| `time_frame` | 短线(1-10 个交易日) / 中线(2-6 周) / 中长线(2-6 个月) | 短线 |
| `style` | 叙事成长型 / 板块轮动型 / 动量型 / 混合 | 叙事成长型 |
| `risk_tolerance` | 保守 / 中等 / 激进 | 中等 |
| `category_preference` | 指定板块（L1/DeFi/Meme/基础设施/…）或"全市场" | 全市场 |
| `max_candidates` | 最终输出标的数上限 | 3 |

> **`direction` 路由规则**：
> - `direction = 做多` → 执行【做多方向】分支，参照 [加密货币做多选择.md](加密货币做多选择.md)
> - `direction = 做空` → 执行【做空方向】分支，参照 [加密货币做空选择.md](加密货币做空选择.md)
> - 用户未明确指定但含"做空/short/看跌/做空山寨/对冲"等语义 → 自动路由到做空分支

### Step 1：获取大盘环境（含降级规则）

**不重新分析大盘**，优先复用已有的大盘分析报告，通过 vnpy_mcp 的 `cta_report_get` 读取：

```
cta_report_get(report_kind="加密货币大盘与板块和资金流向分析")
```

- **报告存在** → 解析并提取：`分析摘要`（direction / 风险观察分）、`板块轮动`（主线板块 / 流出板块 / 轮动阶段 / BTC_D / ETH_BTC汇率）、`风险提示`、`宏观联动`（VIX / HYG_LQD比值 / 与纳斯达克30日相关性）
- **报告不存在或已过期（> 3 日）** → **不执行大盘分析任务、不等待**，改用**价格结构降级闸门**（见下），并在输出的 `gate.source` 中标注 `price_structure_fallback`

#### 价格结构降级闸门（无大盘报告时使用）

数据来源：`crypto-all` 批次（BTC-USD / ETH-USD 的 52 周分位、均线）+ `web_fetch` 直取的 BTC.D / TOTAL2（各 1 次；本环境 web_search 无正文）。

| 闸门判定 | 条件（满足 2 条） | 对选币的影响 |
|---------|------------------|-------------|
| 风险偏好正常 | BTC 站上 MA20 且 MA20>MA50；BTC.D 走平或下降；稳定币市值扩张 | 正常选币，执行阈值 4.0 |
| 风险偏好中性偏弱 | BTC 在 MA20 上下反复；BTC.D 上行；山寨 20 日跑输 BTC | 仓位上限下调 1/3，执行阈值 **4.2** |
| 风险偏好收缩 | BTC 跌破 MA50 且 BTC.D 快速上行；或 24h 全市场爆仓 > $5 亿 | 做多**不执行**，输出「当前不适合做多」；做空按做空评分正常执行 |

> **做空方向补充**：即使闸门为"风险偏好正常"，若存在明确的板块过热信号（某板块 7 日涨幅 > 50% 且跑赢 BTC > 20pct、轮动阶段 = 晚期），仍可执行做空，但仓位上限下调至 5% 且执行阈值提高到 **4.5**。

### Step 1.5：预测下一个轮动板块

在确定候选池之前，先判断资金下一个可能流入的板块。**预测结果直接影响 Step 2 的候选池方向**。

#### 1.5.1 读取板块轮动状态

从大盘报告（或降级闸门）提取：`主线板块`、`流出板块`、`轮动阶段`、`BTC_D`、`ETH_BTC汇率`、`风险偏好`。

#### 1.5.2 获取板块相对强弱数据

```bash
# 加密 5 大板块（核心 / L1 / DeFi / Meme / 基础设施）
python scripts/get_market_data.py --market crypto --batch crypto-all --output json
# 条件触发用的交易所板块（BNB）
python scripts/get_market_data.py --market crypto --batch crypto-exchange --output json
```

从结果中提取各币的 `change_pct`、`pct_52w`、近 20 日收益率（用 price 与 52 周高低结构近似，或按需用 `get_history_bars` 自算）、`avg_volume` 趋势。

另需 `web_fetch` 直取（各 1 次；本环境 `web_search` 只返回标题+链接、无正文）：BTC.D 与 TOTAL2（CoinGecko / CoinMarketCap 页面）、稳定币市值（DefiLlama 页面）。

#### 1.5.3 轮动预测判断矩阵

**满足 2 条及以上即可判定**。

##### 【做多方向】预测下一个轮入板块

| 当前状态 | 可能轮入的板块 | 判断依据 |
|---------|---------------|---------|
| BTC 领涨且 BTC.D 上升（早期） | 暂不追山寨，候补 L1 龙头 | 资金仍在避险，山寨普涨尚未启动 |
| ETH/BTC 上行 + BTC.D 从高位回落（中期） | L1 公链 → DeFi | 增量资金开始向中高市值扩散 |
| Meme 板块 7 日涨幅 > 50% 且 OI 高位（晚期） | **转防御**：BTC / 稳定币 / 不追高 | 投机泡沫特征，做多风险大于收益 |
| 某板块 20 日跑输 BTC > 10pct 但资金费率转正 | 该板块的滞后补涨标的 | 资金开始关注，尚未拥挤 |

##### 【做空方向】预测下一个流出板块

| 当前状态 | 可能流出的板块 | 判断依据 |
|---------|---------------|---------|
| 轮动晚期 + Meme 集体暴涨后滞涨 | Meme | 情绪见顶，资金撤离高投机板块 |
| 板块 7 日涨幅 > 50% + 资金费率 > 0.1% | 该板块高弹性标的 | 杠杆拥挤，回调即踩踏 |
| 某板块 TVL 连续 2 周下降 > 10% | DeFi | 基本面（协议使用）恶化 |
| 未来 30 天该板块多个龙头有大额解锁 | 该板块 | 供给冲击确定性强 |

### Step 2：确定候选池（选币池）

**数据源**：`scripts/crypto_pool.json`（唯一数据源，AI 直接修改该 JSON 即可更新池子）。

```bash
# 查看池子结构（AI 直接读取文件内容，无需运行脚本）
cat scripts/crypto_pool.json
```

> **池子规模**：当前 **55 只 / 10 个板块**（2026-09-13 由 42 只扩充，补齐长期空缺的 RWA、GameFi）。上限 55，超限时按「流动性 + 叙事分层」保留，**不按市值一刀切截断**。
>
> **强制池外探测（每轮必做）**：用 CoinGecko 榜单 API 取当期 top100-300（本环境实测可直连）与池子做差集，差集中「叙事在上升且 rank < 300」的标的批量校验符号后补入池子；详见 [选币操作手册.md](选币操作手册.md) §3.4。**禁止只凭池内标的完成分析**——历史上池子仅 42 只且扩充链路失效，曾导致 HYPE / TAO / ZEC / ONDO / PENDLE 等叙事龙头从未被评估。

**必须执行可交易性校验**（本模块与美股选股最大的差异点）：

1. 调 `get_all_contracts` 取系统可交易合约清单（当前环境：`BINANCE_LINEAR`，700+ 个 U 本位永续）
2. 池中每个标的按 `symbol` 与清单求交集：
   - 命中 → 取清单返回的 `vt_symbol` 作为**唯一交易标识**（**不得使用池中缓存值**，币安部分币种符号带 `1000` 前缀等变体）
   - 未命中 → 从候选池剔除，并记入 `候选池摘要.不可交易剔除项`
3. 池子为空或可用标的 < 5 → 按 [选币操作手册.md](选币操作手册.md) 的**方式一/方式二**补充搜索

**候选池扩充**（池子覆盖不足时）：

```bash
python scripts/get_market_data.py --market crypto --tickers ADA-USD,DOT-USD,LTC-USD,TRX-USD --output json
```
（自定义 ticker 模式；脚本会返回 `error` 的即为无效 yahoo ticker，应剔除）

### Step 3：获取候选池结构化数据

```bash
python scripts/get_market_data.py --market crypto --tickers <候选 yahoo ticker 列表，逗号分隔> --output json
```

逐项提取（**字段名与脚本输出一致**）：

| 数据 | 用途 |
|------|------|
| `price` / `change_pct` | 当前价与当日涨跌 |
| `ma_20` / `ma_50` / `ma_200` | 趋势结构与支撑阻力 |
| `pct_52w` | 处于 52 周什么位置（>85 高位警惕，<20 低位反转候选） |
| `volume` / `avg_volume` | 当日量 / 20 日均量 → 放量缩量判断 |
| `market_cap` | 市值分层（对应池子 T1/T2/T3） |

需要单币技术指标（ATR/CCI/支撑压力位/风险收益比/价格分位）时：

```bash
python scripts/get_market_data.py --fetch-url product-all-info --ticker SOL-USD --output json
```

> ⚠️ 该命令对币种**可正常返回 news + technical**（评级对本市场不适用，会返回降级提示，属正常现象，记为 `not_applicable`）。

### Step 4：项目质量过滤（加密版"基本面"）

**美股用 PE/PEG/增速，加密用下面三类维度**。任一维度明确不合格即剔除，并记入 `候选池摘要`。

> **⚠️ 取数方式（2026-09-13 修订）**：本节表格中的 `web_search "..."` **一律改用 `web_fetch` 直取**（本环境 web_search 只返回标题+链接，无正文）。解锁/代币经济学首选 `tokenomist.ai/<coin>` 币种页（免费部分含：未来 30 天是否有解锁、释放对象、cliff/线性机制、流通比例、销毁率；**解锁数量与占流通比属付费墙**，取不到时按 §四 规则标 `unlock_unknown` 并降一档，**不得编造数字**）。

#### 4.1 代币经济学（最硬的一票否决项）

| 检查项 | 数据来源 | 剔除条件 |
|--------|---------|---------|
| 解锁曲线 | `web_search "{token} unlock schedule"` | **未来 30 天内解锁量 > 流通量 1%**（做多剔除；做空视为催化剂保留） |
| 通胀率 | `web_search "{token} token inflation rate"` | 年化通胀 > 15% 且无销毁机制 → 降一档评分 |
| 流通比例 | `web_search "{token} circulating supply vs total supply"` | 流通 < 20% 且解锁集中在 6 个月内 → 剔除 |
| 供应上限/销毁 | 同上 | 无限增发且无销毁 → 降一档 |

#### 4.2 协议基本面（有协议才适用）

| 检查项 | 数据来源 | 判断 |
|--------|---------|------|
| TVL 趋势 | `web_search "DeFi TVL"` / `"{protocol} TVL"` | 连续 2 周下降 > 10% → 做多剔除 |
| 协议收入 | `web_search "{protocol} fees revenue"` | 收入持续萎缩 → 叙事支撑不足 |
| 质押率 / 活跃地址 | `web_search "{chain} active addresses staking rate"` | 活跃度下降 → 降一档 |

#### 4.3 排除规则（自动排除，见 [选币操作手册.md](选币操作手册.md) §5.4）

稳定币 / 杠杆代币 / 封装币 · 不在可交易清单 · 上线 < 30 天 · 24h 成交额低于门槛 · 有下币公告 · 近 30 日重大负面（SEC 起诉、协议被攻击、交易所跑路）。

### Step 5：技术面过滤

| 检查项 | 做多要求 | 做空要求 |
|--------|---------|---------|
| 均线结构 | 站上 MA20（强趋势站上 MA50） | 跌破 MA20 且 MA20 拐头向下 |
| 价格位置 | `pct_52w` 20~85（**> 90 不追高**） | `pct_52w` > 85（高位滞涨）或明确破位 |
| 量能 | 回踩缩量、突破放量 | 反弹缩量、下跌放量 |
| 形态 | 回踩 MA20/前高突破、下降楔形上破 | 双顶/头肩顶、反弹遇 MA20 受阻 |
| 波动 | ATR% 过高（> 15%）时降低仓位 | 同 |

### Step 6：深度尽调与催化剂验证

> **⚠️ 取数方式（2026-09-13 修订）**：下表 `web_search "..."` 一律改用 **`web_fetch` 直取**（解锁→tokenomist 币种页；上币/下币公告→交易所公告页；ETF 流向→Farside/SoSoValue 页面；SEC 排期→官方页面）。`web_search` 只作入口。

```bash
python scripts/get_market_data.py --fetch-url product-all-info --ticker <币> --output json
```
（news 用于事件核对；technical 用于关键价位）

| 催化剂类型 | 获取方式 | 影响 |
|-----------|---------|------|
| **代币解锁** | `web_search "{token} unlock schedule"` | 最确定的利空（做多避开、做空首选） |
| 上币 / 下币公告 | `web_search "{token} exchange listing delisting"` | 上币 = 强利多；下币 = 暴跌风险（做空催化剂） |
| 协议升级 / 硬分叉 | `web_search "{token} upgrade fork date"` | 事件驱动利多（需核对是否已被预期） |
| 监管裁决（SEC/CFTC） | `web_search "SEC crypto decision calendar"` | 系统性（BTC/ETH）或品种级别风险 |
| ETF / 机构资金 | `web_search "BTC ETF flows" / "{token} ETF"` | 传统资金通道 |
| 生态大会 / 合作公告 | `web_search "{token} news"` | 叙事催化（注意"见光死"） |

### Step 7：评分卡综合打分

**1-5 分制，加权总分**。做多/做空维度不同，见 [加密货币做多选择.md](加密货币做多选择.md) §6.1 与 [加密货币做空选择.md](加密货币做空选择.md) §6.1。

#### 【做多】评分维度与权重

| 维度 | 权重 | 打分要点 |
|------|------|---------|
| 叙事与板块动能 | 20% | 板块 20 日相对 BTC 表现、叙事热度（非情绪极端） |
| 代币经济学 | 15% | 通胀率、解锁曲线、销毁/回购、流通比例 |
| 流动性 | 15% | 24h 成交额、`avg_volume` 分位、盘口深度 |
| 技术面形态 | 20% | 均线结构、形态、量能 |
| 资金面 | 15% | 资金费率（中性偏低更好）、OI 位置、交易所净流入 |
| 催化剂强度 | 15% | 升级/上币/ETF/合作，**且未被价格充分反映** |

#### 【做空】评分维度与权重（加密专属）

| 维度 | 权重 | 打分要点 |
|------|------|---------|
| 板块过热 / 叙事衰竭 | 20% | 板块 7 日涨幅、Meme 情绪、讨论度见顶 |
| 解锁抛压 | 15% | **悬崖解锁 > 线性解锁**；解锁量占流通比 |
| 资金费率与杠杆 | 15% | 费率 > 0.1%/8h 为极端多头拥挤（做空有利） |
| 技术面破位 | 15% | 跌破关键均线/前低、反抽失败 |
| 链上与协议恶化 | 15% | TVL 流失、活跃地址下降、交易所净流入 |
| 下跌催化剂 | 20% | 下币、SEC 裁决、大额解锁、团队抛售 |

#### 加密做空必须先过的两道闸（否则不得输出为可执行做空）

1. **轧空风险评估**：流通市值小（< $500M）+ 费率极端负 + OI 集中 = **不适合做空**（标记 `squeeze_risk: 高`，仅列入观察）
2. **做空成本核算**：负费率意味着持空单需付费；把 8h 费率折算成日成本，若日成本 > 目标跌幅的 1/3，降级为观察

### Step 7.5：反方审查（Devil's Advocate Review）

对每个入选标的，主动搜索反方证据并调整评分（0 ~ -0.5 分）。**2026-09-13 修订**：`web_search` 仅用于找入口，反方证据须用 `web_fetch` 直取正文；若仍取不到，**必须用行情数据自身取证**（近 3 月价格分位、Atr%、`risk_reward_long`、量比、52 周分位）并在 `反方审查.质疑项` 中注明"证据来源：行情数据（搜索正文不可得）"：

| 方向 | 质疑维度 | 检查方式 |
|------|---------|---------|
| 做多 | 涨幅已反映 / 叙事见光死 / BTC.D 上行压制 / 大额解锁临近 / 流动性不足 | `web_search "{token} bearish"` / 解锁日历 / BTC.D |
| 做空 | **轧空风险** / 跌幅已反映 / 基本面反转（TVL 回升）/ 逼空催化剂（上币、ETF） | `web_search "{token} short squeeze"` / 资金费率 / 上币公告 |

> 反方审查的结论必须落到 `反方审查.质疑项`，**不得只写在正文**。

### Step 8：生成入场计划

| 字段 | 做多 | 做空 |
|------|------|------|
| 建仓区间 | 现价 ±3-6%，结合 MA20/前高支撑 | 反弹至 MA20/前低阻力附近 |
| 止损位 | 入场价下方 **6-10%** 或 MA50 下方（取更近者） | 入场价上方 **6-10%** 或 MA20 上方 |
| 第一/第二目标 | 前高 / 上轨阻力 | 前低 / 下方支撑 |
| 仓位上限 | 单标的 10-15%，合计 ≤ 50% | 单标的 **5-8%**，合计 ≤ 20% |
| 工具 | 币安 U 本位永续（`vt_symbol` 以 `get_all_contracts` 返回为准） | 同（做空唯一工具） |
| 费率成本 | 正费率 = 多头付费，需说明 | 负费率 = 空头付费，需折算日成本 |

> **最小下单量校验**：执行前用 `get_contract` 核对最小下单量与最小名义额，避免因精度导致下单失败。

### Step 9：汇总输出

按【六、输出模板】生成结构化 JSON 结果。

> **⚠️ 禁止保存 JSON 文件到磁盘**：生成的 JSON 结果**只返回给用户**（由量化系统自动保存为分析报告），不得在本地保留任何中间结果文件。

### Step 10：以 JSON 格式输出（不保存 JSON 文件）

分析完成后，**以 JSON 格式输出结果（不保存 JSON 文件）**。报告名称（**不得自定义**）：

- 做多 → `加密货币做多选股结果`
- 做空 → `加密货币做空选股结果`

后续其他模块可通过 `cta_report_get(report_kind=...)` 直接读取。

## 三、数据获取方式优先级

> **⚠️ 取数铁律（2026-09-13 修订）**：本环境 `web_search` **只返回标题与链接、不返回正文**——文档中所有 `web_search "..."` 写法一律按本表执行：**优先 CoinGecko API / `web_fetch` 直取**，`web_search` 仅用于发现 URL（拿到链接后再 `web_fetch`）。取不到的数据按 §四 标 `missing` / `unlock_unknown`，**不得编造数字**。

| 数据类别 | 首选方式 | 降级方式 |
|---------|---------|---------|
| 大盘环境 | `cta_report_get("加密货币大盘与板块和资金流向分析")` | **价格结构降级闸门**（Step 1，不执行大盘任务） |
| 跨市场（美股）参考 | `get_market_data.py --market us_stocks --batch us-all` | `web_fetch` 直取 QQQ / ^VIX / US10Y / DXY 页面 |
| 板块相对强弱 | `get_market_data.py --batch crypto-all` / `crypto-exchange` | CoinGecko 榜单 API |
| 候选池价格/均线/量/市值 | `get_market_data.py --tickers <yahoo ticker 列表>` | CoinGecko 榜单 API |
| 单币技术指标（ATR/CCI/支撑压力位） | `get_market_data.py --fetch-url product-all-info --ticker <币>` | `web_fetch` |
| K 线序列（形态自算） | `vnpy_mcp get_history_bars`（币安可用） | — |
| 代币经济学 / 解锁 | **`web_fetch` tokenomist.ai/<coin>**（免费部分含事件/机制/流通比例/销毁；数量与占比为付费墙） | CoinGecko 币种页 / 项目官网 |

| **市值排名 / 榜单（池外探测）** | **CoinGecko `/api/v3/coins/markets?per_page=100&page=n`（实测可直连）** | CMC 页面 `web_fetch` |
| 可交易清单 / vt_symbol | `get_all_contracts` / `search_vt_symbol` | — |

## 四、数据缺失处理规则

| 场景 | 处理方式 |
|------|---------|
| 大盘报告不存在或过期 | 使用**价格结构降级闸门**（Step 1），`gate.source = price_structure_fallback`，不标 missing |
| 某标的代币经济学数据无法获取 | 标记该标的 `tokenomics_missing`，评分降一档，仍可入选但需在风险提示中说明 |
| 某标的技术面数据缺失 | 标记 `technical_data_missing`，跳过该标的 |
| 某标的解锁数据无法获取 | 标记 `unlock_unknown`，**做多时降一档评分；做空时不得作为主要依据** |
| 标的无法与 `get_all_contracts` 交集 | 剔除并记入 `候选池摘要.不可交易剔除项` |
| 候选池中超过 50% 标的无法获取数据 | 降低置信度，标注 `low_data_quality` |
| 所有标的评分均 < 3.5 | 输出「当前未找到符合条件的标的」，列出评分最高的 3 只及差距 |
| `get_market_data.py` 批次取数失败 | 按加密大盘文档 Step 0.3「重试容忍度」重试 1 次，仍失败记入 `采集脚本失败项` 并降级 `web_search` |

### `采集脚本失败项` 字段说明

与【大盘与板块和资金流向分析】模块一致：记录 `get_market_data.py` **实际发生的失败项**，直接引用脚本输出的失败对象。常见两类：批次行情失败（限流最常见）与经济日历抓取失败。无失败项时填空列表 `"get_market_data.py": []`，**不得删除该字段**。

### 输出前自检清单

AI 在输出前必须逐条检查以下 9 项：

| # | 检查项 | 要求 |
|---|--------|------|
| 1 | 字段完整性 | 输出 JSON 包含【六、输出模板】中的所有字段，无遗漏。数据不可得时填入 `missing` 或 `null`，不得删除字段 |
| 2 | 字段名一致性 | 所有字段名与模板完全一致（中文 key），不得自行改用英文或其他命名 |
| 3 | 可交易性已校验 | 每个输出标的的 `vt_symbol` 来自 `get_all_contracts` 返回，不得使用池中缓存值或自行拼接 |
| 4 | 门槛与仓位已按闸门调整 | 闸门降级（`price_structure_fallback`）时执行阈值 4.2、仓位上限下调 1/3；做空过热情形按对应规则 |
| 5 | 做空双闸已过 | 做空输出必须含 `轧空风险评估`，且 `squeeze_risk=高` 的标的一律降级为观察；做空成本（费率）已折算说明 |
| 6 | 指标未跨层滥用 | 没有把月度口径数据（MVRV、全球 M2、矿工 30 日余额等）用于短线决策 |
| 7 | missing / conflict 已标注 | 所有无法获取或来源矛盾的数据已记入 `数据缺失与冲突`；脚本失败项已记入 `采集脚本失败项` |
| 8 | 核心冲突已列出 | `核心冲突` 至少含正反两方向，最后一条为判断 |
| 9 | 无交易动作语言越界 | 不得出现具体下单指令（如"立即市价开多 10 倍"）；仓位/止损为**建议参数**，执行由策略与人工决定 |

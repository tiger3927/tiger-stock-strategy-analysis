# 加密货币选币池定义与操作手册

> 本文档定义**选币池**（候选池）的生成方式与质量控制规则，供 [00_index.md](00_index.md) 的 Step 2 使用。
> 池子数据源：`scripts/crypto_pool.json`（唯一数据源，AI 直接修改该 JSON 即可更新，无需改代码）。

---

## 一、候选池生成方式（按优先级）

```text
1. 优先：crypto_pool.json 现有池子（并做可交易性校验）
2. 不足时：方式一 板块衍生 + 项目质量筛选
3. 仍不足：方式二 全市场分层扫描
4. 用户直接给了币种列表：方式三 用户指定
```

> **加密与美股的关键差异**：美股候选池是"股票池"（几千只），加密的**可交易集合由交易所决定**——本系统当前可交易的是 `BINANCE_LINEAR`（700+ 个 U 本位永续）。**任何候选都必须与 `get_all_contracts` 求交集**，否则无法执行。

## 二、方式一：板块衍生 + 项目质量筛选

### 2.1 确定目标板块

从大盘环境（`gate`）+ 00_index §1.5.3 的轮动矩阵，确定 1-2 个目标板块：

| 板块 | 观察标的（示例，完整清单以 `scripts/crypto_pool.json` 为准） |
|------|-----------------|
| L1 公链 | BTC, ETH, SOL, ADA, DOT, AVAX, SUI, NEAR, APT, HYPE, KAS, INJ |
| L2 / 模块化 | OP, ARB |
| DeFi | AAVE, UNI, MKR, LDO, CRV, ENA, JUP, PENDLE, RUNE |
| Meme | DOGE, PEPE, WIF, BONK, SHIB |
| 基础设施 / AI | LINK, RENDER, FET, AR, TAO, FIL, WLD |
| 交易所平台币 | BNB, CAKE |
| 支付 / 隐私 | XRP, LTC, ZEC, XMR, DASH |
| RWA | ONDO |
| GameFi | IMX |
| DePIN | IOTX |

> 当前池子 55 只 / 10 个板块（2026-09-13）。板块一旦长期为 0（如历史上的 RWA、GameFi），即为池子老化信号，按 §3.2 定向补齐。

### 2.2 搜索候选币

```bash
# 批次数据（价格/均线/52周分位/成交量/市值）
python scripts/get_market_data.py --market crypto --batch crypto-all --output json

# 自定义补充（脚本返回 error 的即为无效 yahoo ticker，直接剔除）
python scripts/get_market_data.py --market crypto --tickers INJ-USD,SEI-USD,TIA-USD --output json
```

补充搜索（**必须走能返回正文的通道**，见 §3.4）：

```text
# 首选：CoinGecko 榜单 API（本环境实测可直连，一次拿回 rank + 市值 + 价格）
python -c "import json,urllib.request;U='https://api.coingecko.com/api/v3/coins/markets?vs_currency=usd&order=market_cap_desc&per_page=100&page=';H={'User-Agent':'Mozilla/5.0'};d=[r for p in (1,2,3) for r in json.load(urllib.request.urlopen(urllib.request.Request(U+str(p),headers=H),timeout=25))];[print(r['market_cap_rank'],r['symbol'],r['current_price'],int(r['market_cap'])) for r in d]"

# 赛道/币种资料：web_fetch 直取（tokenomist 解锁页、DefiLlama 板块页、官网公告）

# ⚠️ web_search 在本环境只返回标题+链接、无正文，**不得作为唯一数据来源**
```

### 2.3 板块核心 + 卫星种子表

每个目标板块至少给出：

| 层级 | 数量 | 定位 | 池子 Tier |
|------|------|------|----------|
| 核心 | 1-2 | 板块风向标、流动性最好 | T1/T2 |
| 中盘 | 2-4 | 超额收益主力、弹性好 | T2 |
| 弹性 | 1-3 | 高赔率、高波动 | T3 |

### 2.4 方式一完成后必须执行：可交易性与流动性检查

1. **可交易性**：调 `get_all_contracts`，逐币按 `symbol` 匹配（注意币安符号变体，如部分币种带 `1000` 前缀）→ 命中者取清单返回的 `vt_symbol`（**不得用池中缓存值**）
2. **流动性**：`24h 成交额 ≥ $20M`（T3 可放宽至 $5M，但仓位减半）；`avg_volume` 不低于 52 周 20 分位
3. **排除规则**：见 §5.4，逐条过

## 三、方式二：全市场扫描（池子覆盖不足时）

### 3.1 按市值分层取数（CoinGecko 榜单 API，实测可直连）

```bash
# 前 300 名分页取回 rank / 市值 / 价格（page=1,2,3 各 100 条）
python -c "import json,urllib.request;U='https://api.coingecko.com/api/v3/coins/markets?vs_currency=usd&order=market_cap_desc&per_page=100&page=';H={'User-Agent':'Mozilla/5.0'};d=[r for p in (1,2,3) for r in json.load(urllib.request.urlopen(urllib.request.Request(U+str(p),headers=H),timeout=25))];[print(r['market_cap_rank'],r['symbol'],r['current_price'],int(r['market_cap'])) for r in d]"
```

分层口径（与 `crypto_pool.json` 的 `mcap_bucket` 一致）：`top10` = rank 1-10；`11-30`；`31-60`；`60+`。
**重点层：31-100 名**——超额收益常来自中市值；`60+` 为高弹性层（占比须 ≥ 20%）。

### 3.2 按赛道维度取数

```text
web_fetch 直取：DefiLlama 板块/TVL 页、tokenomist 解锁页、交易所公告页、项目官网
CoinGecko API 翻页：page=4,5 可扩到 500 名（前 300 通常足够）
web_search：本环境**只返回标题+链接、无正文**，仅作入口线索，数据必须用 web_fetch/API 取得
```

### 3.3 结果合并

1. 去重（同一代币不同名称/多链封装只保留主币）
2. 转成 yahoo ticker 候选清单（注意消歧符号：`SUI20947-USD`、`UNI7083-USD`、`PEPE24478-USD`、`APT21794-USD` 等）
3. 用 `--market crypto --tickers ...` 批量校验（返回 `error` 的剔除）
4. 进入 §5 质量控制

### 3.4 强制池外探测（2026-09-13 新增）

**每轮选币必须执行一次**，防止"池子老化 → 视野固化"：

```bash
# 1) 用 §3.1 的 CoinGecko 命令取回当期 top100-300 榜单，与 crypto_pool.json 做差集
# 2) 对差集中「叙事在上升且 rank < 300」的标的批量校验 yahoo 符号
python scripts/get_market_data.py --market crypto --tickers <差集 yahoo 列表> --output json
# 3) 校验通过且未被 §5.4 排除的 → 加入 crypto_pool.json，并跑 sync_crypto_pool.py
# 4) 校验失败或数据异常的 → 记入 pending_verification（必须写明失败原因，不得静默丢弃）
```

> **背景（必读）**：本池 2026-09-13 之前为 42 只，因动态扩充链路依赖 `web_search`（无正文）而**事实上失效**，导致 HYPE / TAO / ZEC / ONDO / PENDLE / XMR 等叙事龙头长期不在视野内——不是"评分不够被淘汰"，而是**从未被评估**。本次补池至 55 只。
>
> **符号消歧速查**（yahoo 符号不等于裸代码，写错会取不到数）：
> `HYPE32196-USD`（HYPE）· `TAO22974-USD`（TAO）· `JUP29210-USD`（JUP）· `IMX10603-USD`（IMX）· `SUI20947-USD`（SUI）· `UNI7083-USD`（UNI）· `PEPE24478-USD`（PEPE）· `APT21794-USD`（APT）· `GRT6719-USD`（GRT）
>
> **已知不可用**：`TON-USD`（指向另一资产）、`TON11419-USD`（52 周/均线缺失）、`GALA-USD`（行情与市值背离）、`HNT-USD`（市值与 Helium 不符）。

## 四、方式三：用户指定列表

用户直接给出币种/合约时：

1. 转成 yahoo ticker + `symbol` 双标识
2. **仍必须做可交易性校验**（不在 `get_all_contracts` 中的直接剔除并告知用户原因）
3. 补齐池子必需字段（§7.2），写入 `crypto_pool.json`
4. 运行 `python scripts/sync_crypto_pool.py` 校验结构

## 五、候选池质量控制

### 5.1 数量控制

| 候选池大小 | 处理方式 |
|-----------|---------|
| < 10 只 | 补充取数（方式二），直到 ≥ 10 只 |
| 10-55 只 | 正常进入下一轮筛选 |
| > 55 只 | **按流动性 + 叙事分层保留**，不按市值一刀切截断 |

> **2026-09-13 修订**：上限由 40 放宽至 **55**。原 40 上限使 RWA / GameFi 等板块长期为 0，且把新叙事标的挡在池外；截断规则同步由「按市值从大到小截断」改为「按流动性 + 叙事分层保留」——市值一刀切会优先砍掉高弹性新叙事（`pool_size_target` 见 `crypto_pool.json`）。
> 保留"不贪多"的纪律：**每轮实际进入深度尽调的标的 ≤ 8 只**，池子大不等于每轮全跑；流动性门槛（§5.4 #4）比池子规模更重要。

### 5.2 多样性控制

候选池应覆盖**至少 3 个不同板块**。当前池子已覆盖 10 类：L1 公链 / L2-模块化 / DeFi / Meme / 基础设施-AI / 交易所平台币 / 支付-隐私 / RWA / GameFi / DePIN。

> 某类长期为 0（历史上 RWA、GameFi 曾长期空缺）即视为池子老化信号，按 §3.2/§3.4 定向补齐；不得用"当期没热度"长期豁免同一板块。

### 5.3 高弹性（小市值）保障

**高弹性标的在候选池中占比不低于 20%**（对应美股"小盘股 ≥ 20%"）。判定口径：`mcap_bucket` 为 `31-60` 或 `60+` 的标的视为高弹性（见 `crypto_pool.json` 的 `meta.mcap_buckets` / `high_beta_rule`）。

不足时补充搜索：

```text
# 用 CoinGecko 榜单取 61-300 名（§3.1 命令），按 24h 成交额 / 涨幅排序筛出高弹性候选
# 小市值资料用 web_fetch 直取（官网 / DefiLlama / 交易所页面）
# web_search 仅作入口（本环境无正文）
```

> 仍不足 → 在输出中标注 `high_beta_insufficient`，不得用流动性极差（24h 成交额 < $5M）的币凑数。

### 5.4 排除规则

以下标的自动排除（**任一命中即剔除**）：

| # | 排除项 | 判定方式 |
|---|--------|---------|
| 1 | 稳定币 / 杠杆代币 / 封装币 | USDT/USDC/DAI/FDUSD、3L/3S/BTCUP 类、WBTC 等封装 |
| 2 | 不在可交易清单 | `get_all_contracts` 未命中 |
| 3 | 上线时间 < 30 天 | CoinGecko 币种页（`web_fetch`）核对首次上线日期 |
| 4 | 24h 成交额 < $5M（T3 门槛）/< $20M（T1/T2 门槛） | 脚本 `volume` 字段 |
| 5 | 有下币公告 / 已在退市流程 | 交易所公告页（`web_fetch`） |
| 6 | 近 30 日重大负面 | SEC 起诉、协议被攻击、团队跑路、提币暂停（**须核实来源**） |
| 7 | 未来 30 天解锁 > 流通量 1%（做多视角排除；做空保留为候选） | `web_fetch` tokenomist.ai/<coin> 币种页 |
| 8 | 盘口深度不足（目标建仓量对应滑点 > 1%） | 人工/交易所盘口核对 |

> 做多与做空的排除不完全相同：**#7 解锁**对做多是排除项，对做空是加分项——筛选时必须带上 `direction` 语义。

## 六、候选池生成流程总结

```text
用户请求选币
    │
    ├─ 池子已有足够候选？──→ 方式 0：crypto_pool.json + 可交易性校验
    │
    ├─ 用户提供了币种列表？──→ 方式三：直接使用 + 校验（不可交易剔除）
    │
    └─ 需要 AI 筛选？
         │
         ├─ 大盘/轮动有明确主线板块？──→ 方式一：板块搜索 + 核心+卫星保底
         │                                │
         │                                └─ 高弹性占比 < 20%？──→ 是 → 执行 §5.3 补充搜索
         │                                        │                      │
         │                                        └─ 否                  └─ 再检查，直到 ≥ 20%
         │                                                                    │
         │                                                                    ↓
         │                                                              仍不足 → 标注 high_beta_insufficient
         │
         └─ 无明确主线或全市场扫描？──→ 方式二：分层搜索（大/中/小市值 × 赛道）
                                              │
                                              └─ 高弹性占比 < 20%？→ 补充搜索
                                                      │
                                                      ↓
                                              合并去重 → 数量/多样性检查 → 可交易性校验 → 输出候选池
```

## 七、池子文件结构与维护

### 7.1 文件位置与分层

`scripts/crypto_pool.json`，结构镜像美股 `stock_pool.json`：

```json
{
  "meta": {
    "version": "1.0",
    "tier1_updated_at": "2026-09-13",
    "tier2_updated_at": "2026-09-13",
    "tier3_updated_at": "2026-09-13",
    "tier_definitions": {
      "T1": "核心大市值（BTC/ETH + 市值前 10）— 方向基准与流动性锚",
      "T2": "板块龙头（各叙事 1-3 只）— 超额收益主力",
      "T3": "高弹性小市值 / 新叙事 — 高赔率高风险"
    },
    "tradable_source": "get_all_contracts(BINANCE_LINEAR)",
    "vt_symbol_policy": "池中不缓存 vt_symbol；执行时以 get_all_contracts 返回值为准",
    "pool_size_target": "20-45"
  },
  "categories": {
    "L1 公链": {"T1": ["BTC", "ETH"], "T2": ["SOL", "ADA", "DOT", "AVAX", "SUI", "NEAR", "APT"], "T3": ["SEI", "TIA", "..."]},
    "L2/模块化": {"T2": ["OP", "ARB"], "T3": []},
    "DeFi": {"T2": ["AAVE", "UNI", "MKR", "LDO", "CRV"], "T3": ["RUNE"]},
    "Meme": {"T2": ["DOGE", "PEPE", "WIF", "BONK"], "T3": []},
    "基础设施/AI": {"T2": ["LINK", "RENDER", "FET", "AR"], "T3": ["FIL", "WLD"]},
    "交易所平台币": {"T2": ["BNB"], "T3": []},
    "支付/隐私": {"T2": ["XRP", "LTC"], "T3": ["DASH"]},
    "DePIN": {"T3": ["IOTX"]}
  },
  "coins": {
    "SOL": {
      "symbol": "SOL",
      "yahoo": "SOL-USD",
      "category": "L1 公链",
      "tier": "T2",
      "chain": "Solana",
      "mcap_bucket": "top10",
      "yahoo_verified": true
    }
  }
}
```

### 7.2 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `symbol` | ✅ | 币种裸代码（用于与 `get_all_contracts` 匹配） |
| `yahoo` | ✅ | yahoo ticker（用于脚本取数；消歧符号按 `SUI20947-USD` / `UNI7083-USD` / `PEPE24478-USD` 写法） |
| `category` | ✅ | 所属板块（必须与 `categories` 的键一致） |
| `tier` | ✅ | T1 / T2 / T3 |
| `chain` | 建议 | 主链 / 生态（便于同板块集中度判断） |
| `mcap_bucket` | ✅ | `top10` / `11-30` / `31-60` / `60+`（用于分层与"高弹性占比"统计，**不写精确排名**避免过期） |
| `yahoo_verified` | ✅ | 是否经 `--tickers` 批量校验通过；**false 的不得进入候选池** |
| `note` | 可选 | 备注（消歧符号、符号变体风险等） |

> **不缓存的字段**：解锁风险（`unlock_risk`）变化快，**不入池**；每轮分析按 00_index Step 4 用 `web_fetch` 直取 tokenomist 币种页实时核对（`web_search` 无正文，不作为数据来源）。

### 7.3 更新频率（加密比美股快）

| 层级 | 频率 | 说明 |
|------|------|------|
| T1 | 月度 | BTC/ETH + 市值前 10 变化极小 |
| T2 | 双周 | 板块龙头随叙事迁移 |
| T3 | **每周** | 加密叙事切换快（美股 T3 为 30 天，此处必须更勤） |

> **2026-09-13 执行记录**：池子 42 → **55 只 / 10 个板块**（新增 RWA：ONDO；GameFi：IMX；隐私：ZEC/XMR；AI：TAO；新 L1：HYPE/KAS/INJ；DeFi：ENA/JUP/PENDLE；Meme：SHIB；平台币：CAKE），并用 CoinGecko 实测排名校正全部 `mcap_bucket`（旧版 APT/UNI/NEAR/FET 等分桶已过期）。`verified_reserve`（GRT/PYTH/RAY/FLOKI/STRK）符号已验证，供下一轮按叙事补入。

更新后必须：

```bash
python scripts/sync_crypto_pool.py
```

> 校验失败（结构错误、重复标的、板块缺失、yahoo 未验证等）→ 修正后重跑，**不得跳过校验**。

### 7.4 AI 修改池子的边界

AI 可以修改：`coins` 增删、`tier`/`category` 调整、`unlock_risk`/`mcap_rank` 更新、`categories` 增删、`meta` 的时间戳。

AI **不得**修改：`meta.version` 的语义、`tradable_source`、`vt_symbol_policy`（这两条是执行契约，改了会导致选出的币无法交易）。
